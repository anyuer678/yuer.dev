## 项目介绍

Windows 上配环境是件重复且容易留下烂摊子的事：PATH 越改越长、Python 装了三个版本但不知道哪个在生效、项目 A 要的变量污染了项目 B、改完系统变量重启才发现写错了。

EnvForge 把这几件事收进一个本地工具：运行时版本、项目环境档案、系统环境变量（HKCU / HKLM / 当前会话）、健康体检。数据只存本机，核心逻辑零第三方依赖。

## 设计目标

- 写入必须可验证：改之前有快照，改完回读比对，不对就自动回滚，不留半改状态
- 敏感值不落明文：键名命中密钥模式就加密，列表和导出一律 `***`
- 项目隔离：变量按项目档案管理，激活只影响当前会话，不动全局
- 没有 PySide6 也能用：GUI 不可用时回退到 CLI，不崩

## 功能

- **运行时版本**：自动探测 PATH 中的 Python / Node.js / Java / Go / Rust，记录版本与路径，支持手动登记；生成 PowerShell 激活脚本，只对当前会话前置 PATH
- **项目与档案**：一个项目可维护 `dev` / `test` / `prod` 多份档案，支持差异比较、`.env` 导出（默认脱敏）、会话激活
- **敏感值保护**：命中 `SECRET|TOKEN|PASSWORD|API_KEY|PRIVATE_KEY|CREDENTIAL` 等模式的值经 Windows DPAPI 加密入库；DPAPI 不可用时拒绝明文落库，只记键名并告警
- **系统环境变量**：读 `user`（HKCU）、`system`（HKLM，只读）、`session` 三种作用域；PATH 分析标出重复段、失效目录与空段；写入后广播 `WM_SETTINGCHANGE`
- **快照与回滚**：任意时刻存快照、比较两个快照差异、一键回滚（可选删除快照中不存在的变量）；每次写入前自动存 `pre-apply` 快照
- **审计与数据保护**：操作写按天 JSONL（只记变量名与结果，不记值）；打开库做完整性自检，每天自动备份保留 7 份，崩溃写 `logs/crash-*.log`
- **常用变量库**：内置 151 个常用环境变量（10 个分类），带中文说明、示例与敏感标记，可搜可筛可一键加入档案
- **健康体检**：汇总 PATH 问题、多版本并存、PATH 里未登记的运行时、敏感值未加密、项目目录失效，按 error / warn / info 分级
- **环境标准 Spec v1**：TOML 声明一台合格开发机应有的工具版本、变量、目录、命令与端口，`spec capture/check/diff/plan` 支持采集、核对、比较与生成安装计划

## 架构

```text
PySide6 GUI ──┐
              ├── 核心层（纯标准库）
CLI（-m envforge）┘   ├── 运行时探测 / 版本登记
                     ├── 项目档案 + 变量解析（项目隔离）
                     ├── 系统变量读写（HKCU 可写 / HKLM 只读 / session）
                     ├── DPAPI 加解密（不可用则拒绝明文落库）
                     ├── 快照 · 回滚 · 跨进程文件锁 · 回读校验
                     └── SQLite 库 + JSONL 审计 + 每日备份
```

## 技术选择

- **核心只用标准库，GUI 可选 PySide6**：环境工具本身不能成为新的依赖负担，CLI 场景也不该被迫装 GUI
- **DPAPI 而非自研加密**：Windows 上密钥跟着用户账户走，不需要自己管主密钥，也不会出现"密码存在旁边文件里"的假安全
- **SQLite + JSONL 分工**：状态进库（可事务），审计进按天 JSONL（只追加、可 grep、坏了不影响主库）
- **TOML 声明环境标准**：比 JSON 少噪音，人能读能 diff；`plan` 只生成脚本不执行，避免"一键把机器改坏"

## 开发过程

先有核心与 CLI，再接 GUI——这样界面只是壳，逻辑永远能被脚本调用，也意味着出了问题可以在命令行复现。

写入这块改过几轮：最初的实现直接 `setx`，中途失败会留下半改的 PATH。现在所有写入都进跨进程文件锁、写完回读逐键比对、不一致就用前置快照回滚并明确报告"失败键 + 是否已回滚"。
