## 项目介绍

有些事不需要打卡系统，只需要知道"上次做是什么时候"：浇花、换滤芯、给硬盘做备份、练琴。为此打开一个 App 记一笔，成本比事情本身还高。

点时把它压到一步：**在桌面小组件上点一下，对应活动的最近执行时间就变成现在**。不打开应用、不联网、不留常驻服务。

## 设计目标

- 操作成本为零：解锁桌面 → 点一下，两秒内完成
- 零常驻：不用前台服务，不为了记一个时间戳常驻后台
- 数据是本地的：JSON 备份导出/导入，换机自己搬
- 误触可救：连击合并窗口 + 历史记录可撤销

## 功能

- 两种小组件：单活动卡片（整卡即按钮）、全部活动列表（宽屏自动两列，可自由拉伸）
- 单击即记录；连击合并窗口可选 30 秒 / 1 分钟 / 5 分钟，窗口内重复点击只记一次，时间显示自动按窗口对齐并带秒
- 应用内管理：新建 / 重命名 / 排序 / 删除活动
- 历史记录：撤销最近一次、删除任意一条
- JSON 备份导出 / 导入

## 架构

```text
Glance 小组件（AppWidget）
   │  点击事件
   ├── 连击合并判定（窗口对齐）
   └── Room（SQLite）── 活动表 / 历史表
                          └── Compose 应用内管理界面
```

没引入 WorkManager、没有后台同步、没有网络权限——这个应用只在被点击的那一刻存在。

## 技术选择

- **Jetpack Glance**：小组件用 Compose 风格写，比 RemoteViews 手写布局少一大截样板
- **Room**：历史记录要能撤销单条、要能排序，裸 SQLite 手写这些反而更容易错
- **连击合并放在写入前**：先判定再落库，历史表里不会留下需要事后清理的重复记录
- **Compose 管理界面**：只有几个列表和表单，用 Compose 写完整个应用不到千行

## 开发过程

功能一次做完了，之后没有再迭代——这类小工具的价值在于"够用就停"，继续加东西只会让它变慢变复杂。构建时踩的坑记在 README 里：直连 `services.gradle.org` / `dl.google.com` 会超时，Gradle 发行版换腾讯镜像、依赖仓库换阿里云镜像就能过。

## 未来计划

不再开发。当前状态即为最终版本，源码与 APK 构建方式保留在仓库里，需要时随时可重新编译。
