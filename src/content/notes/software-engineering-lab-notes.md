## 实验一：可行性研究与项目计划

案例：**图书馆管理系统**（书目管理、借阅证管理、借还图书、查询、超期缴费五大模块）。

可行性研究三维模型：

- **技术可行性**：实现难度、团队能力是否够
- **经济可行性**：开发成本 vs 收益
- **操作可行性**：用户操作门槛、业务流程是否顺

流程设计：以学生为外部实体，走"借阅证验证 → 系统登录 → 功能选择 → 业务操作 → 数据读写"闭环，关联三大核心数据表。

项目计划用**瀑布模型**划分五阶段（需求/设计/开发/测试/收尾），7 天开发周期，用**甘特图**明确任务与时间节点。

> 体会：可行性研究不是走形式，重点是提前暴露"做不做得成、值不值得做"。甘特图画出来，任务依赖和并行关系一目了然。

## 实验二：需求分析

工具：用例图、数据流图（DFD）、IDEF1X 数据建模。

- **用例图**：参与者（Actor）+ 用例（Use Case）+ 关系（include/extend/泛化）。图书馆系统里"借书"用例 include"验证借阅证"
- **数据流图**四种成分：**数据源点/终点、加工（处理）、数据流、数据存储**。按"顶层图 → 0 层图 → 1 层图"逐层细化
- **IDEF1X**：实体-关系建模方法，标识实体、联系（1:n / m:n）、主键外键

画 DFD 的坑：数据流必须命名（动词+名词），加工至少要有一条输入和输出，数据存储不能直接连外部实体。

## 实验三：系统设计

两种设计路线对比：

- **结构化设计**：数据流图 → 软件结构图（模块化分解）。培训中心管理系统按业务拆"信件分类/学员管理/课程管理/缴费"模块，模块间高内聚低耦合
- **面向对象设计**：UML 类图、时序图、状态图，类间关系（关联/聚合/组合/继承）

软件结构图评价指标：模块**扇入扇出**、内聚耦合度。高扇入（被多个模块调用）说明复用性好，高扇出（调用太多模块）说明控制复杂。

## 贯穿案例的意义

三个实验用同一个图书馆管理系统案例走完整条"**可行性 → 需求 → 设计**"开发前链路，配合实验四（测试技术）补齐了"**分析 → 设计 → 测试**"的软件工程主干。模型图工具从 Mermaid（快速草稿）到亿图/StarUML（正式图），也体会到"先草图后成图"的效率差别。
