## 关系代数

关系代数是关系数据库的查询语言基础，运算结果仍是关系。分传统集合运算与专门关系运算。

**传统集合运算**（要求同属性个数与域相容）：并 ∪、差 −、交 ∩、笛卡尔积 ×。

**专门关系运算**：

- **选择 σ**：按条件选行（水平切片），`σ_sage>20(Student)`
- **投影 π**：选列并去重（垂直切片），`π_sname,sdept(Student)`
- **连接 ⋈**：按连接条件合并两关系；θ 连接、等值连接、**自然连接**（去掉重复列）
- **除 ÷**：R÷S = 找出「包含 S 中全部属性值」的 R 元组，常用于「查询全部/至少」类问题（如选了全部课程的学生的学号）

**运算优先级**：选择、投影最高，其次连接，集合运算最低。查询优化就是调整选择/投影下推，减少中间结果。

**关系演算**：用谓词描述查询。**元组关系演算**（`{t | P(t)}`，如 t ∈ Student ∧ t.Sage > 20）与**域关系演算**。能力与关系代数等价（关系完备性）。

## ER 模型

**三要素**：实体（矩形）、属性（椭圆）、联系（菱形）。

**联系类型**：1:1、1:N、M:N。M:N 联系在关系模型中**必须转换为独立关系**（如 学生-课程 选课表）；1:N 可在 N 端加外键；1:1 可并入任一端。

**属性分类**：简单/复合、单值/多值、派生属性（可由其他属性算出，如年龄由生日派生，一般不存储）。**弱实体**：自身无足够属性构成主键，依赖强实体（如 病房-病床）。

**ER 图转关系模式**的要点：实体 → 关系；联系 → 外键或新关系；主键下划线、外键标 REF。

## 函数依赖与范式

**函数依赖 X→Y**：X 的值决定 Y 的值。**完全函数依赖**（X 的任一真子集都不能决定 Y）vs **部分函数依赖**；**传递依赖**：X→Y、Y→Z 且 Y↛X。

**候选码**：能唯一标识元组、且无冗余属性的最小属性组；主码从候选码中选一个。

**范式递进**：

- 1NF：属性不可再分（原子性）——关系模式的前提
- 2NF：消除**非主属性对候选码的部分依赖**（如「学号+课程号 → 学分」拆开）
- 3NF：消除非主属性对候选码的**传递依赖**（如 学号→系→系主任，系主任应移出）
- BCNF：消除**主属性**对候选码的部分/传递依赖（3NF 不满足 BCNF 的例子：候选码重叠时，如「教师-课程-学生」三元关系）

**分解准则**：保持**无损连接**（分解后能自然连接还原）+ **保持函数依赖**。判断范式：找候选码 → 找非主属性依赖 → 判断是否满足各级范式 → 分解。

## 数据库设计步骤

六步：**需求分析 → 概念结构设计（ER 图）→ 逻辑结构设计（关系模式+规范化）→ 物理结构设计（存储与索引）→ 数据库实施 → 运行与维护**。

- 需求分析产物：数据流图 DFD、数据字典
- 概念设计：用户视角的 ER 模型
- 逻辑设计：ER → 关系模式，规范化到 3NF/BCNF
- 物理设计：确定存储结构、索引、分区

## 索引原理

**为什么索引**：避免全表扫描，先查索引定位再读数据；代价是占用空间、增删改需动态维护。

**分类**：

- 按存储结构：**聚簇索引**（索引顺序 = 物理存储顺序，一张表仅一个，适合范围/排序查询）、**非聚簇索引**（需二次查找，可多个）
- 按功能：普通、唯一（允许空）、主键（唯一且非空）、复合（**最左前缀原则**）、全文、空间索引

**数据结构**：

- **B+ 树**最常用：非叶子只存索引、叶子含全部关键字并有序链成链表；查询稳定、范围查询与全表扫描高效（MySQL/Oracle 都用）
- 哈希索引：等值查询 O(1)，不支持范围/排序/前缀
- 位图索引：适合低基数列；R 树用于空间数据；倒排索引（关键词→文档）用于全文检索

**设计原则**：为 WHERE/排序/连接列和高选择性列建索引；避免在索引列用函数、避免 `LIKE '%..'` 与 OR；小表不建；数量勿过多。用 EXPLAIN 检查执行计划（type 从 system 到 ALL 由好到坏）。

## 速记口诀

- 关系代数：σ 选行、π 选列、⋈ 连表、÷ 查「全部」
- 范式链：1NF 原子 → 2NF 消部分 → 3NF 消传递 → BCNF 消主属性依赖
- 分解两准则：无损连接 + 保持依赖
- 索引选择：范围/排序用 B+ 树聚簇，等值高频用哈希，全文用倒排
- 易错点：候选码不唯一；M:N 联系必须建中间表；复合索引最左前缀
