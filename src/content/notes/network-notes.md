# 计算机网络速记

## 一、OSI 七层 vs TCP/IP 四层 对比

| OSI 七层模型 | TCP/IP 四层模型 | 功能概述 | 典型协议/设备 |
|:---:|:---:|:---|:---|
| 7. 应用层 | 应用层 | 为应用程序提供网络服务接口 | HTTP, FTP, SMTP, DNS, DHCP, Telnet |
| 6. 表示层 | ↑ | 数据格式转换、加密解密、压缩 | SSL/TLS, JPEG, ASCII |
| 5. 会话层 | ↑ | 建立、管理和终止会话 | RPC, NetBIOS |
| 4. 传输层 | 传输层 | 端到端可靠传输、差错恢复 | TCP, UDP |
| 3. 网络层 | 网络层 | 路由选择、逻辑寻址 | IP, ICMP, ARP, OSPF, RIP |
| 2. 数据链路层 | 网络接口层 | 帧的封装与传输、差错检测 | Ethernet, PPP, VLAN |
| 1. 物理层 | ↑ | 比特流传输、电气信号 | 双绞线, 光纤, 集线器 |

> **记忆口诀（从下往上）**：物链网传会表应 —— "物理链路网络传，会面表意应天象"

## 二、物理层

### 2.1 核心概念

| 概念 | 要点 |
|:---|:---|
| 数据通信系统 | 源系统 → 传输网络 → 目的系统 |
| 信道容量 | 信道能传输的最大数据率（比特/秒） |
| 基带传输 | 数字信号不调制直接传输（局域网常用） |
| 宽带传输 | 模拟信号调制后传输（广域网常用） |
| 单工 | 只能单向通信（如广播） |
| 半双工 | 双向但不能同时（如对讲机） |
| 全双工 | 双向且同时（如电话） |

### 2.2 传输介质

| 介质 | 特点 | 应用场景 |
|:---|:---|:---|
| 双绞线（UTP/STP） | 成本低、易安装，衰减较大 | 局域网（Cat5e/Cat6） |
| 同轴电缆 | 抗干扰强，带宽较高 | 有线电视、老式以太网 |
| 光纤 | 速率极高、抗干扰、距离远 | 骨干网、城域网 |
| 无线（微波/卫星） | 移动性强，受环境影响 | 移动通信、卫星通信 |

### 2.3 编码与调制

| 方式 | 说明 |
|:---|:---|
| 数字→数字（基带编码） | NRZ、曼彻斯特编码、差分曼彻斯特 |
| 数字→模拟（调制） | ASK、FSK、PSK、QAM |
| 模拟→数字（PCM） | 采样 → 量化 → 编码（电话系统） |
| 模拟→模拟（调幅/频/相） | AM、FM、PM |

> **曼彻斯特编码特点**：每个比特周期中间有一次跳变，既编码数据又自带时钟同步。

### 2.4 核心定理

| 定理/准则 | 内容 | 公式 |
|:---|:---|:---|
| 奈奎斯特定理 | 无噪声信道最大码元速率 | C = 2W log₂(V)（W=带宽，V=码元级数） |
| 香农定理 | 有噪声信道最大数据率 | C = W log₂(1 + S/N)（S/N=信噪比） |
| 信噪比转换 | dB 与比值换算 | SNR(dB) = 10 log₁₀(S/N) |

> **记忆口诀**：奈奎无噪看带宽，香农有噪加信噪 —— "奈无香有"

## 三、数据链路层

### 3.1 核心功能

| 功能 | 说明 |
|:---|:---|
| 帧定界 | 标识帧的开始和结束（标志字段 01111110） |
| 差错检测 | CRC校验、奇偶校验、海明码 |
| 差错纠正 | 自动重传请求(ARQ)、前向纠错(FEC) |
| 流量控制 | 滑动窗口协议（发送窗口/接收窗口） |
| 介质访问控制 | 信道分配问题 |

### 3.2 差错控制对比

| 方式 | 原理 | 适用场景 |
|:---|:---|:---|
| 奇偶校验 | 添加1位使1的个数为奇/偶 | 简单检测，无法纠正 |
| CRC 循环冗余校验 | 多项式除法，余数为校验码 | 广泛使用（以太网、PPP） |
| 海明码 | 添加多个校验位，可纠1位错 | 需要纠错的场景 |

### 3.3 流量控制协议

| 协议 | 发送窗口 | 接收窗口 | 特点 |
|:---|:---:|:---:|:---|
| 停等协议 | 1 | 1 | 简单但效率低 |
| 后退N帧(GBN) | N | 1 | 发送方超时重传所有已发帧 |
| 选择重传(SR) | N | N | 只重传出错帧，效率最高 |

### 3.4 介质访问控制

#### CSMA/CD（有线以太网）

| 要点 | 说明 |
|:---|:---|
| 全称 | Carrier Sense Multiple Access / Collision Detection |
| 工作流程 | 先听后发 → 边听边发 → 冲突停发 → 随机重发 |
| 最小帧长 | 64字节（保证能检测到冲突） |
| 争用期 | 2τ（端到端往返传播时延） |
| 截断二进制指数退避 | 第 k 次冲突，从 {0,1,...,2^min(k,10)-1} 随机选 |
| 适用 | 早期共享式以太网（Hub），现代交换式以太网已无冲突 |

#### CSMA/CA（无线局域网）

| 要点 | 说明 |
|:---|:---|
| 全称 | Carrier Sense Multiple Access / Collision Avoidance |
| 为什么用CA不用CD | 无线信号衰减大，冲突检测困难 |
| 核心机制 | 发送前等待 DIFS → RTS/CTS 握手 → 数据帧 → ACK确认 |
| NAV | 网络分配向量，其他站据此知道信道忙多久 |
| 适用 | Wi-Fi (802.11) |

> **记忆口诀**：CSMA/CD 有线检测冲突，CSMA/CA 无线避免冲突 —— "有检无避"

### 3.5 以太网帧格式

| 字段 | 长度 | 说明 |
|:---|:---:|:---|
| 前导码 | 8字节 | 7字节同步 + 1字节帧定界（10101010...10101011） |
| 目的 MAC | 6字节 | 接收方物理地址 |
| 源 MAC | 6字节 | 发送方物理地址 |
| 类型/长度 | 2字节 | 标识上层协议（如0x0800=IPv4） |
| 数据 | 46~1500字节 | 载荷 |
| FCS | 4字节 | CRC校验 |
| **最小帧长** | **64字节** | 6+6+2+46+4=64 |

### 3.6 PPP 协议

| 要点 | 说明 |
|:---|:---|
| 全称 | Point-to-Point Protocol |
| 特点 | 点对点、简单、无序号、无确认 |
| 三个组成部分 | 链路控制协议(LCP) + 网络控制协议(NCP) + 数据封装 |
| 帧定界 | 0x7E 标志，转义字符 0x7D |
| 认证 | PAP（明文）/ CHAP（挑战握手） |

### 3.7 交换机与 VLAN

| 概念 | 说明 |
|:---|:---|
| 交换机工作层 | 数据链路层（二层交换） |
| 自学习 | 根据源MAC地址建立转发表 |
| 转发规则 | 查表转发/泛洪/丢弃 |
| 冲突域 | 交换机每个端口是一个独立冲突域 |
| 广播域 | 交换机默认同一广播域，VLAN可隔离 |
| VLAN | 虚拟局域网，802.1Q标签（4字节VLAN tag） |

## 四、网络层

### 4.1 IP 地址分类

| 类别 | 首字节范围 | 默认子网掩码 | 网络号/主机号 | 可用网络数 | 可用主机数 |
|:---:|:---:|:---:|:---:|:---:|:---:|
| A | 1~126 | 255.0.0.0 (/8) | 7位/24位 | 126 | 16,777,214 |
| B | 128~191 | 255.255.0.0 (/16) | 14位/16位 | 16,384 | 65,534 |
| C | 192~223 | 255.255.255.0 (/24) | 21位/8位 | 2,097,152 | 254 |
| D | 224~239 | — | 多播地址 | — | — |
| E | 240~255 | — | 保留 | — | — |

**特殊地址**：

| 地址 | 含义 |
|:---|:---|
| 0.0.0.0 | 本网络本主机 |
| 255.255.255.255 | 有限广播（本网络） |
| 127.x.x.x | 环回地址（本机） |
| 主机号全0 | 网络地址 |
| 主机号全1 | 直接广播地址 |

### 4.2 私有 IP 地址（RFC1918）

| 范围 | C 类地址数 | 适用规模 |
|:---|:---:|:---|
| 10.0.0.0~10.255.255.255 | 1个A类 | 大型 |
| 172.16.0.0~172.31.255.255 | 16个B类 | 中型 |
| 192.168.0.0~192.168.255.255 | 256个C类 | 小型 |

### 4.3 子网划分

**子网掩码规则**：IP地址 AND 子网掩码 = 网络地址

| 示例 | IP | 掩码 | 网络地址 |
|:---|:---|:---|:---|
| /24 | 192.168.1.100 | 255.255.255.0 | 192.168.1.0 |
| /26 | 192.168.1.100 | 255.255.255.192 | 192.168.1.64 |

**CIDR（无类域间路由）**：
- 去除传统分类，用 /n 表示前缀长度
- 子网划分：主机位借位给子网
- 路由聚合（超网）：多个网络合并为更大的地址块

**主机数计算**：
- 可用主机数 = 2^(32-前缀长度) - 2（减去网络地址和广播地址）

### 4.4 路由算法

| 算法类型 | 代表协议 | 特点 |
|:---|:---|:---|
| 距离向量 | RIP | 基于跳数（最多15跳），周期广播，收敛慢 |
| 链路状态 | OSPF | Dijkstra算法，触发更新，收敛快 |
| 路径向量 | BGP | AS间路由策略，基于策略而非最短路径 |

| 协议 | 层次 | 算法 | 收敛速度 | 适用范围 |
|:---|:---:|:---|:---:|:---|
| RIP | 内部网关 | 距离向量 | 慢 | 小型自治系统 |
| OSPF | 内部网关 | 链路状态 | 快 | 大中型自治系统 |
| BGP | 外部网关 | 路径向量 | 中 | 自治系统之间 |

> **记忆口诀**：RIP 跳数限15，OSPF 链路看带宽，BGP 策略走天下

### 4.5 ARP 协议

| 要点 | 说明 |
|:---|:---|
| 全称 | Address Resolution Protocol（地址解析协议） |
| 功能 | IP地址 → MAC地址 |
| 工作层 | 网络层（封装在以太网帧中） |
| 工作流程 | 广播ARP请求 → 目标单播ARP响应 |
| 缓存 | ARP表有生存时间，超时删除 |
| 跨网段 | 通过网关（默认网关）进行ARP |

> **ARP 只在局域网内使用，跨网段走的是网关的MAC地址。**

### 4.6 ICMP 协议

| 类型 | 说明 |
|:---|:---|
| 差错报告报文 | 目的不可达、超时、源抑制、参数问题 |
| 询问报文 | 回送请求/回答（ping）、时间戳请求/回答 |
| 工具 | ping（ICMP回送）、traceroute（利用TTL超时） |
| 位置 | 封装在IP数据报中（协议号1） |

### 4.7 NAT（网络地址转换）

| 类型 | 说明 |
|:---|:---|
| 静态NAT | 一对一固定映射 |
| 动态NAT | 地址池中动态分配 |
| PAT/NAPT | 端口地址转换，多对一，最常用 |
| 应用 | 解决IPv4地址不足、隐藏内网结构 |
| 缺点 | 破坏端到端原则，影响P2P应用 |

## 五、传输层

### 5.1 TCP vs UDP 对比

| 特性 | TCP | UDP |
|:---|:---|:---|
| 连接方式 | 面向连接（三次握手） | 无连接 |
| 可靠性 | 可靠传输（确认+重传） | 不可靠（尽最大努力） |
| 传输方式 | 字节流 | 数据报 |
| 有序性 | 保序 | 不保序 |
| 流量控制 | 有（滑动窗口） | 无 |
| 拥塞控制 | 有（慢开始/拥塞避免） | 无 |
| 首部开销 | 20字节（最小） | 8字节 |
| 传输效率 | 较低 | 较高 |
| 适用场景 | 文件传输、邮件、网页 | 视频流、DNS、游戏、VoIP |

> **记忆口诀**：TCP 可靠有序慢，UDP 快速轻量丢包不慌

### 5.2 TCP 三次握手

```
客户端                          服务器
  |  --- SYN=1, seq=x ------->  |    第1次：客户端发SYN
  |  <-- SYN=1,ACK=1,seq=y,   |    第2次：服务器发SYN+ACK
  |       ack=x+1 ------------  |
  |  --- ACK=1,seq=x+1,      |    第3次：客户端发ACK
  |       ack=y+1 ----------->  |
  |                              |
        连接建立，开始传输
```

**关键问题**：
- 为什么三次：防止已失效的连接请求到达服务器造成资源浪费
- 为什么不是两次：服务器无法确认客户端收到了自己的SYN
- SYN洪泛攻击：大量伪造SYN耗尽服务器资源，可用SYN Cookie防御

### 5.3 TCP 四次挥手

```
客户端                          服务器
  |  --- FIN=1,seq=u ------->  |    第1次：客户端发FIN（不再发数据）
  |  --- ACK=1,ack=u+1 ----->  |    第2次：服务器确认
  |  （服务器可能继续发送数据）      |
  |  <-- FIN=1,seq=w --------  |    第3次：服务器发FIN
  |  --- ACK=1,ack=w+1 ----->  |    第4次：客户端确认
  |                              |
  |  [TIME_WAIT 2MSL]           |
        连接关闭
```

**关键问题**：
- 为什么四次：TCP全双工，双方需各自关闭
- TIME_WAIT（2MSL）：确保最后ACK到达、防止旧连接干扰新连接
- 主动关闭方进入TIME_WAIT，被动关闭方进入CLOSE_WAIT

### 5.4 TCP 拥塞控制

| 算法 | 策略 | 说明 |
|:---|:---|:---|
| 慢开始 | 指数增长 | 初始cwnd=1MSS，每个RTT翻倍 |
| 拥塞避免 | 线性增长 | cwnd达到ssthresh后每个RTT加1 |
| 快重传 | 收到3个重复ACK立即重传 | 不等超时 |
| 快恢复 | ssthresh=cwnd/2, cwnd=ssthresh | 调整后进入拥塞避免 |

**拥塞窗口变化**：
```
cwnd
 |        /\       /\      拥塞避免（线性）
 |       /  \     /  \     
 |      /    \   /    \    
 |     / 慢开始 \ /    \   
 |    / (指数)   X 快恢复  
 |   /          /      
 |  / ssthresh /       
 | /    |     /        
 |/     |    /         
 +------+---+---------→ 时间
        超时     3个重复ACK
```

### 5.5 TCP 流量控制

| 概念 | 说明 |
|:---|:---|
| 滑动窗口 | 接收方通告接收窗口(rwnd)，发送方不超过该值 |
| 零窗口 | 接收方窗口为0时，发送方暂停并发送探测报文 |
| Nagle算法 | 小数据包合并发送，减少网络开销 |
| 延迟确认 | 合并数据和ACK，减少报文数 |

## 六、应用层

### 6.1 DNS（域名系统）

| 要点 | 说明 |
|:---|:---|
| 功能 | 域名 ↔ IP地址 映射 |
| 层次结构 | 根域 → 顶级域 → 二级域 → 三级域 |
| 递归查询 | 客户端 → 本地DNS → 根 → 顶级 → 权威 → 逐级返回 |
| 迭代查询 | 每级DNS返回下一级地址，客户端自行查询 |
| 缓存 | 各级DNS均有缓存，TTL控制有效期 |
| 记录类型 | A(IPv4), AAAA(IPv6), CNAME(别名), MX(邮件), NS(名称服务器) |
| 端口 | 53（UDP为主，区域传送用TCP） |

**DNS 解析过程**：
```
浏览器输入 www.example.com
  ↓
1. 检查浏览器缓存
  ↓
2. 检查操作系统缓存（/etc/hosts）
  ↓
3. 向本地DNS服务器发起递归查询
  ↓
4. 本地DNS依次查询：根 → .com → example.com
  ↓
5. 返回 IP 地址，各级缓存该结果
```

### 6.2 HTTP（超文本传输协议）

| 版本 | 特点 |
|:---|:---|
| HTTP/1.0 | 短连接，每次请求独立TCP连接 |
| HTTP/1.1 | 长连接（Keep-Alive），管道化 |
| HTTP/2 | 多路复用，头部压缩，服务器推送，二进制分帧 |
| HTTP/3 | 基于QUIC（UDP），解决队头阻塞 |

**HTTP 方法**：

| 方法 | 含义 | 幂等 | 安全 |
|:---:|:---|:---:|:---:|
| GET | 获取资源 | 是 | 是 |
| POST | 提交数据 | 否 | 否 |
| PUT | 更新资源（全量替换） | 是 | 否 |
| DELETE | 删除资源 | 是 | 否 |
| HEAD | 只获取头部 | 是 | 是 |
| OPTIONS | 查询支持的方法 | 是 | 是 |

**状态码**：

| 范围 | 类别 | 典型 |
|:---:|:---|:---|
| 1xx | 信息 | 100 Continue |
| 2xx | 成功 | 200 OK, 201 Created, 204 No Content |
| 3xx | 重定向 | 301 永久, 302 临时, 304 未修改 |
| 4xx | 客户端错误 | 400 Bad Request, 403 Forbidden, 404 Not Found |
| 5xx | 服务器错误 | 500 Internal Error, 502 Bad Gateway, 503 Unavailable |

### 6.3 FTP（文件传输协议）

| 要点 | 说明 |
|:---|:---|
| 工作方式 | C/S 架构 |
| 双连接 | 控制连接（21端口）+ 数据连接（20端口） |
| 主动模式(PORT) | 服务器主动连接客户端的数据端口 |
| 被动模式(PASV) | 客户端主动连接服务器的临时端口 |
| 传输方式 | ASCII模式（文本）/ 二进制模式 |

### 6.4 SMTP 与 POP3/IMAP

| 协议 | 功能 | 端口 | 特点 |
|:---|:---|:---:|:---|
| SMTP | 发送邮件 | 25/587 | 推协议，ASCII编码 |
| POP3 | 接收邮件 | 110 | 拉协议，下载后可删除服务器副本 |
| IMAP | 接收邮件 | 143 | 拉协议，支持文件夹管理，服务器保留邮件 |

> **记忆口诀**：SMTP 推出去（发邮件），POP/IMAP 拉回来（收邮件）

### 6.5 DHCP（动态主机配置协议）

| 要点 | 说明 |
|:---|:---|
| 功能 | 自动分配IP地址、子网掩码、网关、DNS服务器 |
| 端口 | 客户端 68（UDP），服务器 67（UDP） |
| 过程（DORA） | Discover → Offer → Request → Acknowledge |
| 广播 | Discover 和 Request 是广播，Offer 和 Acknowledge 也是广播 |
| 租约 | IP地址有时限，到期需续租 |

## 七、综合速记表

### 7.1 协议层次与封装

```
应用层数据（HTTP报文）
    ↓ 加TCP首部
传输层（TCP段）
    ↓ 加IP首部
网络层（IP数据报）
    ↓ 加帧头帧尾
数据链路层（以太网帧）
    ↓ 转换为比特流
物理层（比特流）
```

### 7.2 各层设备对照

| 层次 | 设备 | 寻址依据 |
|:---|:---|:---|
| 物理层 | 集线器(Hub)、中继器 | 无 |
| 数据链路层 | 交换机(Switch)、网桥 | MAC地址 |
| 网络层 | 路由器(Router) | IP地址 |
| 应用层 | 网关(Gateway)、代理服务器 | 应用数据 |

### 7.3 TCP/IP 协议族全景

| 层次 | 协议 | 用途 |
|:---|:---|:---|
| 应用层 | HTTP/HTTPS | 网页浏览 |
| 应用层 | FTP/TFTP | 文件传输 |
| 应用层 | SMTP/POP3/IMAP | 电子邮件 |
| 应用层 | DNS | 域名解析 |
| 应用层 | DHCP | 动态IP分配 |
| 应用层 | Telnet/SSH | 远程登录 |
| 应用层 | SNMP | 网络管理 |
| 传输层 | TCP | 可靠传输 |
| 传输层 | UDP | 快速传输 |
| 网络层 | IP (IPv4/IPv6) | 逻辑寻址 |
| 网络层 | ICMP | 差错报告 |
| 瑑络层 | ARP/RARP | 地址解析 |
| 网络层 | IGMP | 组播管理 |
| 网络层 | OSPF/RIP/BGP | 路由选择 |

### 7.4 易混淆概念辨析

| 概念A | 概念B | 区别 |
|:---|:---|:---|
| MAC地址 | IP地址 | 物理层标识 vs 逻辑标识，MAC不变IP可变 |
| 集线器 | 交换机 | 集线器广播转发，交换机查表转发 |
| 路由器 | 交换机 | 路由器三层（IP），交换机二层（MAC） |
| ARP | RARP | IP→MAC vs MAC→IP（RARP已基本淘汰） |
| TCP | UDP | 可靠有序 vs 快速无连接 |
| CSMA/CD | CSMA/CA | 有线检测冲突 vs 无线避免冲突 |
| 拥塞控制 | 流量控制 | 全局网络负载 vs 点对点速率匹配 |
| 静态路由 | 动态路由 | 手工配置 vs 协议自动学习 |
| NAT | 代理 | 网络层地址转换 vs 应用层转发 |

## 八、经典考题速记

| 考点 | 答案/要点 |
|:---|:---|
| TCP为什么三次握手 | 防止历史连接初始化，同步双方初始序列号 |
| TCP为什么四次挥手 | 全双工，每个方向需单独关闭 |
| TIME_WAIT等待多久 | 2MSL（最大报文段生存时间的两倍） |
| TCP和UDP首部最小长度 | TCP 20字节，UDP 8字节 |
| 以太网最小帧长 | 64字节 |
| 以太网最大帧长 | 1518字节（1500数据+18开销） |
| ARP工作在哪一层 | 网络层（但封装在以太网帧中） |
| ICMP工作在哪一层 | 网络层（封装在IP数据报中） |
| 交换机工作在哪一层 | 数据链路层 |
| 路由器工作在哪一层 | 网络层 |
| NAT解决什么问题 | IPv4地址不足 + 内网安全 |
| RIP最大跳数 | 15跳（16表示不可达） |
| OSPF用什么算法 | Dijkstra最短路径优先算法 |
| BGP是内部还是外部网关协议 | 外部网关协议（AS之间） |
| DNS默认端口 | 53（UDP为主） |
| HTTP默认端口 | 80，HTTPS默认443 |
| DHCP四步流程 | DORA：Discover→Offer→Request→Ack |
| 慢开始的初始拥塞窗口 | 1个MSS |
| 快重传触发条件 | 收到3个重复ACK |
| 滑动窗口大小取决于 | 接收方的接收窗口 |
| 拥塞控制窗口大小取决于 | 拥塞窗口cwnd和接收窗口rwnd的较小值 |
