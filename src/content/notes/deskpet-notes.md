## 出发点

想做一个桌面宠物，但市面上的桌宠大多角色与程序耦合在一起：换个形象就要改代码，加个功能就要动动画逻辑。于是定了一个核心思路——**角色 = 资源包**：桌宠引擎只负责跑，角色是数据（.pet 包，config.json 驱动），不写代码也能换形象。

## 两个关键设计

**状态系统**：idle / focus / sleep / happy / warning 五种状态，不是写死的动画序列，而是由事件中心决策驱动（优先级 + 去重 + 过期管理）。这样桌宠的"心情"来自真实系统状态：CPU 高负载、用户空闲、电池低、复制了敏感内容，都会变成事件，事件再决定表现。

**事件中心**：可插拔数据源架构（系统监控 / 插件 / 剪贴板 / 目录 / 前台应用），统一表驱动。之后加新数据源不用改桌宠本体，注册一个 source 就行。

## 剪贴板拟人化与安全边界

复制链接、代码、长文、图片时，桌宠会按特征从台词池回应；但**敏感内容（token / 密码 / 卡号 / 验证码）原文绝不进入 IPC**——只把"类型"告诉桌宠，不把内容传过去。这是做桌面工具时最容易踩的边界，先划清楚再谈互动。

## 本地优先的扩展口

- **陪伴统计**：时长 / 状态分布 / 热力图 / 周报月报 / 年度导出
- **事件推送 API**：本地 HTTP `POST /api/event`（Bearer 认证），第三方程序可以把事件推给桌宠表达
- **控制中心**：角色 / 台词池 / 日程 / 统计 / 推送 / 事件等 10 个页签

## 工程取舍

- Electron 主进程 + preload 白名单 API 桥（contextIsolation + sandbox）+ 两个 React 19 渲染应用（桌宠窗口 / 控制中心），跨进程契约放 shared/ 类型化
- **零运行时新依赖，全程本地离线**——桌面工具不依赖网络，构建验证全靠脚本
- 450 例单测兜底，迭代节奏 v0.1 桌宠本体 → v0.2 事件中心 → v0.5 统计 → v0.8 推送 API → v0.9 剪贴板互动 → v1.0 事件通知页

## 现状

v1.0 正式版（GPL-3.0），角色包生态继续扩展中，计划支持更多动画模板与社区市场。
