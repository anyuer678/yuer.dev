## 索引是什么

索引是对表的一列或多列排序的结构，像书的目录：没有索引时查 `WHERE name = '张三'` 要全表扫描逐行检查；有索引时先在索引里定位记录物理地址，再直接读数据。核心作用：加快查询、保证唯一性、加速连接、减少排序/分组时间。

**优缺点平衡**：优点是查询快；代价是占物理空间、增删改时要同步维护索引、索引越多维护成本越高。所以索引不是越多越好。

## 按存储结构：聚簇 vs 非聚簇

**聚簇索引（Clustered Index）**：索引顺序 = 数据物理存储顺序。一个表只能有一个（InnoDB 主键默认就是聚簇索引）。范围查询和排序快，但插入/删除/更新要移动数据，开销大。

**非聚簇索引（Non-clustered Index）**：索引顺序与物理存储无关，一个表可多个。索引只存索引列值 + 指向数据行的指针，查询要两次查找（先找索引再找数据，即回表）。

## 按功能分类

| 类型 | 特点 |
|---|---|
| 普通索引 | 无限制，加速查询 |
| 唯一索引 | 值必须唯一，允许 NULL（NULL 不等于 NULL，可多个） |
| 主键索引 | 特殊的唯一索引，不允许 NULL，一表一个，常为聚簇 |
| 复合索引 | 多列索引，遵循最左前缀原则 |

## 四种索引数据结构

### B 树 vs B+ 树（关系型数据库主力）

- B 树每个节点既存键又存数据，B+ 树只有叶子存数据、内部节点只存键
- B+ 树叶子节点用链表串联，**范围查询和顺序遍历极快**（顺着叶子链走即可）
- B+ 树矮胖、扇出大，磁盘 IO 次数少
- 结论：关系库索引基本都用 B+ 树（InnoDB/MyISAM 的默认索引结构）

### 哈希索引

哈希函数把键映射到哈希桶，碰撞用链表/开放寻址处理。**等值查询 O(1)**，比 B+ 树快；但不支持范围查询、排序、前缀匹配（LIKE 张%）、复合索引的部分列查询。适合登录校验（`WHERE username=? AND password=?`）、订单按 id 查这类纯等值场景。MySQL Memory 引擎默认用它，InnoDB 有自适应哈希索引，Redis 底层也是哈希表。

### 位图索引

每一位表示「某行是否含某值」，适合**低基数列**（性别、状态、部门这种取值少的列）。空间省、位运算（AND/OR/NOT）快、多条件组合效率高；但高基数列会膨胀、频繁更新要改多个位图且锁粒度大。用于数据仓库/决策支持（Oracle、SQL Server、PostgreSQL 插件支持）。

### R 树

用最小边界矩形（MBR）组织**空间数据**，支持点查询、范围、最近邻、包含/相交等空间关系查询。MySQL 空间索引、PostgreSQL PostGIS、Oracle 空间索引都用它。

### 倒排索引

**正排**是 文档→关键词，**倒排**是 关键词→文档列表，搜索引擎的核心。支持全文/短语/模糊搜索，Elasticsearch、Solr、MySQL 全文索引都基于它。

## 索引设计原则

**该建索引的列**：WHERE 常出现、ORDER BY/GROUP BY 常用、JOIN 连接列、选择性高（不同值多，如主键/唯一键选择性=1）的列、数据类型小的列（INT 优于 VARCHAR）。

**不该建索引的列**：很少查询、选择性低（性别/状态）、频繁更新、小表（全表扫描更快）、TEXT/BLOB 大对象列。

**复合索引**：
- **最左前缀**：索引 (a, b, c)，`WHERE a=1`、`a=1 AND b=2`、`a=1 AND b=2 AND c=3` 都能用；`WHERE b=2 AND c=3`（没 a）用不上；`a=1 AND c=3` 只用 a
- 选择性高的列放前面；按实际查询模式定列序；一般不超过 5 列
- 覆盖索引最好：索引包含查询需要的所有列，不用回表

**其他**：索引列尽量 NOT NULL；长字符串用前缀索引；避免在索引列上用函数或运算；定期重建/清理无用索引。

## EXPLAIN 与查询优化

`EXPLAIN SELECT ...` 看执行计划，重点看：

- **type（访问类型）**：`system > const > eq_ref > ref > range > index > ALL`，ALL 是全表扫描要避免
- **key**：实际用到的索引；**rows**：预计扫描行数
- **Extra**：`Using index`（覆盖索引，好）、`Using temporary`（临时表，不好）、`Using filesort`（文件排序，不好）

**常见优化手段**：

- 索引列上别用函数：`WHERE YEAR(create_time)=2024` 改用 `create_time >= '2024-01-01' AND create_time < '2025-01-01'`
- 别 `SELECT *`，只查需要的列，配合覆盖索引
- 避免隐式类型转换：`id = '123'` 改 `id = 123`
- `LIKE '%张三'` 前导通配符用不上索引，`LIKE '张三%'` 可以
- OR 条件可能用不上索引，可改写为 UNION
- 小表驱动大表，JOIN 列建索引

## 一句话总结

- 聚簇=物理顺序跟随索引（一表一个）；非聚簇=指针回表
- B+ 树管范围与排序；哈希只管等值；位图给低基数列；R 树管空间；倒排管全文
- 索引是空间换时间，先了解查询模式再设计，别贪多
