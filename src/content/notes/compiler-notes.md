## 编译过程总览

编译器把高级语言翻译成目标机器代码，分**前端**（与机器无关：词法/语法/语义/中间代码）和**后端**（与机器相关：优化/目标代码生成）。

```
源程序 → 词法分析 → 记号流 → 语法分析 → 语法树 → 语义分析 → 中间代码 → 优化 → 目标代码
```

**解释器 vs 编译器**：解释器边翻译边执行（无独立目标文件）；编译器整体翻译后执行。Java 是「编译+解释」混合（字节码 + JVM）；现代 JS/Python 用 JIT（热点代码编译成机器码）。

## 词法分析

**作用**：读入源程序字符流，识别出**记号（token）**，丢弃空白与注释。记号 = 类别（关键字/标识符/常数/运算符/界符）+ 属性值（如标识符名字、常数值）。

**正则表达式**描述记号：字符类 `[a-z]`、闭包 `*`（0 次以上）、正闭包 `+`、可选 `?`、选择 `|`、连接。标识符正则如 `[A-Za-z_][A-Za-z0-9_]*`。

**有限自动机**：

- NFA（非确定）：同一状态同一输入可有多个转移，含 ε 转移
- DFA（确定）：每状态每输入至多一个转移
- 转换：正则 → NFA（Thompson 构造）→ DFA（子集构造法）→ 最小化 DFA（等价类划分）
- NFA 模拟（回溯/子集）或直接构造 DFA 都行，实际工具（lex/flex）直接生成 DFA 表驱动

**实现**：最长匹配原则（选最长的可行前缀）、优先级（关键字优先于标识符）。词法分析器可手工（逐字符状态机）或工具生成（flex）。

## 语法分析

**作用**：按文法检查记号序列是否符合语法规则，构造**语法树（推导树）**。文法 G=(V,T,P,S)：终结符、非终结符、产生式、开始符号。

**二义性**：一个句子存在两棵不同语法树。消除：改写文法（如算术优先级分层 expr → term → factor）或规定优先级与结合性。

**自上而下分析（LL）**：

- 递归下降：每个非终结符一个函数，预测下一个记号选择产生式；需消除左递归（A→Aα|β 改写为 A→βA'、A'→αA'|ε）与提取左公因子
- LL(1)：向前看 1 个记号即可决定；需计算 FIRST（可推导出的首终结符集）与 FOLLOW（可能跟随的终结符集）；预测分析表 + 驱动栈
- 递归下降常配合错误恢复（同步记号、跳过记号）

**自下而上分析（LR）**：从输入逐步**归约**到开始符号（规范归约 = 最右推导的逆过程）。

- 移进-归约：栈上状态 + 输入；冲突：移进/归约、归约/归约
- SLR(1)/LR(1)/LALR(1)：LR(1) 最强大但表大；LALR(1) 合并同心项目集，是 yacc/bison 采用族
- 优先关系法（算符优先）用于表达式

**判定要点**：LR 类分析器能处理的语言比 LL 类更广；手写编译器常用递归下降，工具生成常用 LALR(1)。

## 语法制导翻译与属性文法

**属性文法** = 上下文无关文法 + 属性 + 语义规则。属性两类：

- **综合属性**：由子节点向上计算（如表达式值、类型）；适合自下而上分析时顺便算
- **继承属性**：由父/兄弟向下传递（如声明表中的变量类型）

**语法制导定义（SDD）**：在产生式上挂语义动作；**语法制导翻译方案（SDT）** 把动作嵌入产生式右部。实现：分析时随归约执行动作（yacc 的 `$$ = $1 + $3`），或建立语法树后遍历。

**抽象语法树（AST）**：去掉仅用于分析的非终结符，保留运算结构，是后续阶段的主要输入。

## 语义分析与中间表示

**语义分析**：类型检查（声明与使用一致、运算数类型匹配）、作用域解析、变量绑定到声明。

**中间表示（IR）**：

- 三地址码 / 四元式：`(op, arg1, arg2, result)`，如 `t1 = a + b`；每条语句至多一个运算符
- 三元式 / 间接三元式（共享公共子表达式）
- DAG（有向无环图）：合并公共子表达式
- 静态单赋值 SSA（每个变量只赋值一次，优化友好，LLVM 用）

**三地址码生成**：把 AST/语法树线性化，每个节点一个临时变量；控制流用 goto 与标号（`if x < y goto L1`）。

## 代码生成

**目标**：把 IR 翻译成目标机器指令，考虑寄存器分配与指令选择。评价指标：正确、高效、可重定位。

- **指令选择**：IR 操作 → 目标指令（含寻址方式选择），树覆盖/模板匹配
- **寄存器分配**：图着色法（活跃变量干扰图）、线性扫描；寄存器不够时**溢出（spill）**到内存
- **临时变量管理**：栈帧中分配，活动记录（activation record）含参数、返回地址、局部变量、保存的寄存器

**基本块与流图**：基本块 = 单入口单出口的连续指令序列；入口指令 = 首条/跳转目标/跳转后一条；块间跳转构成控制流图，供优化与寄存器分配使用。

## 代码优化

分类：机器无关（中间代码层）与机器相关（目标代码层）。常见优化：

- **常量折叠/传播**：编译期算常量；`x = 2*3` → `x = 6`
- **公共子表达式删除**：同一表达式只算一次（DAG 合并）
- **复制传播**：`a = b` 后用 b 替 a
- **死代码删除**：删除不被引用/无副作用的分支
- **循环优化**：强度削减（乘变加）、循环不变量外提（把循环内不变的计算移到循环外）、循环展开、归纳变量删除
- **代码提升/下沉**、内联展开

**数据流分析**：定值-使用链（def-use）、到达定值、活跃变量（live variables）——寄存器分配与死代码删除的基础。

## 运行时环境

**存储组织**：静态区（全局变量）、栈（活动记录，函数调用）、堆（动态分配）。过程调用约定：保存返回地址、传参（寄存器/栈）、栈帧指针。

**作用域与符号表**：符号表（名字 → 属性：类型、地址、作用域）；块结构语言用作用域栈，进入块压入、退出弹出。

**非局部访问**：静态链（外层作用域指针）、显示表 display；参数传递：值传递（拷贝）、引用传递（传地址）、值-结果传递。

**垃圾回收**：引用计数（循环引用泄漏）、标记-清除、复制式（停止-复制）、分代回收（新生代/老年代）。

## 速记口诀

- 前端管「对不对、什么样」，后端管「怎么跑、跑得快」
- 词法：正则描述，自动机识别；语法：文法描述，LL/LR 分析
- LR 比 LL 强；递归下降好手写，yacc 类用 LALR(1)
- 综合属性向上算，继承属性向下传
- 优化三件套：常量折叠、公共子表达式删除、死代码删除
- 易错点：消除左递归才能 LL；算符优先只看相邻运算符
