# 第一章 操作系统简介
## 1.1 操作系统的主要共性功能
- 硬件角度:管理硬件(操作硬件以完成功能) 抽象硬件(应用不关心硬件差异)
- 软件角度:服务应用(提供硬件操作) 管理应用(加载调度等)
## 1.2操作系统发展
### 1.2.1 批处理操作系统 GM NAAI/O
Robert L. Patrick和Owen Mock于1956年建设运行在IBM 704上

主要功能：批处理运行任务
### 1.2.2 通用系统 OS/360
IBM System/360 OS 1964

- 首个通用操作系统，首次将操作系统与计算机分离
- 架构师：Gene Amdahl (Amdahl’s Law)
- 项目经理：Fred Brooks (《人月神话》，1999年图灵奖得主)
### 1.2.3 对称与非对称多处理器
多处理器系统又称并行系统或者多核系统

优点：提高吞吐量、规模经济、提高可靠性

- 非对称多处理系统:由一个处理器来操纵系统（主处理器），其他处理器向主处理器要任务或者做预先分配好的任务
- 对称多处理器系统:每个处理器都参与操作系统的所有任务，处理器之间是对等关系。每个处理器都有自己的寄存器集和缓存，但是共享内存。
## 1.3 系统调用
系统调用:应用调用操作系统的机制，实现应用不能实现的功能

- 应用通过CPU的陷入机制进行模式切换（非特权→特权）*有多种陷入方式，包括特定指令、异常、硬件中断等*
- 操作系统内核通过特定的硬件指令返回应用（特权→非特权） *通常只有一种返回方式：如ARM的eret*
# 第二章 操作系统架构
## 2.1 管理操作系统复杂性的方法 (M.A.L.H)方法：
- 模块化 通过分而治之的原则，将一个复杂系统分解为一系列通过明确定义的接口进行交互的模块，并严格保障模块之间的界限。
- 抽象 在模块化的基础上将接口与内部实现分离，从而使模块之间只需通过抽象的接口进行相互调用，而无须关心各个模块间的内部实现。
- 分层 将模块按照一定的原则进行层次划分，约束每层内模块间与跨层次模块间的交互方式，从而有效减少模块之间的交互。
- 层级 层级是另一种模块的组织方式首先将一些功能相近的模块组成一个具有清晰接口的自包含子系统，然后再将这些子系统递归式地组成一个具有清晰接口的更大子系统。
## 2.2 操作系统内核架构及典型OS
### 2.2.1 简要结构，所属的操作系 MS-DOS
将应用程序和操作系统放置在一个层级上，以同样的权限运行。

MS-DOS是一个典型例子

优势在于无需切换权限层级，更加高效

缺点很明显，缺乏良好的隔离能力，任何一个模块出现问题，都会导致操作系统崩溃
### 2.2.2 宏内核 Unix, Linux 和Windows
又称单内核

整个系统分为内核与应用两层:
- 内核:运行在特权级 集中控制所有计算资源
- 外核:应用在非特权级 使用内核服务

缺点:
- 安全性:模块之间没有很强的管理机制
- 系统太复杂无法做最坏情况时延分析
- 系统过于庞大:Linux

宏内核难以满足的场景:
- 向上向下的扩展
- 硬件异构性
- 功能安全
- 信息安全
- 确定性时延

设计原则：最小化内核功能

### 2.3.2 微内核历史
1969年，RC 4000多路编程系统

- 提出模块化设计，允许模块间交互
- 提出复杂消息通信机制用于交互
- 提出"分离策略与机制"的原则
- 提出"管程"（Monitor）的概念
- Per Brinch Hansen等开发者
- 启发了后来的微内核

#### 2.3.2.1 Mach微内核
实现了任务和线程管理、进程间通信（IPC）、内存对象管理、系统调用重定向、设备支持、用户态的多进程、分布式支持等功能

用户态与内核态的分工：Mach允许用户态代码实现Paging（应用管理自己的内存）、重定向功能（允许发生中断/异常时，直接执行用户的二进制，这种连接不需要对内核做修改）

#### 2.3.2.2 L3/L4：极大提升IPC的性能
IPC仅传递信息；使用寄存器传参，限制消息长度；内核去掉了IPC的权限检查等功能，交给用户态判断；系统服务的接口直接暴露给用户态，可能导致DoS攻击

#### 2.3.2.3 seL4
基于L4的微内核

IPC机制：端点（endpoint）
- 通过Capability进行IPC的权限判断
- Capability可被复制和传输

是第一个完成形式化验证的内核

#### 2.3.2.4 QNX Neutrino
QNX：Quick UNIX

使用Neutrino微内核

满足实时要求,广泛用于交通、能源、医疗、航天航空领域，如波音

## 3.2 PC
程序计数器（PC）是 CPU 中的一个寄存器，用于存储下一条即将被执行的指令的地址。

PC 控制着程序指令的顺序流动。每当 CPU 执行完一条指令后，PC 会自动更新为下一条指令的地址。
- 在程序的顺序执行中，PC 会在每次取址阶段增加，指向下一条指令的位置。
-  如果遇到跳转指令（如条件跳转、函数调用等），PC 会更新为跳转目标地址，跳过或重复执行某些代码。
## 3.3 ISA(Instruction Set Architecture)
指令集架构（ISA）是计算机硬件和软件之间的接口，它定义了计算机能够执行的指令类型、每条指令的格式、寄存器操作、内存访问方式等。I

- CPU向软件（应用程序和操作系统）提供的接口
*理解软件在CPU上的运行（操作系统设计、程序调试等）*
- 操作系统中包含体系结构相关的汇编代码
*操作系统启动代码（例如栈尚未设置）*
*部分操作C语言无法表达（例如获取系统状态、刷新TLB）*
*部分场景下，汇编代码比C代码高效很多（例如memcpy）*
## 3.4 函数的调用和返回主要执行的操作
函数调用是另一种形式的无条件跳转

运行时栈（函数栈）：先被调用者后返回，先调用的函数对应的内存区域更靠近栈底
### 3.4.1 函数调用
功能:
- 将返回地址存储在链接寄存器LR (x30寄存器的别名) *LR: Link Register*
- 跳转到被调用者的入口地址

多级函数调用:函数栈帧(主要用于存放返回地址) —— 帧指针：FP
### 3.4.2 函数返回
功能:跳转到返回地址（链接寄存器LR）
## 3.5 用户态和内核态
- 用户态（User-mode）EL0：只能使用用户 ISA 应用程序通常运行在该特权级别
- 内核态（Kernel-mode）EL1：可以同时使用系统 ISA 和用户ISA 操作系统通常运行在该特权级别

操作系统往往同时包含内核态与用户态的代码  *如：Unix包含内核态的kernel 与 用户态的 shell*
## 3.6 异常机制
发生应用程序无法处理的情况，从用户态转换到内核态（下陷），下陷到内核态处理

事件与当前正在执行的指令可以有关，也可以无关
- 有关：svc、eret、缺页异常等，又称为同步异常
- 无关：定时器结束、I/O请求完成等，又称为异步异常
### 3.6.1 同步异常
由CPU内部的事件导致

- 陷阱（Trap）：程序有意导致的异常，控制权将返回到下一条指令 *如：系统调用, 断点*
- 终止（Aborts）：并非有意导致，不可恢复，终止当前进程 *如：校验错误, 机器检查*
- 故障（Faults）：并非有意导致；可能可以修复，重新执行上一条指令，或终止 *如：缺页异常 (可恢复), 保护错误(不可恢复)*

### 3.6.2 异步异常
由CPU外部的事件导致
- 外部设备设置处理器的中断引脚
- 处理函数返回到被中断的下一条指令

例子：
- I/O 中断 *在键盘上按下ctrl+c、从网络收到数据包、磁盘从某个扇区读取完成*
- 硬复位中断 *按下重启按钮*
- 软复位中断 *按下ctl-alt-delete*
### 3.6.3 异常向量表
操作系统预先在一张表中准备好不同类型异常的处理函数

- 表的格式由CPU规定
- 表的基地址存储在VBAR_EL1寄存器中
- CPU在异常发生时自动跳转到对应位置
- 一共16项，其中4条最为常用
### 3.6.4 异常处理函数
异常处理函数运行在内核态，可以不受限制地访问所有资源

处理器将异常类型存储在指定寄存器中 (ESR_EL1)，表明发生的是哪一种异常，异常处理函数根据异常类型执行不同逻辑

![alt text](img/3-6-4.png)

当异常处理函数完成异常处理后，将通过下述操作之一转移控制权：
- 回到发生异常时正在执行的指令 *如：缺页异常*
- 回到发生异常时的下一条指令 *如：系统调用（svc指令）*
- 结束当前进程 *如：发生无法处理的错误*
### 3.6.5 操作系统执行流
1. 实现对异常向量表的设置
- CPU上电后立即执行，是系统初始化的主要工作之一
- 在开启中断和启动第一个应用之前
2. 实现对不同异常的处理函数
- 处理应用程序出错的情况 *如缺页异常*
- 一类特殊的同步异常：系统调用，由应用主动触发
- 处理来自外部设备的中断 *如收取网络包、获取键盘输入等*

## 3.7 用户态到内核态之间的切换
硬件提供了一对指令在用户态、内核态之间切换
svc / eret

**从EL0切换到EL1：**
1. 将发生异常事件的指令地址（PC中的值）保存在异常链接寄存器中
2. 将异常事件的原因保存在异常症状寄存器中
3. 将处理器的当前状态保存在已保存的程序状态寄存器中
4. 保存与特定异常相关的信息，如缺页异常时，将引发异常的内存地址保存到错误地址寄存器中
5. 栈寄存器不再使用用户态栈寄存器，开始使用内核态栈寄存器
6. 修改PATATE寄存器中的特权级标志位，设置为内核态
7. 根据异常向量表，找到异常处理函数的入口地址，并将该地址写入PC，开始运行操作系统


**eret:从内核态返回用户态:**
1. 将SPSR_EL1中的处理器状态写入PSTATE中
- 处理器状态也从 EL1 切换到 EL0
2. 栈寄存器不再使用SP_EL1，开始使用SP_EL0
- 注意：SP_EL1的值并没有改变
- 下一次下陷时，操作系统依然会使用这个内核栈
3. 将ELR_EL1中的地址写入PC，并执行应用程序代码

操作系统在切换过程中的任务:将属于应用程序的 CPU 状态保存到内存中

应用程序需要保存的运行状态称为处理器上下文

处理器上下文（Processor Context）：应用程序在完成切换后恢复执行所需的最小处理器状态集合

**系统调用**
操作系统给应用程序提供的接口

用户与操作系统之间，类似于过程调用的接口,通过受限的方式访问内核提供的服务

最多允许8个参数,x0-x7寄存器,x8用于存放系统调用编号

调用者保存的寄存器必须在用户态保存,返回值存放于x0寄存器中

## 3.8 基本的抽象
目的：程序能够更方便地使用硬件，应用程序可以使用系统提供的一系列功能
- 对处理器的抽象是进程 多个应用程序在一个处理器上分时复用交替执行
- 线程抽象以及多线程机制 允许一个应用程序并行使用多个处理器
- 对物理内存的抽象是虚拟内存
- 对存储、网络、键盘、显示器等外部设备的抽象是文件

## 3.9 进程 
### 3.9.1 进程定义
目的：分时复用有限的CPU资源

分时复用：一个程序在处理器运行一段时间后，会被操作系统暂停执行并切换走，把处理器让给另一个程序使用

通常一个应用程序对应一个进程,是操作系统中对正在执行的程序的抽象表示

多进程程序：应用程序亦可自行创建新进程

操作系统提供进程的抽象用于管理应用程序:记录进程标识号（Process ID， PID）、运行状态（处理器上下文）、所占用的计算资源

进程抽象为应用程序提供了“独占CPU”的假象
### 3.9.2 进程状态切换
操作系统为每个进程维护处理器上下文，包含恢复进程执行所需要的状态，具体包括：PC寄存器值，栈寄存器值，通用寄存器值，状态寄存器值

切换时机：
- 异常导致的上下文切换 *Timer中断（如基于时间片的多任务调度）*
- 用户执行系统调用并进入内核 *如：read/sleep等会导致进程阻塞的系统调用*

进程的上下文切换
- 进程通过中断或系统调用进入内核
- 上下文保存在对应的PCB中 *被调度时，从PCB中取出上下文并恢复*

切换重要步骤:将上一个进程在处理器中的状态保存到对应的PCB中,然后将下一个进程的状态从其PCB读出并恢复到处理器对应的寄存器中。
## 3.10 PCB
进程控制块（PCB）：包含了进程的管理信息，如进程状态、程序计数器（PC）、寄存器内容、内存管理信息等。

操作系统为每个进程维护一个PCB

存放进程相关的各种信息
- 进程的标识符、内存、打开的文件……
- 进程在切换时的状态（上下文context）
## 3.11 虚拟内存
在应用程序与物理内存之间加入一个新的抽象:虚拟内存

应用程序是面向虚拟内存编写的而不再是面向物理内存编写的,应用程序在运行时只能使用虚拟地址,CPU负责将虚拟地址翻译成物理地址,操作系统负责设置虚拟地址与物碑地址之间的映射。

虚拟内存目标:高效性、安全性、透明性

# 第四章 虚拟内存管理
物理内存: 常说的“内存条”就是指物理内存 数据从磁盘中加载到物理内存后，才能被CPU访问 *操作系统的代码和数据,应用程序的代码和数据*

物理地址:物理内存可以看成由连续字节组成的数组 *每个字节都有唯一的物理地址*

虚拟地址空间:应用进程使用虚拟地址访问内存,所有应用进程的虚拟地址空间都是统一的（方便开发）
## 4.1 地址翻译
CPU按照OS配置的规则把虚拟地址翻译成物理地址,翻译对于应用进程时不可见的（无需关心）

CPU中的内存管理单元负责虚拟地址到物理地址的转换

虚拟地址转换成物理地址的过程，通常被称为地址翻译
## 4.2 分页机制
分页机制：
- 虚拟地址空间划分成连续的、等长的虚拟页
- 物理内存也被划分成连续的、等长的物理页
- 虚拟页和物理页的页长相等
- 虚拟地址分为：虚拟页号 + 页内偏移

页表：记录虚拟页号到物理页号的映射关系表

为了使MMU能够找到页表，将夜表起始地址放在页表基地址寄存器中。在地址翻译的过程中，MMU会先通过虚拟页号找对应条目，
取出条目中的物理页号，物理页号+页内偏移得到物理地址

特点：
- 物理内存离散分配：任意虚拟页可以映射到任意物理页，大大降低对物理内存连续性的要求
- 主存资源易于管理，利用率更高：按照固定页大小分配物理内存，能大大降低外部碎片和内部碎片
## 4.3 多级页表
多级页表能有效压缩页表的大小

原因：允许页表中出现空洞,程序中有很多绝大多数页表不会使用,会有很多空洞节省空间

- 若某级页表中的某条目为空，那么该条目对应的下一级页表便无需存在
- 应用程序的虚拟地址空间大部分都未分配

多级页表并非只有最后一级页表可以指向物理页,中间级也可以直接指向物理页,当中间级指向物理页时,其指向的是大页
## 4.4 页表项和大页
### 4.4.1 页表项
- 每级页表有若干离散的页表页
- 第 0 级（顶层）页表有且仅有一个页表页
- 每个页表页中有 512 个页表项

每个虚拟页都有一个对应的页表项，页表项存储了虚拟页到物理页的映射。页表项一般包括以下信息：
- 物理页框的地址：页表项中包含的最重要信息是物理内存中的页框地址，它告诉操作系统虚拟页在哪个物理页上。
- 有效位（Valid bit）：标记该页是否有效。如果无效，访问该页时将触发页面错误。
- 修改位（Dirty bit）：标记该页自从加载到内存以来是否被修改。如果被修改，操作系统需要在页面换出时将该页写回磁盘。
- 访问权限（Access Control）：指示该页的读、写、执行权限，例如该页是否可以读、写或执行。
- 引用位（Reference bit）：在页面置换算法中使用，标记该页是否被访问过，用于决定是否将其换出。

若实际访问与页表项设置的权限不一样,MMU会在地址翻译的过程中触发访问异常

- 表描述符:0/1/2级页表项中的PNF指向下一级页表页
- 块描述符:0/1/2级页表项中的PNF直接指向物理页(大页)

若0/1/2级页表项第一位为0,则为块描述符,1则为表描述符
### 4.4.2 大页
大页是一种比常规页面更大的内存页面，通常用于提高内存访问的效率，特别是在需要频繁访问大量内存的应用程序中。

优势：
- 减少页表的数量：使用大页可以减少需要管理的页表项数量。例如，4 KB 的标准页和 2 MB 的大页相比，后者可以覆盖更多的内存区域，从而减少页表的大小。
- 提高内存访问效率：大页可以减少 TLB（转换后备缓冲区）缺失的次数。因为每次访问大页时，TLB 可以缓存更多的内存内容，减少了页面查找的开销。
- 减少页面换入换出（Page Faults）：由于每个大页包含的内存比常规页面多，因此每次换页时，操作系统需要做的页面调度工作也会减少，从而减少了页面换入换出的次数，进而提高了性能。
## 4.5 TLB——转址旁路缓存
TLB 位于CPU内部，是页表的缓存,目的为减少多级页表下地址翻译过程中的访存次数
### 4.5.1 TLB思路
MMU会先把虚拟页号作为键去查询TLB中的缓存项，若找到则可直接获得对应的物理页号而无须再查询页表。我们称通过TLB能够直接完成地址翻译的过程为TLB命中（TLBhit）;反之，为TLB未命中（TLBmiss）。

TLB 命中可以减少查询页表带来的访存次数，TLB 不命中会导致额外的访存（访问页表+访问数据）

利用：若TLB不命中，硬件将通过页表基地址查询页表，找到对应的页表项，并将翻译结果写到TLB中，若TLB已满，则根据硬件指定的策略替换某一项。
之后若需要再次翻译同样的虚拟页号，硬件就可以迅速地从TLB中找到对应的物理页号（TLB命中）
### 4.5.2 TLB刷新
由于TLB是使用虚拟地址进行查询的,所以操作系统在进行页表切换（应用程序切换）的时候需要主动刷新TLB。

不刷掉TLB的方法：新的硬件特性 地址空间标识ASID（AARCH64）： Address Space ID

- OS为不同进程分配8位或16位 ASID *ASID的位数由TCR_EL1的第36位（AS位）决定，OS会将ASID填写在TTBR0_EL1的高8位或高16位*
- TLB的每一项也会缓存ASID *地址翻译时，硬件会将TLB项的ASID与TTBR0_EL1的ASID对比；若不匹配，则TLB miss*

使用了ASID之后：
- 切换页表（即切换进程）后，不再需要刷新TLB，提高性能
- 修改页表映射后，仍需刷新TLB（为什么？）
## 4.6 立即映射和延时映射
### 4.6.1 立即映射
思路：在创建应用进程时，操作系统在进程页表中为初始虚拟内存区域（如代码段和数据段）直接添加虚拟页到物理页的映射

在立即映射策略下，操作系统立即分配物理页，并通过更新页表项，将新增虚拟内存区域中每个新的虚拟页映射到物理页。

访问文件内容时不需要额外的延迟，因为数据已经加载到内存中。

如果文件很大或者不完全需要访问整个文件，立即映射会浪费内存和时间，因为它会加载整个文件。
### 4.6.2 延时映射
思路：先记录为应用进程分配的虚拟内存区域，但不分配相应相应的物理内存，也不在页表中填写映射；当应用进程实际访问某个虚拟页时，
由于页表没有映射，CPU会触发缺页异常，操作系统在缺页异常的处理函数中为虚拟内存分配物理页，并在页表中添加映射，然后重新执行触发
异常的指令。

这种策略也称为按需分配界面

适用于只访问部分文件的情况：如果进程只访问文件的一部分，延时映射能够减少内存占用。

由于数据是按需加载的，第一次访问某一部分数据时会发生缺页异常，导致加载延迟。

### 4.6.3 区别

- 立即映射：每个虚拟页都对应了一个物理内存页
- 延迟映射：有些虚拟页不对应任何物理内存页 *对应的数据在磁盘上 没有对应的数据（初始化为0）*

## 4.7 什么时候需要引入线程，什么时候线程效率低/高
需要引入线程的情况通常是当程序需要并发执行任务，尤其是涉及I/O密集型任务或计算密集型任务时，线程可以有效提高程序的响应性和性能。

线程效率高时，主要发生在I/O密集型应用、高并发的环境以及能够充分利用多核处理器的计算密集型任务。

线程效率低时，通常是线程创建、销毁和切换开销较大，或者线程之间频繁的锁竞争和过多的上下文切换。
## 4.8 共享内存
允许同一个物理页在不同的应用程序间共享.

两个应用程序共同使用某物理页,再该物理页中两个应用程序可以得到相同的内容,并且能相互看到对方修改的内容

基本用途:支持不同应用程序之间互相通信 传递数据

基于此诞生写时拷贝技术:主要用于内存管理和进程间的资源共享。它允许多个进程共享相同的内存区域，
直到其中一个进程修改了该区域的内容时，操作系统才会创建该进程的内存副本。写时拷贝提高了内存使用效率，减少了不必要的数据复制。
# 第五章 物理内存管理
## 5.1 内存管理
引入虚拟内存后，物理内存分配主要在以下四个场景出现：
1. 用户态应用程序触发on-demand paging（延迟映射）时 *此时内核需要分配物理内存页，映射到对应的虚拟页*
2. 内核自己申请内存并使用时 *如用于内核自身的数据结构，通常通过kmalloc()完成*
3. 内核申请用于设备的DMA缓存时 *DMA缓存通常需要连续的物理页*
4. 发生换页（swapping）时 *通过磁盘来扩展物理内存的容量*
### 5.1.1 内存碎片
概念:无法被利用的内存,其直接导致内存利用率的下降

内存碎片被划分为外部碎片和内部碎片
### 5.1.2 外部碎片
系统中存在足够的空闲内存，加起来足够，却无法满足请求，这些无法使用的空闲物理内存称为外部碎片
### 5.1.3 内部碎片
当分配的内存空间大于实际分配请求所需要的内存空间时，就会浪费部分内存，这种被浪费的内存空间即为内部碎片

## 5.2 伙伴系统的管理
只考思路

基本思想:将物理内存划分为连续的块，以块作为基本单位进行分配。不同块的大小可以不同，每个块都由一个或多个
连续的物理页组成，物理页的数量必须是2的n次幂，（0<=n<预设最大值）其中预设最大值将决定能够分配的连续物理
内存区域的最大值,一般由开发者根据实际情况制定.

当一个请求需要分配 m 个物理页时，伙伴系统将寻找一个大小合适的块，该块包含 2n个物理页，且满足2n−1< m ⩽ 2n
在处理分配请求的过程中，大的块可以分裂成两半，即两个小一号的块，这两个小块互为伙伴。分裂得到的块可以继续分裂
直到得到一个大小合适的块去服务相应的分配请求。在一个块被释放后，分配器会找到其他伙伴，若伙伴块也处于空闲状态
，则这两个伙伴块进行合并，形成一个大一号的空闲块，然后继续尝试向上合并。由于分裂和合并操作都是级联的，因此能
很好地缓解外部碎片的问题。

高效地找到伙伴块：
互为伙伴的两个块的物理地址仅有一位不同，而且块的大小决定是哪一位

例如：
- 块A（0-8K）和块B（8-16K）互为伙伴块
- 块A和B的物理地址分别是 0x0 和 0x2000 仅有第13位不同，块大小是8K（213）

## 5.4 常用的空闲链表
不仅可以用于内核态,也可以用在用户态
### 5.4.1 隐式空闲链表
链表中的每个元素代表一块内存区域，空闲和非空闲的内存块混杂在同一个链表里

每个内存块有一个标头（Header），用来存储该块的大小和状态（空闲或已分配）。在隐式空闲链表中，空闲块的查找
和遍历是通过顺序扫描所有内存块来完成的。分配内存块依次查询，找到第一块满足条件的内存块就返回。如果能满足
分配请求且有剩余，则块进行分裂，一部分用于服务请求，剩余部分留用新的内存块。

在释放内存块时，检查前后两个内存块收否有空闲，如果空闲块存在则进行合并，产生更大的空闲块
### 5.4.2 显式空闲链表
显式空间链表进把空闲的内存块（而不是所有内存块）放在链表中。

显式空闲链表会为每个空闲块维护两个指针，指向上一个和下一个空闲块。

当一个内存块被释放时，它会被插入到空闲链表中，而分配器会直接从链表中选取空闲块，而不需要进行全体扫描。

## 5.5 换页策略
### 5.5.1 OPT策略
理想的换页策略

在选择被换出的页面时，优先选择未来不会再访问的页面，或者在最长时间内不会再访问的页面。

假设物理内存中可以存放三个物理页，初始为空，某应用程序一共需要访问物理页面 1～5

OPT：优先换出未来最长时间内不会再访问的页面
### 5.5.2 FIFO策略
操作系统维护一个队列用于记录换入内存的物理页号，每换入一个物理页就把其页号加到队尾，因此最先换进的物理页号总是处于队头位置
### 5.5.3 LRU
OS维护一个链表，在每次内存访问后，OS把刚刚访问的内存页调整到链表尾端；每次都选择换出位于链表头部的页面
- 缺点-1：对于特定的序列，效果可能非常差，如循环访问内存
- 缺点-2：需要排序的内存页可能非常多，导致很高的额外负载
### 5.5.4 Belady’s Anomaly
在某些特定的页面访问序列中，增加内存页数会导致比原来更高的页面错误率。这种现象就是 Belady 异常。

# 第六章 进程与线程
## 6.1 进程与线程的区别与联系
进程:通常一个应用程序对应一个进程,是操作系统中对正在执行的程序的抽象表示

线程:更加轻量级的运行时抽象，线程只包含运行时的状态，一个进程可以包含多个线程，每个线程共享同一地址空间（方便数据共享和交互），允许进程内并行

联系：
- 线程是进程的组成部分：一个进程可以包含一个或多个线程，进程为线程提供执行环境和资源。所有线程共享进程的资源（如内存、文件描述符等），但每个线程有自己的执行栈和寄存器。
- 线程依赖于进程：线程不能单独存在，它总是依赖于某个进程。进程存在时，它才能包含一个或多个线程。

区别:
![alt text](img/6-1-1.png)

线程和进程的相似之处：
- 都可以与其他进程/线程并发执行（可能在不同核心上）
- 都可以进行上下文切换

线程和进程的不同之处：
- 同一进程的不同线程共享代码和部分数据
- 线程与进程相比开销较低

## 6.2 进程执行状态和管理
- 新生（new）：刚调用process_create
- 就绪（ready）：随时准备执行（但暂时没有执行）
- 运行（running）：正在执行
- 僵尸（zombie）：退出但未回收
- 终止（terminated）：退出且被回收

进程执行状态的典型应用案例：调度

调度的目的：选出下一个可以执行的进程 可以执行 = 就绪（ready）
## 6.3 fork执行
语义：为调用进程创建一个一模一样的新进程
- 调用进程为父进程，新进程为子进程
- 接口简单，无需任何参数

fork后的两个进程均为独立进程
- 拥有不同的进程id
- 可以并行执行，互不干扰（除非使用特定的接口）
- 父进程和子进程会共享部分数据结构（内存、文件等）

当你多次调用 fork() 时，每次调用都会创建一个新的子进程。假设我们调用了 n 次 fork()，那么最终会生成 ( 2^n ) 个进程（包含原始父进程）。
这是因为每个进程都会继续执行 fork()，并生成新的子进程。每个 fork() 调用会返回两次：一次给父进程，另一次给子进程。

### 6.4.1 进程切换的全过程:
1. p0进入内核态:由硬件完成部分寄存器保存 *PC和PSTATE分别自动保存到ELR_EL1和SPSR_EL1*
2. p0处理器上下文保存:将处理器中的寄存器值保存到处理器上下文对应的位置

   4. p1处理器上下文恢复:从处理器上下文中加载各寄存器的值，放入对应寄存器中
   5. p1处理器上下文恢复:由硬件自动恢复部分寄存器 *将ELR_EL1和SPSR_EL1中的值自动保存到PC和PSTATE中*

## 6.5 三种多线程模型
线程模型表示了用户态线程与内核态线程之间的联系
- 多对一模型：多个用户态线程对应一个内核态线程
- 一对一模型：一个用户态线程对应一个内核态线程
- 多对多模型：多个用户态线程对应多个内核态线程
### 6.5.1 多对一模型
将多个用户态线程映射给单一的内核线程

优点：内核管理简单

缺点：可扩展性差，无法适应多核机器的发展
### 6.5.2 一对一模型
每个用户线程映射单独的内核线程

优点：解决了多对一模型中的可扩展性问题

缺点：内核线程数量大，开销大

主流操作系统都采用一对一模型
### 6.5.3 多对多模型
N个用户态线程映射到M个内核态线程（N > M）

优点：解决了可扩展性问题（多对一）和线程过多问题（一对一）

缺点：管理更为复杂

在虚拟化中得到了广泛应用
# 第七章 处理器调度
## 7.1 处理器调度的对象，调度时机
调度:协调对资源的使用请求
### 7.1.1 处理器调度对象
处理器调度的对象是CPU执行的最小单元,在最开始是进程,发展一段时间后变为线程

从原理上来讲对象是线程,为了避免概念混淆,用任务来描述调度对象
### 7.1.2 处理器调度时机
理论上,只要系统进入了内核态,就有可能触发调度

协作式调度(非抢占式):用户态的任务主动调用yield陷入内核态并触发处理器调度,让系统选择其他任务执行
许多操作系统会在系统调用的最后调用sched以触发调度,使当前CPU核心切换并执行其他任务。

抢占式调度:通过中断机制，强制打断当前任务的执行，从而有机会触发调度。操作系统一般将定时触发的时钟
作为稳定的中断来源

每次任务执行，一定时间后会被切换到下一任务，而非执行至终止，通过定时触发的时钟中断实现
## 7.2 常见的调度指标
- 平均周转时间：衡量任务在系统中等待执行的情况。指标越小，全部任务等待时间越少
- 平均响应时间：衡量任务响应用户是否及时。时间点越早越快响应用户请求。
- 实时性：处理有截止时间要求的实时任务
- 资源利用率：尽可能保证系统资源被充分利用
- 公平性：每个任务都有机会执行
- 调度机制的开销：高效实现调度器，调度策略控制调度任务的频率
## 7.3 经典调度策略
### 7.3.1 FCFS（先到先得）
按照进程到达就绪队列的顺序进行调度，即第一个到达就绪队列的进程先执行，直到完成为止。FCFS 是一种非抢占式调度算法。

优点：简单直观，不需要预知用户信息，（公平性）

缺点：
- 长短任务混合场景下对短任务不友好
- 对I/O密集型任务不友好
### 7.3.2 SJF（最短任务优先）
是一种根据进程的执行时间来进行调度的算法。它选择执行时间最短的进程进行调度，从而减少进程的等待时间。SJF 可以是 抢占式或 非抢占式。

特点：平均周转时间短

缺点：
- 必须预知任务运行时间
- 性能表现严重依赖任务到达时间点
### 7.3.3 RR（时间片轮转）
是一种抢占式调度算法，它为每个进程分配一个固定的时间片（通常较小），每个进程在执行时只能占用 CPU 一定的时间。当进程的时间片用尽后，它将被抢占，
放回就绪队列末尾，等待下一次调度。该算法确保了进程能够公平地分配 CPU 时间。

特点：公平性，无需预知任务运行时间

缺点：任务运行时间相似的场景下平均周转时间高
## 7.4 优先级调度
优先级用于确保重要的任务被优先调度，通过为每个任务指定优先级，调度器可以确认哪些任务应该优先执行。
### 7.4.1 高响应比优先
思路：根据每个进程的“响应比”来决定调度顺序

响应比 = 等待时间除以运行时间

步骤：
1. 计算每个进程的响应比：对于每个进程，计算其响应比 ( R = \frac{(W + S)}{S} )，其中 ( W ) 是该进程的等待时间，( S ) 是该进程的服务时间。
2. 选择响应比最大的进程：从就绪队列中选择响应比最大的进程来执行。
3. 执行进程：执行选择的进程，直到其完成。
4. 更新等待时间：执行完当前进程后，更新其他进程的等待时间，然后重新计算响应比。
### 7.4.2 多级队列
Multi-Level Queue (MLQ):将进程分成多个不同优先级的队列，并对每个队列应用不同的调度策略。每个队列中的进程根据其优先级被分类，
调度系统根据队列的优先级来选择进程执行。通常，高优先级队列中的进程会优先于低优先级队列中的进程执行。

适合静态的应用场景

1. 维护多个队列，每个对应静态设置好的优先级
2. 高优先级的任务优先执行
3. 同优先级内使用Round Robin调度（也可使用其他调度策略）

问题:
1. 低优先级任务饥饿 
2. 资源利用率低
3. 优先级反转:低优先任务占用资源导致高优先级任务被阻塞
### 7.4.3 多级反馈队列
MLFQ 调度算法通过多个队列实现多级调度，每个队列有不同的优先级和调度策略。进程在队列中的位置是动态变化的，基于进程的行为（如执行时间、等待时间）来调整其所在队列的优先级。
这使得 MLFQ 能够灵活地处理不同类型的进程，同时保持高优先级队列快速响应短作业，低优先级队列适应长作业。

问题:实现复杂
## 7.5 公平调度解决的问题
优先级调度无法保证任务对资源使用的实际比例

量化任务对系统资源的占用比例,实现对于资源的公平调度。

### 9.1.5 用信号量机制来实现3个进程的取数协调，这里的缓冲区的数量是超过1的。
1. 初始化信号量：empty 信号量初始化为 N，表示缓冲区可以容纳 N 个数据项;full 信号量初始化为 0，表示缓冲区开始时没有数据。
2. 进程取数操作：每个进程首先执行 sem_wait(&full)，等待缓冲区中有数据。当 full 信号量大于 0 时，表示缓冲区中有数据，进程就可以从缓冲区中取数据。
    1. 然后，进程使用互斥锁 mutex_lock(&buffer_mutex) 保护缓冲区，确保每次只有一个进程能访问缓冲区。
    2. 进程读取数据后，更新 out 下标，指向下一个数据项。
    3. 最后，释放互斥锁 mutex_unlock(&buffer_mutex)，并调用 sem_post(&empty)，表示缓冲区腾出了一个空位。
3. 1. 每个进程在取数据时，都会等待 full 信号量，直到缓冲区有数据可以取。
   2. 每次取完数据后，更新 empty 信号量，表示缓冲区有一个空位被释放。
   3. 通过这种方式，信号量机制协调多个进程的取数操作，确保数据一致性，并避免竞争条件。

    // 信号量
    sem_t empty, full;
    mutex_t buffer_mutex;  // 保护缓冲区访问的互斥锁

    // 假设缓冲区是一个数组
    #define N 5  // 假设缓冲区大小为 5
    int buffer[N];  // 缓冲区，最多存储5个数据项
    int in = 0;  // 数据写入的下标
    int out = 0;  // 数据读取的下标

    // 初始化信号量
    sem_init(&empty, 0, N);  // 初始化空位信号量为N
    sem_init(&full, 0, 0);    // 初始化数据信号量为0
    mutex_init(&buffer_mutex); // 初始化互斥锁

    // 进程1的取数操作
    void process_1() {
        // 等待缓冲区有数据（即full信号量>0）
        sem_wait(&full);
        
        // 访问缓冲区前先加锁
        mutex_lock(&buffer_mutex);
        
        // 从缓冲区中取数据
        int item = buffer[out];
        out = (out + 1) % N;  // 循环更新读取位置
        
        // 解锁缓冲区
        mutex_unlock(&buffer_mutex);
        
        // 更新空位信号量
        sem_post(&empty);  // 增加空位信号量
    }

    // 进程2的取数操作
    void process_2() {
        // 等待缓冲区有数据（即full信号量>0）
        sem_wait(&full);
        
        // 访问缓冲区前先加锁
        mutex_lock(&buffer_mutex);
        
        // 从缓冲区中取数据
        int item = buffer[out];
        out = (out + 1) % N;  // 循环更新读取位置
        
        // 解锁缓冲区
        mutex_unlock(&buffer_mutex);
        
        // 更新空位信号量
        sem_post(&empty);  // 增加空位信号量
    }

    // 进程3的取数操作
    void process_3() {
        // 等待缓冲区有数据（即full信号量>0）
        sem_wait(&full);
        
        // 访问缓冲区前先加锁

        // 解锁缓冲区
        mutex_unlock(&buffer_mutex);
        
        // 更新空位信号量
        sem_post(&empty);  // 增加空位信号量
    }

## 9.2 死锁定义
死锁现象：互相等待的僵持现象

一组中的每一个线程都在等待组内其他线程释放资源而造成的无限等待
## 9.3 死锁产生的原因
### 9.3.1 互斥访问
互斥访问保证同一时刻只有一个线程能够访问，在互斥访问的前提下，线程才会出现等待
### 9.3.2 持有并等待
线程持有一部分资源并等待一些资源，不会中途释放（如proc_A不会放锁A）
### 9.3.3 资源非抢占
一旦一个资源被持有，除非持有者主动放弃，其他竞争者都得不到这个资源
### 9.3.4 循环等待
一系列线程循环等待，都无法获得资源

## 9.4 死锁的检测与恢复
### 9.4.1 死锁检测
获取系统中资源分配与线程等待的相关信息，通过资源分配表和线程等待表来记录这些数据

如果形成环就形成了循环等待，可以判断出现了死锁
### 9.4.2 死锁恢复
1. Kill一个进程，看有没有环，有的话继续kill
2. 全部回滚到之前的某一状态
3. 直接kill所有循环中的线程
## 9.5 预防哪些设计
1. 避免互斥访问：通过其他手段（如代理执行）
2. 不允许持有并等待：一次性申请所有资源
3. 资源允许抢占：需要考虑如何恢复
4. 打破循环等待：按照特定顺序获取资源

## 9.6 银行家算法 必考!!!!!!!!!!!!!!!
安全状态：能找出至少一个执行序列，如P2->P1->P5...让所有线程需求得到满足
非安全状态：不能找出这个序列，必定会导致死锁

银行家算法：保证系统一直处于安全状态，且按照这个序列执行

通过模拟分配资源后的状态来判断再分配某个资源后,系统是否还处于安全状态。假设有M类资源，N线程

    全局可利用资源：Available[M]
    每线程最大需求量：Max[N][M]
    已分配资源：Allocation[N][M]
    还需要的资源：Need[N][M]

银行家算法正常工作前提：
1. 系统中的供给关系必须是固定的
2. 任意线程对于任意资源的最大需求量不能超过系统的资源总量
3. 对于任意一类资源,任意线程已分配的资源加上该线程还需要的资源,必须要小于等于该线程对于这一类资源的最大需求量
4. 线程在获得了所有需要的资源后,能在有限时间之内完成工作,并且释放已经获得的资源

安全性检查算法:通过模拟分配资源后的状态来判断再分配某个资源后,系统是否还处于安全状态。如果无法处于安全状态则不分配

安全性检查算法步骤:
1. 创建一个临时数组Available_sim,其初始值与Available一致2,用于记录在接下来的模拟执行中系统可用的资源数量
2. 找到当前系统剩余资源能够满足的线程。即找到一个线程x,对于Available_sim中任意成员m,都满足Available[m] >= Need[x][m],
如果不能找到这样的线程,则代表处于非安全状态
3. 假设将资源全部分配给他,且他执行完成后会释放所有的资源,即对于Available_sim中的所有成员m,都执行Available_sim[m] += 
Allocation[x][m],同时标记线程x执行结束
4. 遍历所有线程,查看是否还有未被标记执行结束的线程,如果有则回到第二步继续执行,否则代表系统处于安全状态

## 11.2 文件的存取方式
### 11.2.1 顺序读取
数据按照文件的存储顺序逐个字节或块地进行读取。换句话说，数据从文件的起始位置开始，按顺序逐一读取，直到文件的末尾。
这种方式要求操作系统在读取时按顺序处理文件中的每个数据块。

特点：线性访问、适合大量数据读取、效率高

优点：简单，容易实现；读取速度较快，尤其在处理大文件时

缺点：只能从头到尾读取，不能直接访问文件中的某个特定位置；如果需要跳跃式访问文件中的不同部分，效率较低。
### 11.2.2 直接读取
数据可以直接访问文件中的任何位置，而不必按照顺序逐一读取。操作系统允许在文件的任何位置直接进行读取和写入操作，
而不需要按照存储顺序进行线性处理。

特点：任意位置访问、效率高、文件指针控制

优点：支持快速随机访问文件中的任何位置；在频繁访问特定位置的数据时，效率更高。

缺点：读取过程相对复杂，需要操作系统管理文件指针；可能导致磁盘的频繁寻址操作，影响性能。

## 11.3 文件目录及其特点
### 11.3.1 单层目录
在单层目录结构中，所有的文件都直接存储在根目录下。每个文件都有一个唯一的文件名，且文件之间没有子目录关系。整个文件系统的文件都在同一级别上。

特点：简单性、访问速度快、适用小型系统

优点：实现简单，管理方便；文件访问速度极快

缺点：无法支持复杂的文件组织；文件数量增加时容易发生管理混乱；难以处理不同用户的文件管理。
### 11.3.2 双层目录
包含两个层次：根目录和用户目录。根目录下存放的是用户目录，而每个用户目录下可以包含该用户的文件。每个用户有自己的独立目录，避免了文件名冲突。

特点：支持多个用户，简单组织，限制性

优点：文件管理比单层目录更加有序；可以避免不同用户之间的文件名冲突。

缺点：目录结构过于简单，不能支持更复杂的文件层次和组织。
### 11.3.3 树形目录
每个目录可以包含多个子目录，子目录下还可以有自己的文件和子目录，形成树状层次结构。根目录是树的根节点，所有其他目录和文件通过分支连接。

特点：层次化管理、灵活性强、支持嵌套

优点：
- 结构清晰，易于管理。
- 可以支持复杂的文件组织和嵌套。
- 适用于大型文件系统和多用户环境。

缺点：
- 需要更多的存储空间来管理目录信息。
- 操作可能较为复杂，尤其是在深层次的目录中。
### 11.3.4 无环图目录
允许目录之间存在连接，但不允许存在循环引用。即，目录或文件可以通过硬链接或符号链接指向其他目录或文件，形成图状结构，但图中不能有环。

特点：支持链接、无环性、适用于多重引用

优点：
- 支持文件和目录的共享与重用。
- 通过链接可以减少数据冗余。

缺点：
- 目录结构和文件管理较为复杂。
- 需要特别注意链接的管理，避免出现死链或循环引用。
## 11.4 硬链接和软链接
### 11.4.1 硬链接
（硬）链接：文件系统提供了一个专门的系统调用，为一个已经存在的文件建立新的文件名映射，这种映射就是链接

将原文件的文件名与数据块直接关联

LINK
- LINK("Mail/inbox/new-assignment", "assignment")
- 将严格的层次结构（树）变成有向图 *注意：用户不能为目录创建link*
- 不同的文件名可以指向同一个inode号

引用计数器（Reference count）
- 一个 inode 可以绑定多个文件名
- LINK 时 +1, UNLINK 时 -1 *当reference count为0时，文件被删除*
- 不允许出现环
### 11.4.2 软链接
符号链接

符号链接文件本身就是一个独立的文件，具有自己的文件名和inode，符号链接是一种特殊的文件，其数据内容是一个字符串，
为该链接所指向的目标文件的路径。

与硬链接不同的是，软链接和目标文件是两个不同独立的链接，可以保存在不同的文件系统中，因此可以实现跨文件系统的链接
## 11.5 VFS设计思路，如何融合不同类型的文件系统
VFS：对多种文件系统进行管理和协调

虚拟文件系统提供统一的管理，对应用程序提供统一的视图和抽象

VFS维护一个统一的文件系统树，
操作系统内核启动时会挂载一个根文件系统，
其他文件系统可以挂载在文件系统树的目录上

VFS维护所有的挂载信息
- 查找文件时的每一步，检查当前目录是否为挂载点
- 若是，则使用被挂载的文件系统继续进行访问

## 13.3 常见的几种外设

在启动之初,操作系统通过实时时钟获取当前时间,连接互联网时可以对时钟进行校验,系统断电后可以通过微电池供电工作很长时间

提供了比实时时钟更高精度的时钟机制 

可以通过晶体振荡器的分频方法实现,也可以通过衰减测量器的递减方式实现

定时器对操作系统的抢占式调度十分重要
### 13.3.3 串口
全称为通用异步收发传输器,用于实现不同计算机之间点对点通讯的设备

主要特点是逐字节地发送和接收消息

串口基本内部结构主要包含串口设备寄存器 收发数据的FIFO队列 波特率发生器和对外引脚
### 13.3.4 网卡
计算机用于连接网络并与其他计算机进行通信的设备,通过总线的方式和CPU互联

每次传输一帧数据（以太网帧）
### 13.3.5 机械硬盘
是一种常用的存储设备

存储介质:机械硬盘
### 13.3.6 闪存
读写速度优于机械硬盘:使用电介质进行存储

按照页/块的粒度进行读写/擦除

支持页/块随机访问
### 13.3.7 固态硬盘
由多块闪存和相关控制器组成。

控制器包括主机接口、闪存控制器、内存缓冲区等单元。
## 13.4 中断和DMA
### 13.4.1 中断
由硬件设备在某些事件发生后再通知CPU的机制被称为中断

中断机制使得设备可以向CPU主动发送中断信号，CPU在还没有收到中断时可以处理其他任务；CPU收到中断后，正在CPU上执行的任务会被打断，
而相应的中断处理函数（ISR）会被执行并立刻响应中断时间。

设备中断是异步发生的

中断控制器：负责中断的配置和管理
### 13.4.2 DMA
直接内存访问技术：DMA

允许设备绕过CPU进行批量物理内存数据的读写

有了DMA，在硬件设备传输数据的同时，CPU可以执行其他任务，以显著提高CPU利用率

- 设备可直接访问总线
- DMA与内存互相传输数据，传输不需要CPU参与
- 适合于高吞吐量I/O

安全状态：能找出至少一个执行序列，如P2->P1->P5...让所有线程需求得到满足
非安全状态：不能找出这个序列，必定会导致死锁

- 全局可利用资源：Available[M]
- 每线程最大需求量：Max[N][M]
- 已分配资源：Allocation[N][M]

### ex.2.6 缺页替换算法优缺点分析
优点:
- MIN/OPT:理论上是最优的，能够最小化缺页率。
- FIFO:实现简单，易于理解。
- Second Chance:改进FIFO 算法的性能,减少Belady异常
- LRU:比 FIFO 更智能，通常可以提供较好的性能。

缺点:
- MIN/OPT:无法实现，因为它要求操作系统知道未来的页面访问序列，在实际中不可用
- FIFO:不能根据页面的使用情况来决定替换页面，可能导致"Belady's Anomaly"（即增加内存反而会导致缺页率增加），性能较差。
- Second Chance:效率较低,无法完全替代更高级的算法,内存开销
- LRU:需要维护页面的使用顺序，通常通过链表或者栈来实现，因此需要更多的内存和计算资源。

## ex.3 进程同步
核心问题:互斥访问 有限等待 空闲让进
### ex.3.1 常用机制
#### ex.3.1.1 互斥锁
互斥锁是一种常见的同步机制，用于保护共享资源，确保同一时间只有一个进程可以访问该资源。互斥锁通常通过锁定和解锁操作来控制。

一个进程访问共享资源时，它会锁定该资源，其他进程则必须等待，直到资源被解锁。
#### ex.3.1.2 信号量
信号量是一种同步原语，用来控制对共享资源的访问。它通常通过一个整数值来表示资源的数量。信号量可以是二进制的（值为 0 或 1）或计数的（表示多个资源的数量）。

信号量有两种操作：
1. P（Wait）操作：当信号量的值大于 0 时，执行进程访问资源，并将信号量减 1。如果信号量值为 0，则进程进入等待队列。
2. V（Signal）操作：释放资源，信号量加 1。如果信号量值为 0，释放操作可能会唤醒一个等待的进程。

#### ex.3.1.3 条件变量
条件变量用于在多线程程序中实现线程之间的协作。它允许线程等待某个条件成立再继续执行，通常与互斥锁一起使用。

条件变量有两个主要操作：
1. 等待：如果条件不满足，进程会释放互斥锁并进入等待状态，直到条件满足。
2. 通知：当条件发生变化时，进程通知等待的线程继续执行。
#### ex.3.1.4 读写锁
读写锁是一种特殊类型的互斥锁，它允许多个线程同时读取资源，但在写入资源时，只允许一个线程进行操作。它通常用于读多写少的场景，以提高效率。

读锁允许多个线程同时获取，写锁则是独占的，写线程会阻塞所有读线程。
### ex.3.2 常见问题
#### ex.3.2.1 生产者-消费者问题
生产者-消费者问题描述了两个进程或线程（生产者和消费者）之间的同步问题。生产者将数据放入共享缓冲区，消费者从共享缓冲区中取出数据。

解决方法：使用信号量或互斥锁来确保缓冲区不会发生溢出或空置问题。例如，通过一个计数信号量来表示缓冲区的可用空间和已使用空间。
#### ex.3.2.2 哲学家就餐问题
该问题描述了多个进程（哲学家）共享资源（筷子）时，如何避免死锁和饥饿。

解决方法：可以通过各种策略来避免死锁，例如限制每个哲学家最多同时拿两支筷子，或者使用互斥锁和条件变量来保证资源访问的顺序。
#### ex.3.2.3 读写锁问题
在多线程环境下，如果多个线程同时读共享数据，可能会导致数据不一致，因此需要确保写操作的互斥。

解决方法：使用读写锁来允许多个线程同时读数据，但在写操作时必须独占数据，避免读写冲突。
#### ex.3.2.4 死锁问题
死锁是指两个或多个进程因争夺资源而相互等待，导致永远无法继续执行。

解决方法：常用的策略有资源分配图、避免循环等待、银行家算法等，或者通过锁的顺序要求来防止死锁。
### ex.3.3 重要概念
互斥访问:在同一时刻，有且仅有一个进程可以进入临界区

条件等待与唤醒：利用睡眠/唤醒机制，避免无意义的等待

多资源协调：协调（阻塞/放行）多个线程共享有限数量的资源
### ex.3.4 感觉会考的问题
**Q:用信号量机制来实现3个进程的取数协调，缓冲区的数量超过1**

**思路**:信号量设置两个empty和full表示空缓冲区信号量,满缓冲区信号量。对进程进行取数操作时，首先等待空缓冲区信号量（确保缓冲区有空位），再等待互斥锁，将内容放入后，释放互斥锁，增加满缓冲区信号量

在实现消费者时，则等待慢缓冲区信号量（确保缓冲区有数据），再等待互斥锁，将内容读取并移除后，释放互斥锁，增加空缓冲区信号

    // 初始化信号量
    semaphore mutex = 1  // 互斥信号量,初始值为1
    semaphore empty = N;  // 空缓冲区信号量，初始值为N
    semaphore full = 0;   // 满缓冲区信号量，初始值为0

    // 进程1、进程2、进程3的取数操作
    process Producer1() {
        while (true) {
            // 生产数据
            item = produce_item();

            // 等待空缓冲区
            sem_wait(empty);

            // 进入临界区，获取互斥锁
            sem_wait(mutex);

            // 将数据放入缓冲区
            put_item_into_buffer(item);

            // 离开临界区，释放互斥锁
            sem_signal(mutex);

            // 增加满缓冲区计数
            sem_signal(full);
        }
    }

    process Producer2() {
        while (true) {
            item = produce_item();
            sem_wait(empty);
            sem_wait(mutex);
            put_item_into_buffer(item);
            sem_signal(mutex);
            sem_signal(full);
        }
    }

    process Producer3() {
        while (true) {
            item = produce_item();
            sem_wait(empty);
            sem_wait(mutex);
            put_item_into_buffer(item);
            sem_signal(mutex);
            sem_signal(full);
        }
    }

    // 消费者进程
    process Consumer() {
        while (true) {
            // 等待满缓冲区
            sem_wait(full);

            // 进入临界区，获取互斥锁
            sem_wait(mutex);

            // 从缓冲区取出数据
            item = remove_item_from_buffer();

            // 离开临界区，释放互斥锁
            sem_signal(mutex);

            // 增加空缓冲区计数
            sem_signal(empty);

            // 消费数据
            consume_item(item);
        }
    }
