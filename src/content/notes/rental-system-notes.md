## 项目介绍

智能房屋租赁系统是软件工程基础课程大作业（团队项目），一个可本地运行、可答辩演示的完整租赁业务系统。用户分三类：**房东、租客、管理员**（默认账号 admin/landlord/tenant）。项目从需求核对文档出发，把 19 项需求全部落地，还加了扩展功能。

## 技术栈

Python + Flask + SQLAlchemy + MySQL + Jinja2 + HTML/CSS/JS。配套 Dockerfile/docker-compose.yml、多平台启动脚本（start.bat / start.ps1 / start.sh）、单元测试（tests/test_app.py）、CHANGELOG 记录迭代过程。

## 功能模块

- **账号**：邮箱验证码注册、密码加密、角色权限控制
- **房源**：发布/编辑/下架/图片视频链接，按地区/商圈/小区/户型/租金智能搜索，推荐分排序
- **智能代理**：自动回复租金、面积、预约、维修等常见问题
- **互动**：租客房东留言、房东新闻、预约看房
- **交易**：在线生成租赁合同、租金账单与模拟支付、维修投诉
- **统计**：出租率、租金收入、活跃度报表（CSV 导出 + 图表）、系统操作日志
- **运维**：SMTP 邮件与短信 Webhook（未配置时写本地 outbox 便于演示）、HTTPS adhoc 启动、并发压测脚本

## 我在团队里的分工

根据成员日志，我承担的是素材与前端视觉专项：

- 建立素材库：按「页面-模块-序号」三段式命名规范，输出图片命名与引用规范文档，统一 Pexels 无版权图源
- 主导房源详情页布局重构：卡片化分区（图片区/属性区/推荐区/地图区），响应式栅格，统一 style.css 规避内联样式冲突
- 前端联调：租客端搜索筛选、房东端入口、通知中心/维修投诉/合同页面的联调测试
- 结题：答辩 PPT 初稿与演示视频审核校对，参与 8 次正式会议

## 踩过的坑

- 自定义样式与既有 CSS 框架覆盖冲突 → 梳理样式优先级，统一在 style.css 调整
- 通知中心未读状态页面切换后丢失 → 前端本地缓存标记 + 后端已读接口联动
- 后端表字段与前端展示字段命名不一致 → 建立字段映射对照表写进接口文档

## 我的收获

- 需求文档和最终实现差距很大，19 项需求逐项核对落地比"写得差不多"费时得多
- 素材规范这种"不起眼"的工作，做好了能让全组开发省很多事
- 答辩材料的校对要提前做，临提交才发现 PPT 文字和功能描述不一致很被动
