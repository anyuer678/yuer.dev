## 项目介绍

暑期实训团队项目，QST 青软实训提出任务，开发一个桌面端在线教育平台 OnlineEduPlatform。背景是教育信息化 2.0 推进、线上教学需求爆发（报告引教育部数据：2024 年在线教育用户规模达 3.2 亿），但市面平台普遍功能碎片化、跨平台兼容不足，所以做一款集成直播、作业管理、白板协作的一体化桌面工具。面向中小学、职业院校、培训机构，未来可与学校教务系统对接、兼容教学摄像头/电子白板等硬件接口。

## 技术栈与架构

Qt 5.15 + Qt Quick/QML，C++17。pro 文件引入 multimedia、sql、network、concurrent、websockets 模块。报告里定了三层架构：

```
前端层 QML 界面组件（直播窗口、作业列表）
  ↓  Qt WebSocket
服务层 C++ 业务逻辑（直播推流、作业处理）
  ↓
数据层 SQLite（本地缓存）+ MySQL（集群存储）
```

数据链路：`前端 QML → Qt WebSocket → 后端 C++ 服务 → MySQL/SQLite`。实际实训实现以 SQLite 为主（edu_data.db 自动建表）。

## 功能模块

| 模块 | 内容 |
|---|---|
| 课程直播 | QCamera 采集 + RTMP 低延迟推流，直播/屏幕录制/弹幕互动 |
| 录播回放 | EduMediaHandler 管理媒体文件，直达文件夹的视频回放 |
| 在线作业 | 教师端布置 / 学生端提交，按角色区分页面 |
| 互动白板 | 白板笔可选颜色/粗细，与录屏配合效果好，可保存 png 截图 |
| 附加 | 弹幕（Danmaku）、学习进度追踪、中英语言切换、屏幕共享 |

## 界面设计细节（报告原文要点）

- **登录页**：输入昵称（决定作业署名）+ 选择身份（教师/学生，决定界面与功能）+ 登录按钮；未输入昵称时输入框变红强调
- **内部界面**：低能耗高画质的渐变素净背景（QML 实现），可更换色调
- **回放页彩蛋**：团队做了两个趣味互动——「模拟抽卡」和「在线烟花」；烟花绽放时显示「您辛苦了」，是开发者的致敬

## 数据库设计

E-R 图 + 表汇总（报告给出核心三表）：

| 表名 | 功能 |
|---|---|
| course_table | 课程基本信息 |
| assignment | 作业详情及提交记录（assign_id 自增主键、course_id 关联课程、title、due_time 截止时间、submit_file 提交文件路径） |
| live_record | 直播历史及观看记录 |

## 单元测试用例（报告原文）

| 测试对象 | 输入 | 预期输出 |
|---|---|---|
| 直播推流模块 | 1080P 摄像头 | 推流码率稳定在 1.2Mbps |

| 白板绘制 | 100 次连续画线 | 无卡顿，线条流畅 |

## 踩过的坑

- QML 与 C++ 交互：属性绑定和信号槽要理清，白板画图坐标在窗口缩放后会偏移，需要按缩放比例换算
- 本地推流录制：QCamera 采集的格式和 QMediaRecorder 期望的容器要匹配，否则录出来打不开
- SQLite 并发访问：作业提交和进度写入同时发生会锁库，改成单连接 + 队列写入

## 我的收获

- Qt Quick/QML 的开发模式和 Widgets 差别很大，声明式 UI 写起来快，但和 C++ 数据模型对接时要小心生命周期
- 桌面应用的多媒体链路（采集 → 编码 → 存储 → 回放）比想象中复杂，每一环的格式都要对齐；直播还涉及 RTMP 协议和推流码率控制
- 写报告本身就是软件工程演练：可行性研究（技术/经济/操作三层面）、需求分析、体系架构设计、数据库概念模型、测试用例，整个流程走一遍
- 产品细节（登录态区分角色、空输入反馈、回放页的趣味彩蛋）看着小，但都是用户体验的一部分
