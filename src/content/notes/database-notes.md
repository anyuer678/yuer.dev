# 第1章 绪论

## 三级模式与两级映像

| 层次 | 名称 | 作用 | 举例 |
|------|------|------|------|
| 外模式 | 用户模式/视图层 | 面向用户的局部数据视图 | CREATE VIEW |
| 概念模式 | 逻辑模式 | 全局逻辑结构，表的定义 | CREATE TABLE |
| 内模式 | 存储模式 | 数据的物理存储方式 | 索引、聚簇 |

| 映像 | 作用 | 实现的独立性 |
|------|------|--------------|
| 外模式/概念模式映像 | 逻辑独立性 | 概念模式变，外模式不变 |
| 概念模式/内模式映像 | 物理独立性 | 存储变，逻辑不变 |

**记忆口诀**：外概内三层，外概逻辑独，概内物理独。

## 数据模型三要素

- **数据结构**：对象及关系的静态描述（表、字段、索引）
- **数据操作**：增删改查（DML）
- **完整性约束**：实体完整性、参照完整性、用户定义完整性

## 数据管理发展

| 阶段 | 时间 | 数据共享 | 数据冗余 | 独立性 |
|------|------|---------|---------|--------|
| 人工管理 | 1950s前 | 无 | 高 | 无 |
| 文件系统 | 1950s-60s | 低 | 高 | 差 |
| 数据库系统 | 1960s后 | 高 | 低 | 高 |

# 第2章 关系代数

## 基本运算速查

| 运算 | 符号 | 作用 | 记忆 |
|------|------|------|------|
| 选择 | σ | 按条件选行（水平切片） | σ像筛子，筛行 |
| 投影 | π | 选列并去重（垂直切片） | π像尺子，量列 |
| 并 | ∪ | 两个关系合并，去重 | 合并同类项 |
| 差 | − | 在R中但不在S中的元组 | 减法 |
| 笛卡尔积 | × | 所有可能组合 | 交叉相乘 |

## 连接运算速查

| 运算 | 符号 | 说明 |
|------|------|------|
| θ连接 | ⋈(条件) | 按任意比较条件连接 |
| 等值连接 | ⋈(A=B) | 属性值相等连接 |
| 自然连接 | ⋈ | 等值连接后去掉重复列 |
| 外连接 | ⟕/⟖/⟗ | 左/右/全外连接，保留未匹配行 |

## 除运算

- **记法**：R ÷ S
- **语义**：找出R中与S的**所有**组合都匹配的元组
- **典型场景**：查询"选修了全部课程的学生"
- **步骤**：π(R的属性-S的属性)(R) - π(R的属性-S的属性)((π(R的属性-S的属性)(R) × S) - R)

## 运算优先级

**选择、投影 > 连接 > 并、差、笛卡尔积**

> 查询优化核心思想：尽早做选择和投影，减少中间结果规模。

# 第3章 关系演算

## 元组关系演算 vs 域关系演算

| 类型 | 变量 | 语法示例 | 说明 |
|------|------|---------|------|
| 元组关系演算(TRC) | 元组变量 | {t \| Student(t) ∧ t.Sage > 20} | 对整行操作 |
| 域关系演算(DRC) | 域变量 | {⟨sname⟩ \| Student(⟨sname, sage, ...⟩) ∧ sage > 20} | 对列值操作 |

## 关键概念

- **自由元组变量**：不含量词限定的变量
- **约束元组变量**：位于量词作用域内的变量（存在量词∃/全称量词∀）
- **关系完备性**：关系代数 ≡ 元组关系演算 ≡ 域关系演算（表达能力等价）

## 典型查询示例

**元组演算**：查询年龄大于20的学生姓名
```
{t | ∃s ∈ Student(s.Sname = t.Name ∧ s.Sage > 20)}
```

**域演算**：同上查询
```
{⟨n⟩ | ∃s, a, d (Student(⟨n, a, d⟩) ∧ a > 20)}
```

# 第4章 SQL

## SQL分类速查

| 类别 | 全称 | 功能 | 关键字 |
|------|------|------|--------|
| DDL | 数据定义语言 | 定义表、索引、视图 | CREATE, ALTER, DROP |
| DML | 数据操纵语言 | 增删改查 | SELECT, INSERT, UPDATE, DELETE |
| DCL | 数据控制语言 | 权限管理 | GRANT, REVOKE |
| TCL | 事务控制语言 | 事务管理 | COMMIT, ROLLBACK |

## DDL核心

```sql
-- 建表
CREATE TABLE 表名 (
    列名 类型 [约束],
    PRIMARY KEY (列),
    FOREIGN KEY (列) REFERENCES 表(列)
);

-- 修改表
ALTER TABLE 表 ADD 列名 类型;
ALTER TABLE 表 DROP COLUMN 列名;
ALTER TABLE 表 MODIFY 列名 新类型;

-- 删除表
DROP TABLE 表名;
```

## DML核心

```sql
-- 查询（SELECT完整结构）
SELECT [DISTINCT] 列
FROM 表
[WHERE 条件]
[GROUP BY 分组列 HAVING 分组条件]
[ORDER BY 排序列 [ASC|DESC]]
[LIMIT n OFFSET m];

-- 聚合函数
COUNT(*), SUM(col), AVG(col), MAX(col), MIN(col)

-- 子查询
-- IN子查询、EXISTS子查询、相关子查询、派生表

-- 多表连接
SELECT * FROM A JOIN B ON A.id = B.aid;
SELECT * FROM A LEFT JOIN B ON A.id = B.aid;
```

## 视图

```sql
-- 创建视图
CREATE VIEW 视图名 AS SELECT 列 FROM 表 WHERE 条件;

-- 视图作用
-- 1. 简化复杂查询  2. 限制数据访问  3. 逻辑数据独立性
-- 视图不存储数据，只存储定义（物化视图除外）
```

## 索引

```sql
-- 创建索引
CREATE INDEX 索引名 ON 表(列);
CREATE UNIQUE INDEX 索引名 ON 表(列);
-- 复合索引
CREATE INDEX 索引名 ON 表(列1, 列2);
-- 删除索引
DROP INDEX 索引名 ON 表;
```

## 存储过程

```sql
DELIMITER //
CREATE PROCEDURE 过程名(参数列表)
BEGIN
    -- SQL语句
    -- IF/ELSE, WHILE, DECLARE等
END //
DELIMITER ;

-- 调用
CALL 过程名(参数);
```

## 触发器

```sql
CREATE TRIGGER 触发器名
{BEFORE|AFTER} {INSERT|UPDATE|DELETE}
ON 表名
FOR EACH ROW
BEGIN
    -- 触发逻辑
END;
-- OLD引用修改前的值，NEW引用修改后的值
```

## SQL易混淆点

| 概念 | 区别 |
|------|------|
| WHERE vs HAVING | WHERE在分组前筛选，HAVING在分组后筛选 |
| DELETE vs TRUNCATE vs DROP | DELETE逐行删（可回滚），TRUNCATE清空（不可回滚），DROP删表结构 |
| INNER JOIN vs LEFT JOIN | INNER只返回匹配行，LEFT返回左表全部+右表匹配 |
| DISTINCT vs GROUP BY | 都去重，但GROUP BY可接聚合函数 |

# 第5章 ER模型

## 三要素

| 要素 | 图形 | 说明 |
|------|------|------|
| 实体 | 矩形 | 现实世界可区分的对象 |
| 属性 | 椭圆 | 实体的性质（主键下划线） |
| 联系 | 菱形 | 实体间的关系 |

## 联系类型

| 类型 | 说明 | 关系模式转换 |
|------|------|-------------|
| 1:1 | 一对一 | 可合并到任一方，加外键 |
| 1:N | 一对多 | 在N端加外键指向1端 |
| M:N | 多对多 | **必须**建立独立关系（中间表） |

**记忆口诀**：1:1随便放，1:N放N端，M:N建新表。

## 属性分类

| 分类 | 说明 | 示例 |
|------|------|------|
| 简单属性 | 不可再分 | 性别、年龄 |
| 复合属性 | 可再分 | 姓名(姓,名)、地址(省,市,区) |
| 单值属性 | 一个取值 | 学号 |
| 多值属性 | 多个取值 | 电话号码 |
| 派生属性 | 可由其他属性计算 | 年龄(由出生日期派生) |
| 码属性 | 唯一标识 | 主键 |

## 弱实体

- 无独立主码，依赖于强实体存在
- 用**双矩形**表示，部分码用**双下划线**
- 示例：病房(强实体) - 病床(弱实体)

## ER图转关系模式规则

| ER概念 | 关系模式转换 |
|--------|-------------|
| 实体 | → 关系（表） |
| 1:1联系 | → 任一方加外键 |
| 1:N联系 | → N端加外键 |
| M:N联系 | → 新关系，包含双方主键 |
| 多值属性 | → 新关系 |
| 复合属性 | → 取最底层简单属性 |
| 弱实体 | → 关系，包含强实体主键 |

# 第6章 规范化

## 函数依赖速查

| 类型 | 定义 | 示例 |
|------|------|------|
| 平凡函数依赖 | Y⊆X，X→Y是平凡的 | {A,B}→A |
| 非平凡函数依赖 | Y⊈X，X→Y是非平凡的 | A→B |
| 完全函数依赖 | X的任一真子集不能决定Y | {学号,课程号}→成绩 |
| 部分函数依赖 | X的某真子集能决定Y | {学号,课程号}→姓名 |
| 传递函数依赖 | X→Y, Y→Z, Y↛X | 学号→系号→系主任 |

## Armstrong公理

| 公理 | 内容 | 推论 |
|------|------|------|
| 自反律 | Y⊆X → X→Y | — |
| 增广律 | X→Y → XZ→YZ | — |
| 传递律 | X→Y, Y→Z → X→Z | — |
| **合并律** | X→Y, X→Z → X→YZ | 由公理推出 |
| **分解律** | X→YZ → X→Y, X→Z | 由公理推出 |
| **伪传递律** | X→Y, WY→Z → WX→Z | 由公理推出 |

## 范式递进

| 范式 | 要求 | 消除的问题 |
|------|------|-----------|
| 1NF | 属性不可再分（原子性） | — |
| 2NF | 满足1NF + 非主属性完全依赖于候选码 | 消除部分函数依赖 |
| 3NF | 满足2NF + 非主属性不传递依赖于候选码 | 消除传递函数依赖 |
| BCNF | 所有决定因素都是候选码 | 消除主属性的部分/传递依赖 |

**记忆口诀**：1NF原子化，2NF消部分，3NF消传递，BCNF决定因素必须是码。

## 候选码求解步骤

1. 出现在函数依赖**左边**的属性集合 → L
2. 出现在函数依赖**右边**的属性集合 → R
3. 出现在**两边**的属性集合 → LR
4. **只在左边**出现的属性必须在候选码中
5. **不在任何一边**出现的属性必须在候选码中
6. 求闭包，验证是否能决定所有属性

## 模式分解

| 分解类型 | 要求 | 方法 |
|---------|------|------|
| 无损连接分解 | 分解后自然连接能还原 | 分解为R-X和X |
| 保持函数依赖分解 | 分解后不丢失函数依赖 | 按依赖分组 |

**分解准则**：同时满足**无损连接** + **保持函数依赖**。

## 范式判定步骤

```
找候选码 → 找非主属性 → 检查部分依赖 → 检查传递依赖 → 判定级别 → 不满足则分解
```

# 第7章 数据库设计

## 六阶段流程

| 阶段 | 主要任务 | 产出 |
|------|---------|------|
| 1. 需求分析 | 收集用户需求 | 数据流图(DFD)、数据字典 |
| 2. 概念设计 | 建立概念模型 | ER图 |
| 3. 逻辑设计 | ER→关系模式 | 规范化后的表结构 |
| 4. 物理设计 | 存储与索引设计 | 存储方案、索引策略 |
| 5. 数据库实施 | 建库、载数据、测试 | 可运行的数据库 |
| 6. 运行维护 | 日常维护、性能调优 | 持续优化 |

**记忆口诀**：需概逻物，实施维护（需概念逻辑物理）。

## 各阶段详细任务

### 需求分析
- 数据需求：哪些数据、数据间关系
- 处理需求：数据操作频率、响应时间
- 产出：DFD图、数据字典（数据项、数据结构、数据流、数据存储）

### 概念设计
- 从用户视角构建ER模型
- 不依赖具体DBMS
- ER图→全局ER图（合并子系统ER图）

### 逻辑设计
- ER图转关系模式（按转换规则）
- 规范化到3NF或BCNF
- 模式评价与优化

### 物理设计
- 确定存储结构（堆、聚簇、Hash）
- 选择存取方法（索引、散列）
- 确定数据分布（分区、分片）
- 评估时间/空间开销

## 设计方法对比

| 方法 | 特点 |
|------|------|
| 自顶向下 | 先全局后局部，结构清晰 |
| 自底向上 | 先局部后全局，容易实现 |
| 混合策略 | 顶层自顶向下，底层自底向上 |

# 第8章 索引与查询优化

## 索引类型速查

| 索引类型 | 适用场景 | 优点 | 缺点 |
|---------|---------|------|------|
| B+树索引 | 范围查询、排序、等值查询 | 查询稳定、范围高效 | 维护成本较高 |
| Hash索引 | 等值查询 | O(1)查找 | 不支持范围、排序 |
| 位图索引 | 低基数列(性别、状态) | 位运算快 | 不适合高基数、DML慢 |
| 全文索引 | 文本检索 | 支持关键词搜索 | 占空间、更新慢 |
| 倒排索引 | 全文检索 | 关键词→文档映射 | 构建成本高 |

## B+树核心特征

| 特性 | 说明 |
|------|------|
| 非叶子节点 | 只存索引键值，不含数据 |
| 叶子节点 | 存所有键值+数据指针，**有序链表** |
| 平衡 | 所有叶子在同一层 |
| 查询 | 从根到叶，O(log n) |
| 范围查询 | 叶子链表顺序扫描 |
| 高度 | 3-4层可支持千万级数据 |

## 聚簇索引 vs 非聚簇索引

| 对比项 | 聚簇索引 | 非聚簇索引 |
|--------|---------|-----------|
| 数据存储 | 索引即数据的物理顺序 | 索引与数据分离 |
| 数量 | 每表**仅一个** | 每表可**多个** |
| 主键默认 | 是（InnoDB） | — |
| 二级查找 | 不需要 | 需要（先查索引再定位数据） |
| 适用场景 | 范围查询、排序 | 点查询 |

**记忆口诀**：聚簇一张表一个，数据跟着索引走；非聚簇多张表多个，先查索引再找数。

## 复合索引最左前缀原则

```sql
-- 建索引 (a, b, c)
WHERE a = 1           -- ✓ 使用索引
WHERE a = 1 AND b = 2 -- ✓ 使用索引
WHERE a = 1 AND b = 2 AND c = 3 -- ✓ 使用索引
WHERE b = 2           -- ✗ 不使用
WHERE b = 2 AND c = 3 -- ✗ 不使用
WHERE a = 1 AND c = 3 -- ✓ 只用a部分
```

## 索引设计原则

| 应该做 | 不应该做 |
|--------|---------|
| 在WHERE/JOIN/ORDER BY列建索引 | 在低选择性列建索引(如性别) |
| 在高选择性列建索引 | 在索引列上用函数/表达式 |
| 小表可以不建索引 | 避免过多索引(影响写性能) |
| 控制索引数量 | 避免LIKE '%abc'前导通配 |
| 用EXPLAIN检查执行计划 | 避免OR连接非索引列 |

## 查询优化策略

| 策略 | 说明 |
|------|------|
| 选择下推 | 先做σ选择，再做其他运算 |
| 投影下推 | 先做π投影，减少中间结果 |
| 连接优化 | 小表驱动大表 |
| 子查询优化 | 相关子查询→JOIN |
| 索引利用 | 走索引而非全表扫描 |

## EXPLAIN执行计划type列（从好到坏）

```
system > const > eq_ref > ref > range > index > ALL
```

- **system**：表仅一行
- **const**：主键或唯一索引等值查询
- **eq_ref**：JOIN时主键/唯一索引
- **ref**：非唯一索引等值查询
- **range**：索引范围扫描
- **index**：全索引扫描
- **ALL**：全表扫描（最差）
