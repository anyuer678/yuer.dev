## 背景

EvoCode 是一个 AI 软件维护与演化平台，立项时分析引擎和报告生成都在一个 Python 服务里。跑通原型很快，但代码分析（确定性）和 LLM 输出（概率性）的演化节奏完全不同。

## 五个功能方向

平台围绕软件维护与演化做五件事：

1. **结构分析**：解析代码结构（模块、依赖、调用关系），这是所有上层能力的事实基础
2. **质量评估**：基于结构分析给出可量化的质量指标，不依赖 LLM 的主观判断
3. **技术债识别**：标记代码中的技术债点（重复代码、过长函数、坏味道）
4. **重构建议**：对识别出的问题给出具体的重构方向
5. **升级辅助**：帮助评估依赖升级的影响范围，降低升级风险

## 发生了什么

第一次拆分发生在引入多模型支持时：LLM 的 Provider 抽象被 Spring Boot 网关接管，Python 侧只保留确定性分析。数据流变成单向：分析结果 → 网关 → LLM。

## 结论

确定性计算和概率性生成是两种"信任等级"，混在一起会让调试互相污染。拆开后：分析结果可单测、可缓存；LLM 生成可以随时换模型而不影响事实层。

## 下一步计划

- 把分析任务异步化，支持增量解析（只分析变更的部分）
- 质量评估模块先落地：基于结构分析给出可量化的指标
