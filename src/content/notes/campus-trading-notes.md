## 项目介绍

软件交互课程大作业，一个校园 C2C 二手交易平台。C2C 指个人对个人的交易：买家浏览卖家发布的商品、按分类过滤或站内搜索、留言联系卖家；也能发布求购信息，让有货的卖家反过来联系买家。项目按团队分工开发，每位成员负责一个模块并写功能说明文档，我的分工集中在消息与提醒相关功能。

## 技术栈

Spring Boot 一键启动 + MyBatis + MySQL 5.7（JDK 1.8），前端是 webapp/JSP 页面 + jQuery Ajax 局部刷新，Navicat 导入 `c2c.sql` 建库建表。前端交互用 Ajax 局部刷新而不是整页跳转，体验上更接近现代站点。

## 功能模块

### 账号体系
- 手机号 + 短信验证码注册（每个手机号只能注册一个账号），登录后才能浏览和发布
- 个人信息完善：姓名、性别、学号、宿舍号、邮箱、所在校区
- 演示环境没有真实短信服务，验证码用固定值 + 日志输出兜底

### 商品交易
- **二手商城**：展示全部商品，侧边栏按分类过滤；数据多时分页（上一页/下一页/跳页）
- **商品详情**：图片、名字、价格、数量；下方留言区，已登录用户可评论，发布者可查看留言达成交易意向；可加入购物车
- **发布商品 / 发布求购**：填信息 + 选图片，Ajax 提交入库；「我发布的商品」「我发布的求购」可修改/删除
- **购物车**：添加数量/减少、移除、选收货地址结算
- **站内搜索引擎**：每个页面顶部有搜索框，按商品名模糊查询

### 我的扩展部分：价格参考与消息提醒
- **价格参考接口** `GET /goods/price/reference?categoryId=`：统计同分类商品在 `goodsoforderform`/`shopinformation` 的成交价，返回 min/max/avg，帮助卖家定价
- **一键议价** `POST /message/bargain/send`：详情页模态框选「少 5 元 / 少 10 元 / 包邮 / 自定义金额」，封装成消息写入 message 表
- **求购订阅**：`/subscribeCategory.do` 订阅某分类；发布商品成功后模糊匹配 `userwant` 表 + `buy_subscribe` 表，向匹配用户发站内信「有新的商品【商品名】可能符合您的需求，价格：xx元」
- **降价提醒**：商品更新且新价低于旧价时，通知收藏该商品的用户
- **过期提醒**：每日凌晨 2 点定时任务扫描发布超 30 天的商品，提醒发布者更新或下架
- **消息分类**：message 表按 `message_type` 区分（1=交易、2=价格提醒、3=过期提醒），列表可按类型过滤，`is_read` 标记已读

## 数据库设计

核心表：用户表、`shopinformation`（商品）、`userwant`（求购）、`goodsoforderform`（成交订单）、`usercollection`（收藏）、`buy_subscribe`（分类订阅）、`message`（站内信，扩展了 message_type/bargain_type/related_id/is_read 字段）。

## 踩过的坑

- JSP + 原生 JS 交互层代码量大，筛选条件一多查询 SQL 就要动态拼条件，注意用参数绑定防注入
- 消息表是后期扩展的，加枚举字段时要考虑旧数据兼容（默认值、可空）
- 短信验证码演示环境无真实服务，用固定验证码 + 日志输出兜底
- 分类过滤依赖侧边栏每个分类的 id，前后端 id 约定要一致，否则 Ajax 查不到数据

## 我的收获

- 多条件组合筛选的动态 WHERE 写法是这次最实用的技能点
- 消息驱动的功能（议价、订阅匹配、降价/过期提醒）本质都是「事件 → 写消息表 → 前端轮询/查询」，这个模式后面做任何通知类功能都能复用
- 定时任务（`@Scheduled` 每日 2 点扫过期商品）比想象中简单，但要注意任务幂等，避免重复发提醒
- 团队分工「每人一个模块 + 功能说明文档」的模式让贡献可追溯，接口契约（路径、参数、返回 JSON）必须文档化
- 交易类业务的状态（在售/已售/已下架）要用枚举管理，靠字符串裸写容易乱
