# 数据库系统学习指导

## 一、课程资料分析

### 资料结构
- **资料类型**：PPT课件（ch1-ch10）
- **内容覆盖**：关系代数、SQL语言、规范化设计、数据库设计、索引技术等

### 详细知识点

#### ch1 数据库系统概述
- **数据库基本概念**
  - **数据（Data）**：描述事物的符号记录
    - 数据的含义称为语义
    - 数据和语义不可分
  - **数据库（Database, DB）**：长期存储在计算机内、有组织的、可共享的数据集合
    - 特点：永久存储、有组织、可共享
  - **数据库管理系统（Database Management System, DBMS）**
    - 位于用户和操作系统之间的数据管理软件
    - 功能：
      - 数据定义功能（DDL）
      - 数据操纵功能（DML）
      - 数据库运行管理
      - 数据库的建立和维护
    - 常见DBMS：MySQL、Oracle、SQL Server、PostgreSQL
  - **数据库系统（Database System, DBS）**
    - 组成：数据库、DBMS、应用程序、数据库管理员（DBA）
    - 特点：数据结构化、数据共享性高、数据独立性高、统一管理和控制
- **数据库系统结构**
  - **三级模式结构**
    - **模式（Schema）**：也称逻辑模式，数据库中全体数据的逻辑结构和特征的描述
      - 是所有用户的公共数据视图
      - 一个数据库只有一个模式
    - **外模式（External Schema）**：也称子模式或用户模式
      - 数据库用户能够看见和使用的局部数据的逻辑结构和特征
      - 是数据库用户的数据视图
      - 一个数据库可以有多个外模式
    - **内模式（Internal Schema）**：也称存储模式
      - 数据物理结构和存储方式的描述
      - 是数据在数据库内部的表示方式
      - 一个数据库只有一个内模式
  - **两级映像**
    - **外模式/模式映像**：保证数据的逻辑独立性
      - 模式改变时，通过修改外模式/模式映像，使外模式保持不变
      - 应用程序不需要修改
    - **模式/内模式映像**：保证数据的物理独立性
      - 内模式改变时，通过修改模式/内模式映像，使模式保持不变
      - 应用程序不需要修改
- **数据模型**
  - **层次模型（Hierarchical Model）**
    - 用树形结构表示数据及其联系
    - 特点：有且只有一个根节点，其他节点有且只有一个父节点
    - 优点：结构简单、查询效率高
    - 缺点：不能表示多对多联系、插入删除限制多
  - **网状模型（Network Model）**
    - 用有向图结构表示数据及其联系
    - 特点：允许一个以上的节点无双亲，一个节点可以有多个双亲
    - 优点：可以表示多对多联系、存取效率高
    - 缺点：结构复杂、编程复杂
  - **关系模型（Relational Model）**
    - 用二维表结构表示数据及其联系
    - 特点：
      - 单一的数据结构（关系）
      - 关系必须是规范化的
      - 数据的逻辑结构是二维表
    - 优点：
      - 结构简单、清晰
      - 数据独立性高
      - 建立在严格的数学概念基础上
      - 非过程化的数据操纵
    - 缺点：查询效率有时不如非关系模型
- **数据库管理系统的功能**
  - 数据定义功能
  - 数据组织、存储和管理
  - 数据操纵功能
  - 数据库的事务管理和运行管理
  - 数据库的建立和维护功能
  - 其他功能（通信、数据转换、异构数据库互操作等）
- **数据库系统的发展历程**
  - 第一代：层次、网状数据库系统
  - 第二代：关系数据库系统
  - 第三代：面向对象数据库系统
  - 现代：NoSQL、NewSQL数据库系统

#### ch2_1~5 关系代数
- **关系模型基本概念**
  - **关系（Relation）**：一个关系对应通常说的一张表
  - **元组（Tuple）**：表中的一行，也称记录
  - **属性（Attribute）**：表中的一列，也称字段
  - **域（Domain）**：属性的取值范围
  - **分量（Component）**：元组中的一个属性值
  - **关系模式（Relation Schema）**：对关系的描述
    - 形式化表示：R(U, D, DOM, F)
    - 简化表示：R(A1, A2, ..., An)
  - **候选码（Candidate Key）**：能唯一标识关系中元组的属性或属性组
  - **主码（Primary Key）**：从候选码中选定的一个
  - **外码（Foreign Key）**：关系R中的属性或属性组，它是另一个关系S的主码
  - **全码（All-key）**：关系模式的所有属性组是这个关系模式的候选码
- **关系代数运算**
  - **传统集合运算**
    - **并（Union）**：R∪S = {t | t∈R ∨ t∈S}
      - 要求：R和S具有相同的目（列数），且相应属性取自同一个域
    - **差（Difference）**：R-S = {t | t∈R ∧ t∉S}
      - 要求：R和S具有相同的目（列数），且相应属性取自同一个域
    - **交（Intersection）**：R∩S = {t | t∈R ∧ t∈S}
      - 要求：R和S具有相同的目（列数），且相应属性取自同一个域
      - 等价于：R-(R-S)
    - **笛卡尔积（Cartesian Product）**：R×S = {trts | tr∈R ∧ ts∈S}
      - 结果的目数：R的目数 + S的目数
      - 结果的元组数：R的元组数 × S的元组数
  - **专门关系运算**
    - **选择（Selection）**：σF(R) = {t | t∈R ∧ F(t)='真'}
      - 从关系R中选择满足条件F的元组
      - 是从行的角度进行的运算
      - 例子：σ年龄>20(学生)
    - **投影（Projection）**：πA(R) = {t[A] | t∈R}
      - 从关系R中选择指定的属性列
      - 是从列的角度进行的运算
      - 会自动去除重复的元组
      - 例子：π姓名,年龄(学生)
    - **连接（Join）**：从两个关系的笛卡尔积中选取属性间满足一定条件的元组
      - **θ连接**：R ⋈θ S = {trts | tr∈R ∧ ts∈S ∧ tr[A]θ ts[B]}
      - **等值连接**：θ为等号的θ连接
      - **自然连接**：特殊的等值连接，要求两个关系中进行比较的分量必须是相同的属性组，并且在结果中把重复的属性列去掉
      - **外连接**：
        - 左外连接（Left Outer Join）：保留左边关系R的所有元组
        - 右外连接（Right Outer Join）：保留右边关系S的所有元组
        - 全外连接（Full Outer Join）：保留左右两边关系的所有元组
    - **除（Division）**：R÷S = {tr[X] | tr∈R ∧ πY(S)⊆Yx}
      - 设R(X, Y)，S(Y, Z)，X、Y、Z为属性组
      - 结果是满足条件的X属性组的取值
      - 例子：查询选修了所有课程的学生学号
- **关系演算概念**
  - 关系演算以数理逻辑中的谓词演算为基础
  - 按谓词变元的不同分为：
    - 元组关系演算
    - 域关系演算
  - 关系代数、元组关系演算、域关系演算三者在表达能力上是等价的

#### ch2_6 关系演算-域演算
- **元组关系演算**
  - 以元组为变量
  - 表达式形式：{t | P(t)}
    - t是元组变量
    - P是公式
  - 例子：
    - {t | Student(t) ∧ t.age > 20}
    - {t | ∃s(Student(s) ∧ t.sno = s.sno ∧ t.sname = s.sname)}
- **域关系演算**
  - 以域为变量
  - 表达式形式：{<x1, x2, ..., xn> | P(x1, x2, ..., xn)}
  - QBE（Query By Example）是域关系演算的代表
- **关系代数与关系演算的等价性**
  - 任何关系代数表达式都可以等价地转换为元组关系演算表达式
  - 任何元组关系演算表达式都可以等价地转换为关系代数表达式
  - 安全的元组关系演算表达式、安全的域关系演算表达式和关系代数表达式是等价的

#### ch3-4 SQL
- **SQL基本语法**
  - SQL的特点：
    - 综合统一（DDL、DML、DCL一体化）
    - 高度非过程化
    - 面向集合的操作方式
    - 以同一种语法结构提供多种使用方式
    - 语言简洁，易学易用
  - SQL的组成：
    - 数据定义语言（DDL）
    - 数据操纵语言（DML）
    - 数据查询语言（DQL）
    - 数据控制语言（DCL）
- **数据定义语言（DDL）**
  - **CREATE TABLE（创建表）**
    - 语法：CREATE TABLE <表名> (
        <列名> <数据类型> [列级完整性约束],
        ...
        [表级完整性约束]
      );
    - 常用数据类型：
      - INT/INTEGER：整数
      - DECIMAL/NUMERIC(p, s)：定点数
      - FLOAT/REAL：浮点数
      - CHAR(n)：定长字符串
      - VARCHAR(n)：变长字符串
      - DATE：日期
      - TIME：时间
    - 完整性约束：
      - PRIMARY KEY：主码约束
      - FOREIGN KEY：外码约束
      - NOT NULL：非空约束
      - UNIQUE：唯一约束
      - CHECK：检查约束
      - DEFAULT：默认值
    - 例子：
      ```sql
      CREATE TABLE Student (
          Sno CHAR(9) PRIMARY KEY,
          Sname CHAR(20) NOT NULL,
          Ssex CHAR(2),
          Sage SMALLINT,
          Sdept CHAR(20)
      );
      ```
  - **ALTER TABLE（修改表）**
    - 增加列：ALTER TABLE <表名> ADD <新列名> <数据类型> [完整性约束];
    - 修改列：ALTER TABLE <表名> MODIFY <列名> <数据类型>;
    - 删除列：ALTER TABLE <表名> DROP COLUMN <列名>;
    - 增加约束：ALTER TABLE <表名> ADD CONSTRAINT <约束名> <约束定义>;
    - 删除约束：ALTER TABLE <表名> DROP CONSTRAINT <约束名>;
  - **DROP TABLE（删除表）**
    - 语法：DROP TABLE <表名> [CASCADE | RESTRICT];
    - CASCADE：级联删除，删除依赖该表的对象
    - RESTRICT：限制删除，只在没有依赖对象时才能删除
- **数据操纵语言（DML）**
  - **INSERT（插入数据）**
    - 插入单个元组：
      ```sql
      INSERT INTO <表名> [(<属性列1>, ...)]
      VALUES (<常量1>, ...);
      ```
    - 插入子查询结果：
      ```sql
      INSERT INTO <表名> [(<属性列1>, ...)]
      <子查询>;
      ```
  - **UPDATE（更新数据）**
    - 语法：
      ```sql
      UPDATE <表名>
      SET <列名> = <表达式> [, ...]
      [WHERE <条件>];
      ```
  - **DELETE（删除数据）**
    - 语法：
      ```sql
      DELETE FROM <表名>
      [WHERE <条件>];
      ```
- **数据控制语言（DCL）**
  - **GRANT（授予权限）**
    - 语法：
      ```sql
      GRANT <权限> [, ...]
      ON <对象类型> <对象名>
      TO <用户> [, ...]
      [WITH GRANT OPTION];
      ```
    - 常用权限：SELECT、INSERT、UPDATE、DELETE、ALTER、CREATE、ALL PRIVILEGES
  - **REVOKE（收回权限）**
    - 语法：
      ```sql
      REVOKE <权限> [, ...]
      ON <对象类型> <对象名>
      FROM <用户> [, ...]
      [CASCADE];
      ```
- **查询语言（SELECT）**
  - **基本查询**
    - 语法：
      ```sql
      SELECT [ALL | DISTINCT] <目标列表达式> [, ...]
      FROM <表名或视图名> [, ...]
      [WHERE <条件表达式>]
      [GROUP BY <列名> [HAVING <条件表达式>]]
      [ORDER BY <列名> [ASC | DESC]];
      ```
  - **连接查询**
    - **内连接（INNER JOIN）**：
      ```sql
      SELECT ...
      FROM 表1 JOIN 表2 ON 表1.列 = 表2.列;
      ```
    - **外连接（OUTER JOIN）**：
      - 左外连接（LEFT OUTER JOIN）
      - 右外连接（RIGHT OUTER JOIN）
      - 全外连接（FULL OUTER JOIN）
    - **自连接（Self Join）**：表与自身连接
  - **子查询（嵌套查询）**
    - 不相关子查询：子查询的查询条件不依赖于父查询
    - 相关子查询：子查询的查询条件依赖于父查询
    - 带IN谓词的子查询
    - 带比较运算符的子查询
    - 带ANY（SOME）或ALL谓词的子查询
    - 带EXISTS谓词的子查询
  - **聚合函数（SUM、AVG、COUNT、MAX、MIN）**
    - COUNT([DISTINCT | ALL] *)：统计元组个数
    - COUNT([DISTINCT | ALL] <列名>)：统计一列中值的个数
    - SUM([DISTINCT | ALL] <列名>)：计算一列值的总和
    - AVG([DISTINCT | ALL] <列名>)：计算一列值的平均值
    - MAX([DISTINCT | ALL] <列名>)：求一列值中的最大值
    - MIN([DISTINCT | ALL] <列名>)：求一列值中的最小值
  - **GROUP BY和HAVING**
    - GROUP BY：将查询结果按某一列或多列的值分组
    - HAVING：筛选分组后的组
  - **ORDER BY**
    - 对查询结果排序
    - ASC：升序（默认）
    - DESC：降序

#### ch7 Entity-Relation Model
- **E-R模型基本概念**
  - 实体-联系模型（Entity-Relationship Model）
  - 用于数据库概念设计
  - 三个基本概念：实体、属性、联系
- **实体（Entity）**
  - 客观存在并可相互区别的事物
  - 实体集（Entity Set）：同一类型实体的集合
  - 实体型（Entity Type）：用实体名及其属性名集合来抽象和刻画同类实体
- **属性（Attribute）**
  - 实体所具有的某一特性
  - 属性的分类：
    - 简单属性（Simple Attribute）：不可再分的属性
    - 复合属性（Composite Attribute）：可以再分的属性
    - 单值属性（Single-valued Attribute）：一个实体只有一个值的属性
    - 多值属性（Multivalued Attribute）：一个实体有多个值的属性
    - 派生属性（Derived Attribute）：可以从其他属性推导出来的属性
- **关系（Relationship）**
  - 实体之间的联系
  - 联系的类型：
    - 一对一联系（1:1）
    - 一对多联系（1:n）
    - 多对多联系（m:n）
  - 联系也可以有属性
- **E-R图设计**
  - **实体的表示**：用矩形表示，矩形框内写明实体名
  - **属性的表示**：用椭圆形表示，并用无向边将其与相应的实体连接起来
  - **关系的表示**：用菱形表示，菱形框内写明联系名，并用无向边分别与有关实体连接起来，同时在无向边旁标上联系的类型
  - **基数约束**：
    - 参与约束（Participation Constraint）：
      - 全部参与（Total Participation）
      - 部分参与（Partial Participation）
    - 基数（Cardinality）：
      - 最小基数
      - 最大基数
  - **弱实体（Weak Entity）**：
    - 不能独立存在，必须依赖于其他实体
    - 用双线矩形表示
    - 标识联系用双线菱形表示

#### ch8 规范化
- **函数依赖**
  - **函数依赖的定义**：设R(U)是属性集U上的关系模式，X、Y是U的子集。若对于R(U)的任意一个可能的关系r，r中不可能存在两个元组在X上的属性值相等，而在Y上的属性值不等，则称X函数确定Y或Y函数依赖于X，记作X→Y
  - **术语和记号**：
    - X→Y，但Y⊈X，则称X→Y是非平凡的函数依赖
    - X→Y，但Y⊆X，则称X→Y是平凡的函数依赖
    - 若X→Y，则X称为这个函数依赖的决定因素
    - 若X→Y，Y→X，则记作X←→Y
    - 若Y不函数依赖于X，则记作X↛Y
  - **完全函数依赖**：在R(U)中，如果X→Y，并且对于X的任何一个真子集X'，都有X'↛Y，则称Y对X完全函数依赖，记作X→fY
  - **部分函数依赖**：若X→Y，但Y不完全函数依赖于X，则称Y对X部分函数依赖，记作X→pY
  - **传递函数依赖**：在R(U)中，如果X→Y（Y⊈X），Y↛X，Y→Z，Z∉Y，则称Z对X传递函数依赖，记作X→tZ
  - **Armstrong公理系统**：
    - 自反律（Reflexivity）：若Y⊆X⊆U，则X→Y为F所蕴涵
    - 增广律（Augmentation）：若X→Y为F所蕴涵，且Z⊆U，则XZ→YZ为F所蕴涵
    - 传递律（Transitivity）：若X→Y及Y→Z为F所蕴涵，则X→Z为F所蕴涵
  - **推理规则**：
    - 合并规则（Union）：由X→Y，X→Z，有X→YZ
    - 伪传递规则（Pseudotransitivity）：由X→Y，WY→Z，有XW→Z
    - 分解规则（Decomposition）：由X→Y及Z⊆Y，有X→Z
- **范式**
  - **第一范式（1NF）**：关系模式R的所有属性都是不可分的基本数据项
  - **第二范式（2NF）**：关系模式R∈1NF，且每一个非主属性完全函数依赖于任何一个候选码
    - 消除了非主属性对码的部分函数依赖
  - **第三范式（3NF）**：关系模式R∈2NF，且每一个非主属性不传递函数依赖于任何一个候选码
    - 消除了非主属性对码的传递函数依赖
  - **BC范式（BCNF）**：关系模式R∈1NF，若X→Y且Y⊈X时X必含有码，则R∈BCNF
    - 所有非主属性对每一个码都是完全函数依赖
    - 所有主属性对每一个不包含它的码也是完全函数依赖
    - 没有任何属性完全函数依赖于非码的任何一组属性
    - 消除了主属性对码的部分和传递函数依赖
- **模式分解**
  - **模式分解的定义**：关系模式R<U,F>分解为若干个关系模式R1<U1,F1>, R2<U2,F2>, ..., Rn<Un,Fn>，其中U = U1∪U2∪...∪Un，并且没有Ui⊆Uj，Fi是F在Ui上的投影
  - **无损连接分解**：分解后的关系可以通过自然连接恢复原来的关系
    - 判定算法：
      1. 构造一张n行k列的表格
      2. 逐步修改表格
      3. 如果修改后的表格中有一行全是a，则分解是无损连接的
  - **保持函数依赖分解**：分解后的关系模式的函数依赖集的闭包包含原来的函数依赖集的闭包
    - 判定：(F1∪F2∪...∪Fn)+ ⊇ F+
  - **模式分解的目标**：
    - 达到较高的范式
    - 具有无损连接性
    - 保持函数依赖

#### ch9 DataBase Design
- **数据库设计流程**
  - **需求分析阶段**：准确了解与分析用户需求
  - **概念结构设计阶段**：通过对用户需求进行综合、归纳与抽象，形成一个独立于具体DBMS的概念模型
  - **逻辑结构设计阶段**：将概念结构转换为某个DBMS所支持的数据模型，并对其进行优化
  - **物理结构设计阶段**：为逻辑数据模型选取一个最适合应用环境的物理结构（包括存储结构和存取方法）
  - **数据库实施阶段**：设计人员运用DBMS提供的数据语言、工具及宿主语言，根据逻辑设计和物理设计的结果建立数据库，编制与调试应用程序，组织数据入库，并进行试运行

  - **冲突的类型**：

  - **E-R模型向关系模型转换**：

#### ch5-6 事务管理与并发控制
- **事务的基本概念**
  - **事务的定义**：用户定义的一个数据库操作序列，这些操作要么全做，要么全不做，是一个不可分割的工作单位
  - **事务的ACID特性**：
    - **原子性（Atomicity）**：事务是数据库的逻辑工作单位，事务中包括的诸操作要么都做，要么都不做
    - **一致性（Consistency）**：事务执行的结果必须是使数据库从一个一致性状态变到另一个一致性状态
    - **隔离性（Isolation）**：一个事务的执行不能被其他事务干扰，即一个事务内部的操作及使用的数据对其他并发事务是隔离的，并发执行的各个事务之间不能互相干扰
    - **持续性（Durability）**：持续性也称永久性，指一个事务一旦提交，它对数据库中数据的改变就应该是永久性的，接下来的其他操作或故障不应该对其执行结果有任何影响
  - **事务的状态**：
    - 活动状态（Active）
    - 部分提交状态（Partially Committed）
    - 提交状态（Committed）
    - 失败状态（Failed）
    - 中止状态（Aborted）
- **事务控制语句**
  - **BEGIN TRANSACTION**：开始一个事务
  - **COMMIT**：提交事务，将所有修改永久保存
  - **ROLLBACK**：回滚事务，撤销所有未提交的修改
  - **SAVEPOINT**：设置保存点，允许部分回滚
  - **RELEASE SAVEPOINT**：删除保存点
- **并发控制概述**
  - **为什么需要并发控制**：
    - 提高系统资源利用率
    - 减少事务平均响应时间
    - 多用户数据库系统需要同时处理多个事务
  - **并发操作可能带来的问题**：
    - **丢失修改（Lost Update）**：两个事务T1和T2读入同一数据并修改，T2的提交结果覆盖了T1的提交结果，导致T1的修改丢失
    - **不可重复读（Non-repeatable Read）**：事务T1读取数据后，事务T2执行更新操作，使T1无法再现前一次读取结果
    - **幻读（Phantom Read）**：事务T1按一定条件从数据库中读取了某些数据记录后，事务T2插入了一些记录，当T1再次按相同条件读取数据时，发现多了一些记录
- **封锁（Locking）**
  - **基本概念**：封锁就是事务T在对某个数据对象（例如表、记录等）操作之前，先向系统发出请求，对其加锁
  - **基本封锁类型**：
    - **排他锁（Exclusive Lock，X锁）**：若事务T对数据对象A加上X锁，则只允许T读取和修改A，其他任何事务都不能再对A加任何类型的锁，直到T释放A上的锁
    - **共享锁（Shared Lock，S锁）**：若事务T对数据对象A加上S锁，则事务T可以读A但不能修改A，其他事务只能再对A加S锁，而不能加X锁，直到T释放A上的S锁
  - **封锁协议**：
    - **一级封锁协议**：事务T在修改数据R之前必须先对其加X锁，直到事务结束才释放。可防止丢失修改
    - **二级封锁协议**：一级封锁协议加上事务T在读取数据R之前必须先对其加S锁，读完后即可释放S锁。可防止丢失修改和读脏数据
    - **三级封锁协议**：一级封锁协议加上事务T在读取数据R之前必须先对其加S锁，直到事务结束才释放。可防止丢失修改、读脏数据和不可重复读
  - **活锁和死锁**：
    - **活锁（Livelock）**：事务T1封锁了数据R，事务T2又请求封锁R，于是T2等待。T3也请求封锁R，当T1释放了R上的封锁之后系统首先批准了T3的请求，T2仍然等待。然后T4又请求封锁R，当T3释放了R上的封锁之后系统又批准了T4的请求……T2有可能永远等待
      - 解决方法：采用先来先服务的策略
    - **死锁（Deadlock）**：事务T1封锁了数据R1，T2封锁了数据R2，然后T1又请求封锁R2，因T2已封锁了R2，于是T1等待T2释放R2上的锁。接着T2又申请封锁R1，因T1已封锁了R1，T2也只能等待T1释放R1上的锁。这样就出现了T1在等待T2，而T2又在等待T1的局面，T1和T2两个事务永远不能结束
      - 死锁的预防：
        - 一次封锁法：要求每个事务必须一次将所有要使用的数据全部加锁
        - 顺序封锁法：预先对数据对象规定一个封锁顺序，所有事务都按这个顺序实行封锁
      - 死锁的诊断与解除：
        - 超时法：如果一个事务的等待时间超过了规定的时限，就认为发生了死锁
        - 等待图法：事务等待图是一个有向图G=(T,U)，T为结点的集合，每个结点表示正运行的事务；U为边的集合，每条边表示事务等待的情况。如果发现图中存在回路，则表示系统中出现了死锁
        - 死锁的解除：选择一个处理死锁代价最小的事务，将其撤销，释放此事务持有的所有锁，使其他事务能继续运行下去
- **多粒度封锁（Multiple Granularity Locking）**
  - **基本概念**：在一个系统中同时支持多种封锁粒度供不同的事务选择
  - **封锁粒度**：
    - 数据库级
    - 表级
    - 页级
    - 行级
  - **意向锁（Intention Lock）**：
    - **IS锁（意向共享锁）**：如果对一个结点加IS锁，表示它的后裔结点拟（意向）加S锁
    - **IX锁（意向排他锁）**：如果对一个结点加IX锁，表示它的后裔结点拟（意向）加X锁
    - **SIX锁（共享意向排他锁）**：如果对一个结点加SIX锁，表示对它加S锁，再加IX锁
- **基于时间戳的协议（Timestamp-Based Protocols）**
  - **基本概念**：每个事务在进入系统时被赋予一个唯一的时间戳，时间戳决定了事务的串行化顺序
  - **时间戳的实现**：
    - 系统时钟
    - 逻辑计数器
  - **冲突解决**：
    - 若事务T1请求的数据项正在被具有较大时间戳的事务T2以冲突方式持有，则T1等待
    - 否则，T1获得该数据项的锁
- **基于有效性检查的协议（Validation-Based Protocols）**
  - **基本概念**：事务分为三个阶段执行：读阶段、有效性检查阶段、写阶段
  - **三个阶段**：
    1. 读阶段：事务读取数据项并将值存入临时变量
    2. 有效性检查阶段：检查事务是否可以提交而不违反串行化
    3. 写阶段：如果有效性检查成功，将临时变量中的值写入数据库
- **隔离级别（Isolation Levels）**
  - **读未提交（Read Uncommitted）**：一个事务可以读取另一个未提交事务的数据
  - **读已提交（Read Committed）**：一个事务只能读取另一个事务已经提交的数据
  - **可重复读（Repeatable Read）**：确保在同一事务中多次读取同一数据时，其值保持一致
  - **可串行化（Serializable）**：最高的隔离级别，确保事务串行执行
- **数据库恢复技术**
  - **故障的种类**：
    - **事务内部的故障**：事务没有达到预期的终点就夭折了
    - **系统故障**：造成系统停止运转的任何事件，使得系统要重新启动
    - **介质故障**：外存故障，如磁盘损坏
    - **计算机病毒**：一种人为的故障或破坏
  - **恢复的实现技术**：
    - **数据转储（Backup）**：
      - 静态转储：在系统中无运行事务时进行的转储操作
      - 动态转储：转储期间允许对数据库进行存取或修改
      - 海量转储：每次转储全部数据库
      - 增量转储：每次只转储上一次转储后更新过的数据
    - **登记日志文件（Logging）**：
      - 日志文件的格式和内容：
        - 事务开始标记
        - 事务结束标记
        - 每个更新操作
      - 日志文件的作用：
        - 事务故障恢复和系统故障恢复必须用日志文件
        - 在动态转储方式中必须建立日志文件
        - 在静态转储方式中，也可以建立日志文件
      - 登记日志文件的原则：
        - 登记的次序严格按并发事务执行的时间次序
        - 必须先写日志文件，后写数据库
  - **恢复策略**：
    - **事务故障的恢复**：
      - 反向扫描日志文件，查找该事务的更新操作
      - 对该事务的更新操作执行逆操作
      - 继续反向扫描日志文件，查找该事务的其他更新操作
      - 如此处理下去，直至读到该事务的开始标记
    - **系统故障的恢复**：
      - 正向扫描日志文件，找出在故障发生前已经提交的事务
      - 对撤销队列中的各个事务进行撤销处理
      - 对重做队列中的各个事务进行重做处理
    - **介质故障的恢复**：
      - 装入最新的数据库后备副本
      - 装入相应的日志文件副本，重做已完成的事务
  - **检查点技术（Checkpoint）**：
    - 基本思想：在日志文件中增加检查点记录，增加重新开始文件
    - 检查点记录的内容：
      - 建立检查点时刻所有正在执行的事务清单
      - 这些事务最近一个日志记录的地址
    - 使用检查点的恢复步骤：
      1. 从重新开始文件中找到最后一个检查点记录在日志文件中的地址
      2. 由该检查点记录得到检查点建立时刻所有正在执行的事务清单
      3. 建立两个事务队列：UNDO-LIST和REDO-LIST
      4. 对UNDO-LIST中的事务执行UNDO操作
      5. 对REDO-LIST中的事务执行REDO操作

#### ch10 DataBase Index
- **索引基本概念**
  - 索引是对数据库表中一列或多列的值进行排序的一种结构
  - 作用：
    - 加快数据的查询速度
    - 保证数据记录的唯一性
    - 实现表与表之间的参照完整性
    - 在使用ORDER BY和GROUP BY子句进行数据检索时，可以显著减少查询中分组和排序的时间
  - 索引的代价：
    - 创建索引和维护索引要耗费时间
    - 索引需要占用物理空间
    - 当对表中的数据进行增加、删除和修改的时候，索引也要动态的维护
- **索引类型**
  - **聚簇索引（Clustered Index）**：
    - 索引项的顺序与表中记录的物理顺序一致
    - 一个表只能有一个聚簇索引
    - 数据行的物理顺序与列值（一般是主键的那一列）的逻辑顺序相同
  - **非聚簇索引（Non-clustered Index）**：
    - 索引项的顺序与表中记录的物理顺序不一致
    - 一个表可以有多个非聚簇索引
    - 数据行的物理顺序与列值的逻辑顺序不同
  - **唯一索引（Unique Index）**：
    - 索引列的所有值都只能出现一次
    - 可以保证数据的唯一性
  - **复合索引（Composite Index）**：
    - 基于多个列创建的索引
    - 查询时遵循最左前缀原则
  - **全文索引（Full-text Index）**：
    - 用于全文搜索
    - 支持复杂的文本查询
- **B+树索引原理**
  - **B+树的结构**：
    - 所有叶子节点都在同一层
    - 叶子节点包含所有关键字值
    - 叶子节点之间用链表相连
    - 非叶子节点只包含索引项，不包含数据
  - **B+树的优点**：
    - 平衡树，查询效率稳定
    - 范围查询效率高
    - 全表扫描效率高
  - **B+树的操作**：
    - 查找
    - 插入
    - 删除
- **索引设计原则**
  - 选择唯一性索引
  - 为经常需要排序、分组和联合操作的字段建立索引
  - 为常作为查询条件的字段建立索引
  - 限制索引的数目
  - 尽量使用数据量少的索引
  - 尽量使用前缀来索引
  - 删除不再使用或者很少使用的索引
  - 考虑索引的更新代价
- **索引优化策略**
  - **查询优化**：
    - 避免在索引列上使用函数
    - 避免使用NOT IN和<>
    - 使用覆盖索引
    - 利用最左前缀原则
  - **索引维护**：
    - 定期分析索引的使用情况
    - 删除未使用的索引
    - 重建碎片较多的索引
    - 更新统计信息
- **索引使用场景**
  - 适合建立索引的场景：
    - 主键自动建立唯一索引
    - 频繁作为查询条件的字段
    - 查询中与其他表关联的字段
    - 查询中排序的字段
    - 查询中统计或分组的字段
  - 不适合建立索引的场景：
    - 频繁更新的字段
    - 表记录太少
    - 数据重复且分布平均的字段
    - 经常增删改的表

## 四、常见问题与解决方案

- **问题**：数据不一致
  **解决**：使用事务，确保ACID特性，合理设计外键约束，使用乐观锁或悲观锁

## 六、速记宝典（口诀 + 对比表 + SQL速查）

### 6.1 数据库系统三级模式速记

**口诀**：「**外看局部，模管全局，内存物理**」

| 模式 | 别名 | 含义 | 数量 | 速记 |
|------|------|------|:--:|------|
| 外模式 | 子模式/用户模式 | 用户看到的部分数据视图 | 多个 | **"每个人的视角"** |
| 模式 | 逻辑模式 | 全体数据的逻辑结构 | 1个 | **"全局蓝图"** |
| 内模式 | 存储模式 | 数据物理存储方式 | 1个 | **"硬盘怎么存"** |

**两级映像**：
- 外模式/模式映像 → **逻辑独立性**（模式变了，改映像即可）
- 模式/内模式映像 → **物理独立性**（存储变了，改映像即可）

### 6.2 关系代数运算速记

**传统集合运算**：「**并交差笛**」= ∪ ∩ - ×
- 并(∪)：两表所有行（去重）
- 交(∩)：两表共有行
- 差(-)：在表A不在表B的行
- 笛卡尔积(×)：两表所有行的排列组合

**专门关系运算**：「**选投连除**」= σ π ⋈ ÷

| 运算 | 符号 | 含义 | 记忆 |
|------|:--:|------|------|
| 选择 | σ | 选行（按条件过滤） | **σ**elect rows |
| 投影 | π | 选列 | **π**ick columns |
| 连接 | ⋈ | 两表按条件拼起来 | join |
| 除 | ÷ | "满足所有条件的..." | 最难，考得少 |

**连接的类型**：
| 类型 | 含义 | SQL写法 |
|------|------|--------|
| θ连接 | 按任意条件连接 | `FROM A JOIN B ON 条件` |
| 等值连接 | θ为=的连接 | `FROM A JOIN B ON A.x=B.x` |
| 自然连接 | 同名属性等值+去重列 | `NATURAL JOIN` |
| 外连接 | 保留不匹配的行 | `LEFT/RIGHT/FULL OUTER JOIN` |

### 6.3 SQL四大语句速记

**口诀**：「**增删改查**」= INSERT DELETE UPDATE SELECT

**SELECT查询结构**：
```sql
SELECT   列名          -- 选什么列（投影）
FROM     表名          -- 从哪张表
WHERE    条件          -- 筛选行（选择）
GROUP BY 分组列        -- 分组
HAVING   分组条件      -- 分组后筛选
ORDER BY 排序列 ASC/DESC -- 排序
```

**执行顺序**（非常重要！）：`FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY`
- 记忆：**"从哪来，筛什么，怎么分，分后筛，选什么，怎么排"**

**聚合函数**：「**COUNT数个数，SUM求和，AVG平均，MAX最大，MIN最小**」

**WHERE vs HAVING**：
| | WHERE | HAVING |
|---|-------|--------|
| 时机 | 分组前筛选 | 分组后筛选 |
| 条件 | 不能用聚合函数 | 能用聚合函数 |
| 记忆 | **"先筛后分"** | **"分完再筛"** |

### 6.4 ER模型速记

**ER图三要素**：
| 元素 | 图形 | 含义 | 记忆 |
|------|:--:|------|------|
| 实体 | 矩形 | 要存的对象（人、物、概念） | **实=实实在在** |
| 属性 | 椭圆 | 实体的特征 | **属=属于谁** |
| 联系 | 菱形 | 实体之间的关系 | **联=关联** |

**联系的三种基数比**：
- **1:1**：一个A对应一个B（如：班级-班长）
- **1:N**：一个A对应多个B（如：班级-学生）
- **M:N**：多个A对应多个B（如：学生-课程）
- 记忆：**"一对一写一起，一对多外键放多方，多对多建中间表"**

### 6.5 规范化理论速记

**口诀**：「**1NF原子不可分，2NF完全依赖主，3NF不依赖非主，BCNF决定必主**」

| 范式 | 核心要求 | 反例 | 速记 |
|:--:|------|------|------|
| 1NF | 列不可再分（原子性） | 一列存多个值 | **"每个格子只放一个值"** |
| 2NF | 满足1NF + 非主属性完全依赖主码 | 部分依赖（依赖主码的一部分） | **"不能只依赖主码的一半"** |
| 3NF | 满足2NF + 非主属性不传递依赖主码 | 传递依赖（A→B, B→C） | **"不能拐弯依赖"** |
| BCNF | 满足3NF + 决定因素必含码 | 主属性部分依赖码 | **"谁决定谁就是码"** |

**函数依赖速记**：
- 完全依赖：学号→姓名（学号确定，姓名唯一确定）
- 部分依赖：(学号,课程号)→姓名（其实学号就够了，课程号多余）
- 传递依赖：学号→班级，班级→辅导员 → 学号→辅导员（拐了一个弯）

### 6.6 事务ACID特性速记

**口诀**：「**一原二一三隔四久**」

| 特性 | 含义 | 记忆 |
|------|------|------|
| **A**tomicity（原子性） | 要么全做，要么全不做 | **"不可分割"** |
| **C**onsistency（一致性） | 事务前后数据一致 | **"规则不破"** |
| **I**solation（隔离性） | 并发事务互不干扰 | **"各行其是"** |
| **D**urability（持久性） | 提交后永久保存 | **"永不失忆"** |

**并发问题**：「**脏不重幻**」
- 脏读：读到别人未提交的数据
- 不可重复读：同一事务两次读到不同值（别人改了）
- 幻读：同一事务两次读到不同行数（别人插了/删了）

**隔离级别**（低→高）：「**读未提 → 读已提 → 可重复 → 可串行**」
- 级别越高越安全，但性能越低

### 6.7 索引速记

**索引类型**：
| 类型 | 特点 | 适用场景 |
|------|------|---------|
| B+树索引 | 数据有序，范围查询快 | 大部分场景（默认） |
| Hash索引 | 等值查询极快，不支持范围 | 等值查询 |
| 聚簇索引 | 数据物理按索引顺序存储 | 主键（一张表只能一个） |
| 非聚簇索引 | 索引和数据分开存储 | 辅助索引（可以有多个） |

**口诀**：「**聚簇定存储，非聚指位置**」

### 6.9 高频易错点

1. **WHERE不能用聚合函数**（COUNT/SUM等），HAVING才能用
2. **SQL执行顺序**：FROM→WHERE→GROUP→HAVING→SELECT→ORDER，和书写顺序不同！
3. **自然连接自动去重同名列**，等值连接不去重
4. **2NF消除部分依赖，3NF消除传递依赖**，别搞反
5. **聚簇索引一张表只能有一个**（数据只能按一种顺序存）
6. **DELETE删行可回滚，TRUNCATE清表不可回滚，DROP删表不可回滚**
