## 事务管理

**ACID特性：**
| 特性 | 含义 | 实现机制 |
|------|------|----------|
| 原子性 | 要么全做，要么全不做 | undo日志 |
| 一致性 | 事务前后数据一致 | 应用层保证 |
| 隔离性 | 并发事务互不干扰 | 锁/MVCC |
| 持久性 | 提交后永久保存 | redo日志 |

## 并发控制

**隔离级别：**

| 隔离级别 | 脏读 | 不可重复读 | 幻读 |
|----------|------|------------|------|
| READ UNCOMMITTED | ✅ | ✅ | ✅ |
| READ COMMITTED | ❌ | ✅ | ✅ |
| REPEATABLE READ | ❌ | ❌ | ✅ |
| SERIALIZABLE | ❌ | ❌ | ❌ |

**锁类型：**

| 锁 | 说明 |
|------|------|
| 共享锁(S) | 读锁，可并发读 |
| 排他锁(X) | 写锁，独占 |
| 意向锁(IS/IX) | 表级锁，表示事务想加行级S/X锁 |
| 行锁 | 粒度最小，并发最高 |
| 表锁 | 粒度最大，并发最低 |

**死锁处理：**
- 预防：一次封锁法、顺序封锁法
- 检测：等待图（有环=有死锁）
- 解除：选择牺牲者，回滚事务

## MVCC（多版本并发控制）

| 知识点 | 核心 |
|--------|------|
| 原理 | 每行记录维护多个版本，读不加锁 |
| 实现 | undo日志 + ReadView |
| 读操作 | 根据ReadView判断版本可见性 |
| 写操作 | 创建新版本，旧版本保留在undo日志 |

---

## 日志系统

| 日志类型 | 作用 |
|----------|------|
| undo日志 | 撤销未提交事务，保证原子性 |
| redo日志 | 重做已提交事务，保证持久性 |
| checkpoint | 将脏页写入磁盘，缩短恢复时间 |

**两阶段提交：**
- prepare阶段：将redo日志写入磁盘
- commit阶段：将undo日志写入磁盘，释放锁

## 性能优化

| 优化层面 | 方法 |
|----------|------|
| 索引优化 | 合理建索引、避免全表扫描 |
| 查询优化 | EXPLAIN分析、避免SELECT *、子查询改JOIN |
| 表设计 | 范式化vs反范式化、字段类型选择 |
| 架构优化 | 读写分离、分库分表、缓存 |

**EXPLAIN关键字段：**
| 字段 | 说明 |
|------|------|
| type | 访问类型：const>eq_ref>ref>range>index>ALL |
| key | 实际使用的索引 |
| rows | 预估扫描行数 |
| Extra | Using index(覆盖索引)、Using filesort(文件排序) |

## 分布式数据库

| 知识点 | 核心 |
|--------|------|
| CAP定理 | 一致性(C)、可用性(A)、分区容错(P)，三者最多满足两个 |
| BASE理论 | 基本可用、软状态、最终一致性 |
| 分片 | 水平分片(按行)、垂直分片(按列) |
| 一致性协议 | Raft、Paxos |

---

**使用建议**：事务隔离级别和MVCC是面试和考试重点，CAP定理是分布式系统核心概念。
