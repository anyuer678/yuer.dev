## 背景

PolyCodeHub 是一个全栈在线判题（OJ）平台，2025 年 9 月写出雏形，2026 年 8 月迁移到独立仓库继续迭代。早期所有逻辑堆在一个服务里，扩展多语言判题后明显吃力——判题是 CPU 密集且要隔离的，认证和 API 又是另一类需求。

## 发生了什么

第一次重构把系统拆成四个角色：

- **Next.js 前端**：题库、提交、比赛、社区
- **Node.js + Express API 网关**：统一入口，转发请求
- **Java 21 + Spring Boot 认证服务**：登录、JWT、鉴权
- **Python 3.12 + FastAPI 判题服务**：进程级沙箱评测

数据层用 PostgreSQL 16 存题库/用户/提交，Redis 7 做排行榜与限流，RabbitMQ 承载判题任务的异步链路——提交后立即返回，判题排队执行，网关不阻塞。

判题沙箱是核心：非容器方案，`setuid` 降权到专用 sandbox 用户、清空补充组，seccomp 拦截网络 socket（禁止 `AF_INET`/`AF_INET6`/`AF_NETLINK`），再叠加虚拟内存 / CPU / 文件大小 / 进程数 / 文件描述符限制，防止提交代码触达内网或滥用资源。

## 结论

把"入口"（网关）、"身份"（认证）、"执行"（判题沙箱）拆开之后，各自可以独立伸缩和加固。沙箱只信任提交的输入并执行，网关不碰执行细节，认证不依赖判题状态。异步链路让判题服务可以水平扩展而不拖垮 API。
