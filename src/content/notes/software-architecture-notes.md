## 软件架构是什么

软件架构是系统的高层次结构，描述系统组成部分、它们之间的关系以及与环境的关系。它是**早期设计决策**，直接影响性能、安全、可维护性等质量属性，也是项目干系人之间的**沟通基础**和可重用的设计知识。

演进历史：60-70 年代无架构（只关注算法）→ 80 年代结构化设计（自顶向下分解）→ 90 年代面向对象（OOAD + 设计模式）→ 2000 年代后架构独立成学科（微服务、云原生）。

## 质量属性（非功能需求）

架构设计的主要目标是满足质量属性，常见的有：

| 属性 | 含义 |
|---|---|
| 性能 | 响应时间、吞吐量、资源利用率 |
| 可修改性 | 可维护、可扩展、可重用、可移植 |
| 可用性 | 正常运行时间/总时间，用「9」衡量：99.9% ≈ 每年停 8.76h、99.99% ≈ 52min、99.999% ≈ 5min |
| 安全性 | 机密性、完整性、认证、授权、不可否认 |
| 易用性 | 学习难度、操作效率、出错率、满意度 |
| 可测试性 | 可观察、可控制、可诊断 |
| 其他 | 可靠性、健壮性、互操作性、合规性 |

提高可用性靠冗余、容错、故障检测与恢复。

## 架构设计原则

**SOLID**：

- **S** 单一职责：一个类只有一个改变的理由
- **O** 开闭：对扩展开放、对修改关闭
- **L** 里氏替换：子类应能替换父类且不改变行为
- **I** 接口隔离：接口小而专一，不强迫依赖用不到的接口
- **D** 依赖倒置：高层与低层都依赖抽象，细节依赖抽象

加上**高内聚低耦合**（模块只做一件事、模块间依赖松散）、**信息隐藏**（内部实现细节不外露，只通过接口交互）、**DRY**（不重复自己，每个知识只在一处表达）。

## 常见架构风格

1. **分层架构（N 层）**：表现层→业务层→持久层→数据层，每层只依赖下层。传统企业应用；简单易懂易测试，但可能有「污水池反模式」（逻辑都堆在中间层）、性能开销、扩展性有限
2. **客户端-服务器**：客户端请求、服务器服务，职责分离、数据集中管理；服务器是单点故障和瓶颈
3. **主从（Master-Slave）**：主节点协调、从节点执行，如数据库主从复制；提高性能但主节点仍是关键点
4. **管道-过滤器**：过滤器处理数据、管道传递数据，如 Unix shell 管道、编译器；简单可重用可并行，但数据转换有开销、不适合交互应用
5. **事件驱动（EDA）**：生产者/消费者通过事件通道通信，如 GUI、消息队列；松耦合可扩展异步，但调试难、事件顺序难保证
6. **微内核（插件架构）**：核心系统 + 插件扩展，如 Eclipse、VS Code、浏览器；灵活可定制，但设计复杂
7. **微服务**：拆成多个独立部署的小服务，各自数据库、API 通信，如 Netflix；独立部署扩展、技术栈灵活、容错好，但分布式复杂度、运维成本、数据一致性都是代价
8. **云原生**：微服务 + 容器化（Docker）+ 编排（K8s）+ CI/CD + 弹性伸缩，为云设计
9. **DDD 领域驱动**：以领域为核心，限界上下文、聚合、实体、值对象、领域服务、领域事件；业务清晰、模型与实现一致

**选型考虑**：需求（功能 + 非功能）、团队经验、技术栈、时间、成本、演进。**没有最好的架构风格，只有最适合的**。

## 框架与库

- **库**：被程序调用，控制权在程序手里
- **框架**：调用程序（控制反转 IoC），提供骨架与约定，程序按框架规则填充
- 常见 Java 框架：SSH（Struts+Spring+Hibernate）、SSM（Spring+Spring MVC+MyBatis）、Spring Boot（简化配置）

## 一句话总结

架构 = 早期决策 + 质量属性权衡；SOLID 管类设计，架构风格管系统级组织；风格没有绝对优劣，按需求场景选。
