## 项目介绍

《智慧医养大数据公共服务平台医生服务系统》是面向参与医养结合工作的医生用户的子系统，8 人团队开发，目标是让老年人健康管理数字化：档案、预警、随访、评估、转诊一条线。整个项目按软件工程规范走完需求分析 → 概要设计 → 详细设计 → 开发 → 测试的全流程，文档齐全。

## 技术栈

- 后端：Spring Boot + Spring MVC + MyBatis-Plus + MySQL + Redis
- 认证：JWT 拦截器 + 图形验证码（Redis 存储）
- 横切：Spring AOP 自定义 `@OperationLog` 注解做操作日志
- 前端：原生 HTML/CSS/JS（静态资源随 Spring Boot 打包），无框架
- 统一响应封装 R（泛型 T）+ 全局异常处理，17 个 Controller

## 功能模块

| 模块 | 内容 |
|---|---|
| 登录认证 | 账号密码 + 验证码、记住密码、密码找回、RBAC 权限、登录日志 |
| 老人健康档案 | 基本信息、既往病史、用药、体检、过敏史、家族史、生活习惯，支持导出/打印 |
| 健康预警 | 预警规则配置，基于健康数据异常指标智能预警 |
| 随访管理 | 重点人群定期随访，随访历史记录、列表/详情弹窗 |
| 干预管理 | 干预记录查看与编辑（补全 5 个查看字段） |
| 健康评估 | 评估 + 报告生成 |
| 转诊协同 | 前后端角色校验 + 状态机 + 取消原因字段，6 步分工方案 |
| 服务时间线 | 老人的服务全程记录 |

## 开发标准与踩坑

团队定了三条铁律：只修明显 Bug 不做性能优化、每次修改聚焦一个功能、最小化整体工作量。修改走 4 步流程：改前查修改记录、改中同步 target/classes + 带版本号、改后写修改记录、验证（后端 curl + token / 前端 F12）。

记录在案的 18 个问题里，印象深的有：

- **start.bat 双击闪退**：环境自检 + pause + 独立窗口解决
- **验证码无法加载**：是环境问题不是代码——Redis 没启动
- **MySQL 连接失败**：application.yml 密码写错，改成实际密码
- **浏览器缓存旧 JS**：HTML 里 script 标签加 `?v=版本号`
- **转诊列表 500 错误**：数据库补 `cancel_reason` 列
- **target/classes 没同步**：Spring Boot 静态资源改完要手动 Copy-Item 同步，容易漏

## 我的收获

- 完整的团队协作流程：需求文档 → 设计文档 → 代码 → 修改记录，改 Bug 前先查记录避免重复
- 前后端联调时"复现问题"比"猜问题"有用，F12 Network + Console 是最快的定位手段
- 版本号防缓存、启动脚本自检这类小细节，平时自己写 demo 根本不会注意，但真实项目里特别重要
