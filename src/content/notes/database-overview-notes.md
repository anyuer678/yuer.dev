## 数据库与 DBMS

**数据库（DB）**：长期存储在计算机内、有组织、可共享的大量数据的集合。四个特点：永久存储、有组织、可共享、数据量大。

**数据库管理系统（DBMS）**：位于用户和操作系统之间的数据管理软件，是数据库系统的核心。主要功能：

1. 数据定义（DDL）：CREATE TABLE / CREATE INDEX
2. 数据操作（DML）：SELECT / INSERT / UPDATE / DELETE
3. 数据库运行管理：事务管理、并发控制、恢复
4. 数据库的建立与维护：备份、恢复、重组

数据库系统（DBS）= 数据库 + DBMS + 应用程序 + 数据库管理员 + 用户。

## 数据管理三阶段

| 阶段 | 数据共享 | 独立性 | 特点 |
|---|---|---|---|
| 人工管理 | 无 | 无 | 程序自带数据，不保存 |
| 文件系统 | 低 | 差 | 数据与程序分离但共享差，冗余多 |
| 数据库系统 | 高 | 高 | 结构化、共享性高、独立性高 |

## 数据模型的三层

- **概念模型**：面向用户，E-R 模型（实体-联系）
- **逻辑模型**：面向机器实现，最常用的是**关系模型**（二维表）
- **物理模型**：数据在存储介质上的组织方式（索引、聚簇、哈希）

建模过程：现实世界 → 概念模型（E-R）→ 逻辑模型（关系）→ 物理模型。

## 关系模型的基本概念

| 术语 | 含义 |
|---|---|
| 关系 | 一张二维表 |
| 元组 | 表中的一行 |
| 属性 | 表中的一列 |
| 码（Key） | 唯一标识元组的属性或属性组 |
| 候选码 | 可以作为码的属性组（可能多个） |
| 主码 | 从候选码中选中的一个 |
| 外码 | 另一个关系的主码 |
| 域 | 属性的取值范围 |
| 分量 | 元组中的一个属性值 |
| 关系模式 | 对关系的描述：关系名(属性1, 属性2, ...) |

**关系模型的优点**：建立在严格数学概念上、概念单一（实体和联系都用关系表示）、存取路径对用户透明、数据独立性高、理论基础坚实。**缺点**：查询效率不如非关系模型，需要查询优化。

## 三类完整性约束

1. **实体完整性**：主码不能为空
2. **参照完整性**：外码必须是主码的有效值或空
3. **用户定义完整性**：用户自定义约束（如年龄 > 0、性别只能是男/女）

这是关系模型的核心规则，违反会报错。SELECT / INSERT / DELETE / UPDATE 四类操作都受约束检查。

## 数据库系统组成

**DBA（数据库管理员）职责**：决定信息内容和结构、决定存储结构与存取策略、定义安全性要求和完整性约束、监控运行、改进重组、备份恢复。

**用户分类**：最终用户（通过应用使用，不写 SQL）、应用程序员（写应用 + SQL）、DBA（管理与维护）、系统分析员和数据库设计人员（需求分析与数据库设计）。

## 关系模型的数学基础

关系是**笛卡尔积的有限子集**。基本关系代数操作（五大）：选择 σ、投影 π、并 ∪、差 −、笛卡尔积 ×。附加操作：交 ∩、自然连接 ⋈、除 ÷。这些是 SQL 的理论基础。
