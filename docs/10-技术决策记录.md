# 10 技术决策记录（ADR）

> 记录关键决策与备选方案，回答未来的自己"当时为什么这么选"。
> 新增决策必须追加本文档；推翻旧决策时，先写新 ADR 再改代码。

## ADR-001 框架：Vue 3 + Vite（2026-08）

- **背景**：需要内容驱动的静态作品集，未来有 AI 集成、GitHub 同步诉求。
- **备选**：Astro（内容站更自然，岛屿架构）；纯 HTML/CSS/JS（零依赖）。
- **决策**：Vue 3 + Vite。
- **理由**：生态成熟、上手快；`import.meta.glob` 原生支持内容管线；后续 AI 增强（v2.5）在 Vue 生态内集成顺畅；不引学习成本。
- **代价**：SEO 需要额外预渲染（v1.5 引入 vite-ssg）；Astro 路径被推迟到 v2 再评估。

## ADR-002 样式：原生 CSS + 设计令牌，不引 UI 库（2026-08）

- **背景**：视觉要求"浅色纸张感"，需要强辨识度。
- **备选**：Tailwind（原子化快但易导致千站一面）；Element Plus / shadcn（组件库脸）。
- **决策**：CSS 变量令牌 + 原生 CSS，组件级 scoped。
- **理由**：设计完全可控；全站样式总量小（约 3 个 css 文件 + 组件 scoped），无框架学习成本；性能最优。
- **代价**：手写组件样式（本项目组件有限，成本可接受）。

## ADR-003 内容管线：构建期 glob 打包，非运行时请求（2026-08）

- **背景**：内容要"零代码新增"；同时无后端。
- **备选**：运行时 fetch GitHub raw（慢、依赖网络）；引入 CMS 后端（违背静态原则）。
- **决策**：`import.meta.glob` + `eager`，构建期全部打包进 bundle。
- **理由**：纯静态、无网络依赖、内容即文件。
- **代价**：内容变更需重新构建部署（静态站常态，可接受）。
- **预留**：管线对象保留 `raw` 字段，v2.5 AI 直接复用，无需改造数据源。

## ADR-004 Markdown 渲染：markdown-it + highlight.js，v1 前端渲染（2026-08）

- **备选**：vite-plugin-md（把 md 变组件，构建期渲染）；vitepress（重框架）；shiki（体积大）。
- **决策**：markdown-it + highlight.js/common（按需语言）。
- **理由**：体积小、样式可控；v1 的 SEO 短板由 v1.5 的 vite-ssg 解决，不提前复杂化。
- **代价**：SEO 弱（已列入 v1 已知风险）。

## ADR-005 状态枚举：四值制 development/completed/archived/experiment（2026-08）

- **背景**：项目与 Lab 需要状态表达；太多状态会稀释语义。
- **决策**：统一四值枚举；Lab 不使用 development（实验即其常态）。
- **理由**：覆盖"进行中/完成/不再维护/试验性"全部现实场景；枚举校验简单。
- **偏离许可**：若未来出现"暂停维护"类状态，先扩展本文档与 `04-内容层` §3 的枚举，再改代码。

## ADR-006 过滤逻辑：技术栈多选为 OR，状态单选（2026-08）

- **备选**：AND（多选交集）；全单选。
- **决策**：状态单选、技术多选且 OR（任一命中即显示）。
- **理由**：OR 符合"找相关项目"的浏览直觉（含某技术即算命中）；状态互斥天然单选。
- **代价**：无法表达"同时用了 A 和 B"的精确查询（v1 不提供，注明即可）。

## ADR-007 深链方案：404.html 兜底，不用 hash 路由（2026-08）

- **备选**：hash 路由（`/#/projects/xxx`，URL 丑、不利于分享）；v1 即 SSG 预渲染（工程量大）。
- **决策**：history 路由 + `public/404.html` 兜底。
- **理由**：URL 干净、分享体验好；404 兜底实现成本约 1 个构建脚本。
- **代价**：网络层返回 404 状态码（内容正常渲染；SEO 由 v1.5 预渲染解决）。

## ADR-008 slug 不可变（2026-08）

- **背景**：内容 URL 的稳定性决定外链与分享价值。
- **决策**：slug 一经发布不可变；修改视为新内容。
- **理由**：避免 404 蔓延；简单可执行。
- **偏离许可**：重大品牌调整时走重定向表（`02-信息架构` §7），仍保留旧 slug 跳转。

## ADR-009 视觉方向：暖白纸张感 + 陶土橙强调（2026-08）

- **背景**：目标读者是面试官与同行，需要"可信、克制、有设计感"的记忆点。
- **备选**：科技蓝渐变 + 玻璃拟态（辨识度低、廉价感）；暗色终端风（阅读负担、与"成长档案"调性不符）。
- **决策**：浅色纸张感、细线、克制动效。
- **理由**：差异化强（技术圈大量暗色科技风）；正文阅读舒适；与"数字花园"定位契合。

## ADR-010 邮箱防爬：字符实体编码（2026-08）

- **背景**：Contact 页邮箱直接暴露会被爬虫抓取。
- **决策**：HTML 中邮箱用实体编码（`&#64;`），渲染后再组合 `mailto:`。
- **备选**：JS 动态拼接（增加首屏 JS）；第三方表单服务（超出 v1 范围）。
- **代价**：轻微实现成本；防爬不绝对（够用即可）。

## ADR-011 动效总量控制：全站仅 6 处动效（2026-08）

- **背景**：动效是双刃剑，过量会显得"廉价"。
- **决策**：清单制（`03-设计系统` §7.2），新增动效需先列入清单。
- **理由**：克制本身是设计语言的一部分；性能预算友好。

## ADR-012 版本化升级：每版先写规格增量再动代码（2026-08）

- **背景**：v1.5/v2.0/v2.5/v3.0 各有较大改动面。
- **决策**：任何版本升级，先在本文档与对应规范文档追加"增量规格"，评审后再实施。
- **理由**：文档是本项目的核心资产（成长档案定位），代码是衍生品。

## ADR-013 内容管线：meta-only 设计 + 手写 frontmatter 解析器（2026-08）

- **背景**：markdown-it + highlight.js 若随管线 eager 打包进主 bundle（约 60–80KB gzip），首屏 JS 超预算；gray-matter/js-yaml 额外占约 15KB。
- **备选**：eager 全量渲染（简单但首屏超预算）；gray-matter 继续使用（标准但重）。
- **决策**：
  1. `utils/content.js` 只解析 frontmatter 导出 meta；正文原文非 eager glob，与 `utils/markdown.js` 一起被详情页动态 import（Vite 自动拆共享 chunk）
  2. 手写约 50 行 frontmatter 解析器，仅支持受控子集（单行标量/简单数组），越界内容由校验脚本规则 14 拦截
- **理由**：首屏预算达标；错误只在开发期出现（构建失败而非运行时异常）；受控 schema 使自研解析器安全。
- **代价**：新增一条校验规则；解析器需回写 `09-参考实现` §4.1；未来若 schema 复杂化（如嵌套对象）再引入成熟库。

## ADR-014 过滤状态：URL query 为唯一事实来源（2026-08）

- **背景**：列表过滤需要"刷新/分享后状态保持"，且组件间不共享 state。
- **备选**：组件内 ref 状态 + watch 同步 URL（双份状态易漂移）；pinia 全局状态（过度设计）。
- **决策**：不持有过滤 state；一律从 `route.query` 派生，变更走 `router.replace`。
- **理由**：单一事实来源，刷新/分享天然一致；零状态管理依赖。
- **代价**：每次过滤触发一次路由更新（history replace，不产生历史记录，可接受）；列表滚动位置不保留（已定）——切页回顶。
