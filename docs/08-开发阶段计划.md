# 08 开发阶段计划

> 实施路线：阶段划分、每阶段任务与验收标准、全局完成定义、风险与版本路线图。

## 1. 总体策略

1. **设计先行**：P0/P1 定稿视觉（tokens.css + 首页锚点），之后只做增量，避免返工
2. **先骨架后内容**：路由 + 布局壳一次到位，页面先填空，再逐页实现
3. **内容驱动验证**：P3 先放 2 个示例项目验证内容管线，管线通了再批量填充
4. **最后打磨**：动效、响应式、SEO、部署统一收尾
5. **全程守规范**：每个阶段验收对照 `01-需求规格` 的 F 编号与本文档"完成定义"

## 3. 全局完成定义（DoD，每阶段提交前逐条打勾）

- [ ] 桌面 + 移动端无布局问题、无横向滚动
- [ ] 数据来自 content 层，页面无硬编码业务文案
- [ ] 动效克制且尊重 `prefers-reduced-motion`
- [ ] `npm run validate` / `npm run lint` 零错误
- [ ] `npm run build` 通过，`npm run preview` 抽查关键路由
- [ ] 页面 title/description 正确设置
- [ ] 新增内容（项目/笔记/时间线/Lab）零代码改动可完成

## 4. 风险与对策

| 风险 | 等级 | 对策 |
| --- | --- | --- |
| 内容空洞、项目信息不足 | 高 | 模板 + 示例引导（`04-内容层` §11/§12）；宁少勿滥，首发 4 项目即可 |
| SPA SEO 弱 | 中 | v1 接受；v1.5 引 vite-ssg 预渲染 + sitemap |
| 过度设计拖慢进度 | 中 | 视觉 P0 定稿；之后样式改动走 `03-设计系统` 评审 |
| 内容与代码耦合回潮 | 中 | 校验脚本 + review 检查 content/ 外禁止文案 |
| slug 发布后失效 | 低 | slug 不可变约定 + 保留字校验 |
| GitHub Pages 深链 404 | 中 | `public/404.html` 兜底 + 发布后 curl 验证（`02-信息架构` §6） |
| 依赖膨胀（被组件库吸引） | 低 | 依赖策略（`07-工程规范` §10），新增依赖需评审 |

## 5. 版本路线图（详细）

| 版本 | 范围 | 关键改动 |
| --- | --- | --- |
| v1.0 | 静态作品集 | 本文档全部内容 |
| v1.1 | 打磨期 | 重定向表、锚点 TOC、封面图支持 |
| v1.5 | Markdown CMS | vite-ssg 预渲染（SEO）、sitemap.xml、minisearch 站内搜索、内容校验升级 |
| v2.0 | GitHub 同步 | 定时构建拉取 commit/star/release；项目页展示动态数据 |
| v2.5 | AI 增强 | 基于本站内容（预构建 embeddings 或 serverless 函数）的问答入口 |
| v3.0 | 知识系统 | 笔记双向链接、项目-笔记自动关联、个人知识图谱 |

每跳一个版本：先写该版本的规格增量（追加本套文档），再动代码。
