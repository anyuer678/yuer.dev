## 1. 架构总览

### 1.1 分层模型

```
┌────────────────────────────────────────────────────┐
│ P0 展示层      pages/（10 个路由页面）               │
├────────────────────────────────────────────────────┤
│ P1 业务组件层  components/features/（页面专属组件）    │
├────────────────────────────────────────────────────┤
│ P2 基础组件层  components/ui/ + components/layout/   │
├────────────────────────────────────────────────────┤
│ P3 应用服务层  composables/（动画、复用逻辑）          │
│                router/（路由、meta、SEO 副作用）       │
├────────────────────────────────────────────────────┤
│ P4 数据层      utils/content.js（静态导出）            │
│                utils/markdown.js（动态渲染，独立 chunk）│
├────────────────────────────────────────────────────┤
│ P5 内容资产层  src/content/*（Markdown / JSON）        │
├────────────────────────────────────────────────────┤
│ P6 工程层      scripts/（校验、404 复制）、CI/CD        │
└────────────────────────────────────────────────────┘
```

**依赖只能自上而下**，禁止反向依赖与跨层跳级（组件禁止直接读 content 文件，必须走 P4）。

### 1.2 三条核心设计决策（详细论证见第 5 节与 ADR）

| 决策 | 一句话 |
| --- | --- |
| D1 meta-only 管线 | 主 bundle 只解析 frontmatter（meta），Markdown 渲染整体移入详情页懒加载 chunk |
| D2 URL 即状态 | 列表过滤状态的唯一事实来源是 `route.query`，组件不持有过滤 state |
| D3 零运行时数据 | 一切内容构建期打包；浏览器全程零 fetch、零后端 |

### 1.3 全局数据流（一图）

```
[构建期]
*.md / *.json ─→ import.meta.glob(?raw, eager)
                    │
                    ▼
        parseFrontmatter（轻量，≤1KB 实现）
                    │  normalize + sort + 过滤 draft
                    ▼
        utils/content.js 静态导出（模块级常量）
                    │
[运行期·主chunk]     ├──→ pages/* 列表页、首页、时间线、Lab
                    │
[运行期·懒加载]      └──→ 详情页：动态 import 原文 md + utils/markdown.js
                              （markdown-it + highlight.js 仅在详情 chunk）
```

## 4. 数据流与状态设计

### 4.1 内容数据流（构建期）

```
*.md ──glob(?raw, eager)──▶ 原始字符串
        │
        ▼ parseFrontmatter（轻量解析器，见 §5.1）
    { meta, offset }
        │
        ▼ normalize：布尔归一、数组归一、缺省补值、过滤 draft
    ProjectMeta / NoteMeta
        │
        ▼ sort（规则见 04 §8.3）
        │
        ▼ 聚合导出（含 techList / tags 派生）
```

产物是**纯静态模块级常量**，无任何运行时计算依赖（派生查询如过滤在页面内 computed，每次访问 O(n) 足够）。

### 4.2 页面数据流（运行期）

- **列表页**：`route.query` → `computed` 派生 → 渲染。数据源 `projects` 等为常量。
- **详情页**：`route.params.slug` → `getProject(slug)`（同步 meta）→ `onMounted` 动态 import 原文 + markdown.js → `ArticleContent` 渲染。
- **首页**：`featuredProjects` / `recentNotes` 直接渲染，无状态。

### 4.3 过滤状态流（决策 D2：URL 即状态）

```
用户点击 FilterBar
   └→ emit('update:modelValue')
        └→ 页面 handler：router.replace({ query: 新查询对象 })
             └→ route.query 变化（唯一事实来源）
                  └→ computed 重新派生 → 列表重渲染
刷新 / 分享链接
   └→ route.query 初始化 → 同一派生链（结果一致）
```

规则：
- 组件**只** emit，不写路由（`05-组件规范` FilterBar 已定义）
- 空值不写入 query（清除筛选 = 从 query 删除该 key，而不是写入空串）
- query 读取统一封装：`toQueryArray(route.query.tech)` 处理 `string | string[] | undefined` 三种形态
- 多选 tech 写入重复参数（`?tech=a&tech=b`，`02` §4 规则 6）

### 4.4 详情页加载时序

```
挂载 → getProject(slug)
  ├─ undefined → 渲染 NotFound（同路由内 v-if，不 redirect）
  └─ 命中 →
       ├─ 页头（meta 同步渲染，无闪烁）
       └─ 正文：async load → import(原文) + import(markdown.js)
            ├─ 加载中：正文区骨架（min-height 占位，无闪烁）
            └─ 完成：renderMarkdown → v-html
```

## 5. 关键模块详细设计

### 5.1 内容管线：meta-only + 轻量 frontmatter 解析器（决策 D1）

**动机（性能）**：`markdown-it` + `highlight.js/common` 约 60–80KB gzip，若随管线 eager 进主 bundle，首屏 JS 超预算（150KB）。列表页只需要 meta；只有详情页需要 HTML。

**措施**：
1. `content.js` 只做 frontmatter 解析与聚合（不 import markdown-it）
2. 正文原文用**非 eager** glob 驻留在详情模块，与 `markdown.js` 一起被动态 import → Vite 自动拆为共享详情 chunk
3. frontmatter 解析器**手写**（约 50 行，见下），替代 gray-matter + js-yaml（约 15KB gzip），理由：
   - 本项目 frontmatter 是受控子集：单行 `key: value`，值为字符串/布尔/整数/简单字符串数组/空
   - 校验脚本（P6 层）保证该子集不被破坏；越界内容直接构建失败
   - 省掉 15KB 且规避 js-yaml 的解析开销

```js
// utils/parse-frontmatter.js（主 bundle 内，≤1KB gzip）
export function parseFrontmatter(raw) {
  const m = /^---\r?\n([\s\S]*?)\r?\n---\r?\n?/.exec(raw)
  if (!m) throw new Error('frontmatter missing')
  const meta = {}
  for (const line of m[1].split(/\r?\n/)) {
    const t = line.trim()
    if (!t || t.startsWith('#')) continue
    const i = t.indexOf(':')
    const key = t.slice(0, i).trim()
    let v = t.slice(i + 1).trim()
    if (v === '') { meta[key] = null; continue }
    if (v.startsWith('[') && v.endsWith(']')) {
      meta[key] = v.slice(1, -1).split(',').map(s => s.trim().replace(/^["']|["']$/g, '')).filter(Boolean)
    } else if (v === 'true') meta[key] = true
    else if (v === 'false') meta[key] = false
    else if (/^-?\d+$/.test(v)) meta[key] = Number(v)
    else meta[key] = v.replace(/^["']|["']$/g, '')
  }
  return { meta, raw: raw.slice(m[0].length).trimStart() }
}
```

限制与兜底：
- 数组元素必须单行、逗号分隔、纯字符串（校验规则 14 新增，见 §6.4）
- 解析失败或字段异常 → 校验脚本报错，**构建失败**（错误只发生在开发期）

### 5.2 Markdown 渲染模块（独立 chunk）

```js
// utils/markdown.js —— 仅被详情页动态 import
import MarkdownIt from 'markdown-it'
import hljs from 'highlight.js/lib/common'

const md = new MarkdownIt({ html: false, linkify: true, highlight })
// 外链规则：http(s) 链接 target=_blank + rel=noopener noreferrer（站内绝对路径不处理）
// h2 锚点：渲染后为 <h2 id="<slug>-<n>">（anchor 规则，n 每次渲染从 1 计数）

export function renderMarkdown(raw, idPrefix = 's') { return md.render(raw) }
```

- `html: false`：正文禁止内嵌 HTML，从根上防 XSS（`04` §10 语法约束的强制执行点）
- 代码高亮：标注语言才高亮；未标注转义输出（`01` F04 已统一）
- 本模块 + 原文 md 会被 Vite 拆为共享 chunk（两个详情页复用，只加载一次）

### 5.4 过滤模块（Projects / Notes / Lab 共用模式）

```js
// pages/Projects.vue（模式样板，其余页面复制此结构）
const route = useRoute()
const router = useRouter()

const status = computed(() => (route.query.status ?? ''))
const techs = computed(() => toQueryArray(route.query.tech))

const filtered = computed(() =>
  projects.filter(p =>
    (!status.value || p.status === status.value) &&
    (techs.value.length === 0 || techs.value.some(t => p.tech.includes(t)))))  // OR

function applyFilter(next) {
  const query = { ...route.query }
  next.status === '' ? delete query.status : query.status = next.status
  next.tech.length === 0 ? delete query.tech : query.tech = next.tech
  router.replace({ query })
}
```

`toQueryArray`（`utils/query.js`）：统一处理 `string | string[] | undefined | null`。

- 图片：圆角、居中、`margin` 节奏
- 链接：accent 色、正文内 hover 下划线
- 表格：边框细线、表头加粗、`.table-wrap` 由渲染层包裹（可 overflow-x）
- 阅读节奏：行高 1.7、段落间距 16px、窄栏 720px（F04）
- **hljs 亮色主题**：禁用 hljs 默认暗色，按 03 §2.4 色板覆盖 6 类 token（关键字橙/字符串绿/函数紫/注释灰/数字正文色/变量斜体）；代码块无 `.hljs` 时纯文本转义无配色

- 不引预处理器；不用 CSS 嵌套（平铺 BEM 保持可读性）
- `v-html` 内容的样式只能来自全局 markdown.css（scoped 不穿透），所以 ArticleContent 必须包裹 `.article` 类

### 5.6 动画模块（useScrollReveal）

```js
// composables/useScrollReveal.js
export function useScrollReveal(targetRef, { stagger = 0 } = {}) {
  // ① 匹配 prefers-reduced-motion → 直接给全部后代 .reveal 加 .revealed，return（不创建观察器）
  // ② 实例级 IntersectionObserver（每页面一个实例，不在模块层共享——单 RouterView 场景，
  //    实例级生命周期干净：onUnmounted disconnect，切页后旧观察器不残留）
  //    options: { threshold: 0.15, rootMargin: '0px 0px -40px' }
  // ③ 观察 targetRef 根元素：首次进入视口 → 遍历后代 .reveal，
  //    按 data-index 设 transition-delay = index × stagger → 加 .revealed
  //    → observer.unobserve(根) + disconnect（一次性语义，不重复触发）
  // ④ 时序注意：与 PageTransition（out-in）配合——新页面组件挂载后再开始观察，
  //    过渡期间旧页面仍在退出，避免在过渡容器内误触发
}
```

- 触发条件与 Vue 组件生命周期耦合（onMounted 注册 / onUnmounted 清理），由 hook 内部处理

CSS 契约：

```css
.reveal { opacity: 0; transform: translateY(16px); transition: opacity var(--dur-slow) var(--ease-standard), transform var(--dur-slow) var(--ease-standard); }
.reveal.revealed { opacity: 1; transform: none; }
```

适用范围仅：区块标题 + 卡片组（`03` §7.2 清单制）。

### 5.7 SEO 模块

**分层策略**（诚实面对 SPA 限制：JS 注入的 meta 对多数爬虫无效，按页面类型分级）：

| 页面类型 | title / description | OG 标签 | 爬取性 |
| --- | --- | --- | --- |
| 首页 | `afterEach` 设置（title 规则见 `02` §2） | index.html 静态齐全：og:title / og:description / og:image（1200×630） | 完整 |
| 列表页 | `afterEach` 设置（固定路由文案） | 不注入（继承站点默认） | 中：爬虫渲染后可读，注入的 meta 不可靠 |
| 详情页 | 组件内 `watchEffect` 同步设置（meta 在主 bundle，不等正文） | **v1 不注入**（JS 注入对爬虫无效）；详情页 OG 列入 v1.5 SSG 增量 | 低，v1 接受，v1.5 修复 |

**静态基础**（index.html 硬编码）：`lang="zh-CN"`、theme-color、favicon、description、JSON-LD Person（schema.org）；`robots.txt` 放行全部；**不做** dynamic OG 注入、不做 canonical（v1.1 启用）。

**`utils/seo.js` API**（组件不直接操作 document）：

```js
export function setTitle(t)          // document.title 赋值（守卫空串，静默跳过）
export function setDescription(d)    // 缺省回退 site.bio
export function setCanonical(url)    // v1.1 启用（签名预留）
export function applyMeta(route)     // afterEach 统一入口：按路由表规则求值 title/description
```

**细节**：
- 详情页 title 用 meta 同步设置（不等正文加载完成）；列表页 title 为固定路由文案，**不含当前过滤条件**（过滤状态不进 title，避免长 query 噪音）
- `applyMeta` 对无 `meta.title` 的路由（详情页）跳过，交给组件内 `watchEffect` 覆盖
- 所有 setter 幂等；设置失败（document 不可用）静默跳过

### 5.8 布局壳细节

- `AppHeader`：sticky top-0；bg `rgba(250,250,248,0.9)` + `backdrop-blur`（不支持时降级不透明，`07` §15）
- `MobileDrawer`：Teleport 到 body；`aria-expanded` + `aria-controls`；Esc 与遮罩关闭；焦点圈闭（focus trap 简化版：关闭时归还焦点到菜单按钮）；body 滚动锁

### 5.10 响应式架构

断点三档（F10，mobile-first）：

| 档位 | 宽度 | 布局 |
| --- | --- | --- |
| 手机 | < 640px | 单列 |
| 平板 | 640–1024px | 两列 |
| 桌面 | ≥ 1024px | 原设计 |

实现规则：
- **媒体查询写死数值 640 / 1024，不引用 CSS 变量**（CSS 变量在 media query 中不生效——tokens.css 注释声明，避免实现时踩坑）

- **代码块 pre 允许局部横向滚动**（`overflow-x: auto`）——"全站无横向滚动条"指页面级（F10），pre 内滚动是期望行为，这是唯一例外
- 触摸目标 ≥ 44px：导航项、按钮、FilterBar 项、卡片链接（F10）
- 图片 `width:100%` + 显式宽高（aspect-ratio 兜底）防溢出与 CLS
- 表格包 `.table-wrap`（`overflow-x:auto`），v1 不做小屏卡片式重构

| 正文（.article） | padding 16px | 窄栏 720px 居中 | 同左 |

| 时间线 | 月列收窄 | 标准 | 标准 |
| FilterBar | 纵向堆叠 wrap | 横向 wrap | 横向 |

### 5.11 无障碍架构（WCAG 2.1 AA 核心项；验收清单 `07` §14）

**landmark 与语义**：
- `header / nav / main / footer`；SkipLink → `#main`（main 上 `tabindex="-1"` 使可聚焦）
- 每页唯一 h1（详情页 = 内容标题）；区块标题 h2 级连
- 卡片结构 + **主链接 overlay 方案**：`<article><h2><RouterLink class="cover">`，cover 用 `::after` 覆盖整卡；卡内 demo/github 等独立链接 `z-index` 抬升——**禁止 a 嵌套 a**

**键盘与焦点**：
- 全站焦点可见：base.css 统一 `:focus-visible` outline（非鼠标点击显示）
- MobileDrawer：打开时焦点移入首个可聚焦项；Esc 关闭；关闭后焦点归还菜单按钮（§5.8）
- Tab 顺序 = 视觉顺序（DOM 序）

**aria**：
- FilterBar 状态组：`aria-pressed` 按钮组（v1 采用；实现简单且无障碍测试友好）；tech 多选同理
- 图标链接（GitHub 等）：aria-label
- **TagRotator**：轮换区 `aria-hidden="true"`（对读屏是噪音），hero 副标题静态文本承载同等信息——读屏不感知轮换
- ExternalLink：可视文本 + 必要 aria-label（如纯图标时）

**动效**：
- `prefers-reduced-motion`：useScrollReveal 直接加 `.revealed` 不创建观察器（§5.6）；TagRotator 静态首项（F02）；PageTransition 降级为无过渡

**对比度**：验收时用 axe-core / 浏览器检查器过一遍：正文 ≥ 4.5:1、大号文字 ≥ 3:1（F12）；违规回改 `03` 令牌——03 为权威，禁止组件内硬编码颜色绕过

## 6. 质量与安全架构

### 6.1 三层防护（错误只在开发期出现）

| 层 | 工具 | 拦截内容 |
| --- | --- | --- |
| L1 内容校验 | `npm run validate` | schema 缺失、枚举越界、slug 冲突、链接失效、段落缺失、alt 缺失 |
| L2 构建 | `npm run build`（eager 解析在构建期执行；Markdown 渲染是运行时懒加载，见决策 D1） | frontmatter 语法错误 → 直接构建失败 |
| L3 人工 | `13-测试与发布检查单` | 视觉、交互、性能、深链 |

设计意图：**运行时没有错误分支可处理的内容错误**（除了路由参数，见 §4.4）。

### 6.2 安全设计

| 威胁 | 对策 |
| --- | --- |
| 正文 XSS | markdown-it `html: false` + 校验脚本拒绝内嵌 HTML 标签模式 |

| 密钥泄露 | 全站零环境变量、零运行时请求 |

### 6.3 性能架构

chunk 规划（目标首屏 ≤ 150KB gzip）：

| chunk | 内容 | 预估值 |
| --- | --- | --- |
| 主 index | vue + vue-router + content.js + parse-frontmatter + 壳 + Home（其余页面均懒加载） | ~100–120KB gzip |
| 页面懒加载 | 各页面 2–5KB / 个 | 按需 |

### 6.4 校验脚本规格（scripts/validate-content.mjs，L1）

> 规则清单与字段约束的唯一权威是 `04-内容层规范` §9/§3；本节定义**如何检查**。

**运行方式与约定**：
- `npm run validate` → `node scripts/validate-content.mjs`（Node ≥ 18）；退出码：0 通过 / 1 失败（CI 失败即停，`01` §4：禁止跳过）
- 文件枚举用 `node:fs` 递归读 `src/content/`（**不用 import.meta.glob**——那是 Vite 运行时特性）；`_` 开头文件跳过
- frontmatter 解析**复用** `utils/parse-frontmatter.js`（纯函数、零 Vite 依赖）——Node 与浏览器同一实现，杜绝双实现漂移
- 输出格式：`ERROR [规则N] 相对路径: 消息`；全部检查完一次性打印（不 fail-fast），末尾汇总 `共 N 个错误`
- 错误消息给出**修复指引**（"应改为 x"），面向内容作者而非程序员

**15 条规则实现要点**（编号同 04 §9）：

| 规则 | 检查算法要点 |
| --- | --- |
| 1–2 | 逐文件 parseFrontmatter（复用实现）；必填字段按 04 §3/§4 字段表 |
| 3 | slug：kebab-case 正则 + 保留字表（`02` §4）+ 与文件名一致；冲突用 Set 检测 |
| 4 | 枚举：`PROJECT_STATUS` / timeline `type`（04 §4/§6） |
| 5 | 正则 `^\d{4}-\d{2}(-\d{2})?$` + 月份 01–12 |
| 6 | tech 元素查 04 §7 规范名表（Set 查找 O(1)） |
| 7 | summary 长度（UTF-16 计数，与 CSS 截断弱绑定，取近似） |
| 8 | 必需段落：行首匹配 `^## 段落名$`（04 §3 九段清单） |
| 9 | `new URL()` 可解析 + `https:` 协议 |
| 10 | 正则提取正文站内链接（`](/projects/xxx)` / `](/notes/xxx)`），slug 对照文件集 |
| 11 | featured 计数 ≤ 3 |
| 12 | JSON.parse + 手写字段类型断言（不引 schema 库） |
| 13 | markdown 图片语法 `![alt](url)`：alt 非空（注意：正文禁 `<img>` 标签由规则 15 拦；13 管的是 **markdown 语法**层的 alt） |
| 14 | 数组字段元素：字符串 + 无 `,`（元素单行） |
| 15 | **围栏切分**：按 ` ``` ` 行把正文切成"代码 / 非代码"交替段，仅非代码段匹配 `<[a-zA-Z!/]` |
| — | about.md 豁免规则 1–13（无 frontmatter，§5.9.2），仅查规则 15 与空文件 |

> 规则 13 与 15 的分工：13 管 markdown 图片语法（alt 缺失），15 管 HTML 注入（`html: false` 双保险），互不替代。

### 6.5 图片与媒体策略

- 存放：`public/images/<slug>/`（与内容 slug 绑定，04 §10）
- 格式：照片类 JPG（压缩后 ≤ 300KB/张）；图标/线稿 SVG；v1 不做 WebP 自动转换（GH Pages 原样分发，体积预算内）
- 显式 `width/height`（像素）或 `aspect-ratio` → 防 CLS（F10）；CSS 只改显示不改比例
- `loading="lazy"`（首屏外）；`alt` 必填（校验规则 13）
- 首页 hero 无图（LCP = 标题文本，见 §7.4 预算）
- `og-image.png` 1200×630，放 public/（一次性生成）

### 6.6 运行期边界（需要代码兜底的场景统一表）

| 场景 | 行为 | 依据 |
| --- | --- | --- |
| 未知 slug / draft 直链 | 同路由渲染 NotFound（不 redirect） | F03/F04 |
| 详情 loader 缺失（meta 残留但文件消失——校验理论上已拦截，此为回潮防线） | 页头 + 正文区"正文缺失"提示 | 防回归 |
| 列表无结果（含非法 query 值） | EmptyState + 清除筛选（删 query key，不清其他浏览器状态） | F03/F06/F07 |
| 首页区块空 | 区块整体隐藏，不显示 EmptyState | 01 §4 |
| techList / noteTags 为空 | FilterBar 对应行隐藏 | 防空 UI |
| JS 禁用 | GH Pages 返回 404.html 静态文案，无法渲染 SPA | 诚实声明，v1.5 SSG 修复 |
| 外部链接失效 | 静态站不可自动检测；发布检查单人工抽查 | 01 §4 |

> 其余边界场景与决策见 `01` §4 边界情况表——本表只列"程序内需要写代码兜底"的。

## 7. 构建与部署架构

### 7.1 构建管线

```
npm run build
  ├─ validate-content.mjs    （L1）
  ├─ vite build              （L2；postbuild 前）
  │    ├─ 主 chunk（meta 数据已内联）
  │    └─ 详情共享 chunk + 页面 chunk（懒加载）
  └─ copy-404.mjs            （postbuild：dist/index.html → dist/404.html）
```

`vite.config.js` 完整草稿（P0 直接照抄）：

```js
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  base: '/<repo>/',                       // 自定义域名时改 '/'（07 §9.3）
  plugins: [vue()],
  resolve: { alias: { '@': '/src' } },
  server: { host: true },                 // 局域网调试可选
  build: {
    target: 'es2019',
    chunkSizeWarningLimit: 120,           // 详情共享 chunk 约 70KB，不误报
    cssCodeSplit: true,                   // 默认即 true，页面级 CSS 独立（显式声明）
    sourcemap: false,                     // 生产不产出 map（体积/隐私）
  },
})
```

- 详情共享 chunk 无需手动配置：`markdown.js` + 原文 md 只被两个详情页动态 import → Vite 自动拆为共享 chunk
- 不使用 `manualChunks`（保持默认拆包；强行分组会破坏懒加载边界）
- `import.meta.glob`（eager + 非 eager）均为 Vite 标准能力，无插件需求

产物结构：

```
dist/
├── index.html
├── 404.html          # postbuild 复制
├── robots.txt        # public/ 原样拷贝
├── favicon.svg
├── og-image.png
└── assets/           # js/css 分块 + 图片
```

### 7.2 部署拓扑

```
push main → GitHub Actions（validate → lint → build → upload-pages-artifact）
          → GitHub Pages <user>.github.io/<repo>
          → 任意子路由命中 404.html → SPA 接管渲染（深链正常）
```

- 无 CDN 配置项（GH Pages 自带缓存，`no-cache` 于 index.html 由 GH 处理）
- 自定义域名：`public/CNAME` + DNS，`base` 改 `/`（`07` §9.3）

### 7.3 CI/CD 工作流规格（.github/workflows/deploy.yml）

> 前置：GitHub Pages 部署源必须设为 **"GitHub Actions"**（仓库 Settings → Pages → Source）。

```yaml
name: deploy
on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm
      - run: npm ci
      - run: npm run validate          # L1 内容校验
      - run: npm run lint              # 代码检查
      - run: npm run build             # L2 构建
      - uses: actions/upload-pages-artifact@v3
        with:
          path: dist
  deploy:
    needs: build
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

- 失败即停：validate / lint / build 任一失败 → 不部署（三层防护 L1/L2 在 CI 生效）
- 自定义域名：`public/CNAME` 入库随站发布（`07` §9.3）

### 7.4 性能预算与验收

| 指标 | 预算 | 验收方式 |
| --- | --- | --- |
| 首屏 JS | ≤ 150KB gzip | build 产物统计 + Lighthouse 实测 |
| 主 chunk | ≤ 120KB gzip（vite 告警阈值 120） | `npm run build` 输出 |
| 详情共享 chunk | ≤ 80KB gzip | 同上 |
| LCP | ≤ 1.5s（4G 模拟） | Lighthouse mobile |
| CLS | ≤ 0.1 | Lighthouse |
| Lighthouse Performance | ≥ 90 | 发布前人工跑一次 |

- 每次 build 检查产物体积；超预算先查主 bundle（meta/壳），再查详情 chunk
- 新增依赖走 `07` §10 评审——依赖最小化是预算的第一道防线
- 预案：详情共享 chunk 超预算 → highlight.js 改 `lib/core` + 按需注册语言（04 §7 规范名表内约 10 种），预计再省 50%+；仅当实测超预算时启用

### 7.5 静态降级（无 JS 体验）

index.html 内置 `<noscript>` 块（复制为 404.html 后同样生效）：
- 提示"本站需要 JavaScript 才能完整渲染"（诚实声明）
- 静态 HTML 可达的链接：首页、`/projects`、`/notes`、`/about`、GitHub 外链（真实路径，纯 HTML 可点）

限制声明（与 §6.6 表一致）：JS 禁用或爬虫直取 HTML 时，只能看到 noscript 内容与空骨架——v1 接受，v1.5 SSG 修复。

## 8. 测试架构（策略）

| 层级 | 手段 | 频率 |
| --- | --- | --- |
| 静态 | validate（内容）/ lint（代码） | 每次提交 |
| 构建 | build 通过 + 产物预览 | 每次提交 / 每次发布 |
| 人工 | `13-测试与发布检查单` 全量 | 每次发布 |
| 自动化（可选 v1.1） | Playwright 冒烟：全路由可达 + 首页渲染 + 过滤交互 | CI 定时/发布前 |

自动化列为可选：静态站核心风险在内容与视觉，人工检查单性价比更高；若内容量增长再引入冒烟。

冒烟清单（v1.1 引入 Playwright 时照此实现）：
- 10 个页面 / 11 条路由记录（含 catch-all）全部可达且渲染正确（首屏断言：h1 文本 / 页面关键组件存在）
- 深链直达：`/projects/<slug>`、`/notes/<slug>` 直开渲染正确（含 404.html 兜底模拟）
- 过滤交互两例：Projects 状态切换、tech 多选 → query 正确写入、刷新后状态保持
- 未知路由 → NotFound 文案
- 首页 LCP 元素存在（hero 标题）
