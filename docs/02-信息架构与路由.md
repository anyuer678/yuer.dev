# 02 信息架构与路由

## 1. 站点地图

```
/                 Home       首页
├── /about        About      自我介绍
├── /projects     Projects   项目档案列表（核心）
│   └── /projects/:slug       项目详情
├── /timeline     Timeline   成长时间线
├── /notes        Notes      开发日志列表
│   └── /notes/:slug          笔记详情
├── /lab          Lab        实验小项目
├── /contact      Contact    联系方式
└── /:pathMatch(.*)*         404
```

## 2. 路由表（vue-router 全量定义）

| 路径 | 组件 | 名称 | title 规则 | 导航显示 |
| --- | --- | --- | --- | --- |
| `/` | Home | home | `site.brand · tagline[0]` | 否（品牌回首页） |
| `/about` | About | about | `关于 · site.name` | 是 |
| `/projects` | Projects | projects | `项目 · site.name` | 是 |
| `/projects/:slug` | ProjectDetail | project-detail | `{title} · {subtitle 或 site.name}` | 否 |
| `/timeline` | Timeline | timeline | `时间线 · site.name` | 是 |
| `/notes` | Notes | notes | `笔记 · site.name` | 是 |
| `/notes/:slug` | NoteDetail | note-detail | `{title} · site.name` | 否 |
| `/lab` | Lab | lab | `实验室 · site.name` | 是 |
| `/contact` | Contact | contact | `联系 · site.name` | 是 |
| `/:pathMatch(.*)*` | NotFound | not-found | `页面不存在 · site.name` | 否 |

实现要求：

- 所有页面组件**懒加载**：`() => import('@/pages/Home.vue')`
- 详情路由取参统一用 `route.params.slug`（实现样板见 `14-技术架构设计` §5.9.4；组件不必声明 props）
- title 在路由 `meta.title` 中声明为函数（如 `meta: { title: (site) => \`项目 · ${site.name}\` }`），由 `afterEach` 统一执行
- 每个静态路由声明 `meta.description`（列表页一句话描述，用于 SEO）；详情路由 title/description 由组件内 watchEffect 依据 slug 数据设置（`14` §5.7）

## 3. 导航规范

- Header 导航顺序固定：About / Projects / Timeline / Notes / Lab / Contact
- 激活态：`RouterLink` + `exact-active-class`（详情页不点亮列表导航）
- 品牌（logo 文字"Yuer Studio"）点击回 `/`
- 移动端行为：< 640px 显示汉堡按钮 → 右侧抽屉；打开时 `aria-expanded="true"`、锁定 body 滚动、Esc 与遮罩点击关闭、关闭后焦点回到按钮

## 4. URL 与 slug 规则

1. 路径一律 kebab-case 小写
2. `slug` 唯一；一旦发布不可变更（改 slug 视为新内容，旧链接自然失效）
3. **保留字**（内容 slug 不得占用）：`about`、`projects`、`timeline`、`notes`、`lab`、`contact`、`home`
4. 内链一律使用绝对路径（`/projects/evocode`），禁止相对路径，避免部署目录层级问题
5. 外链一律新标签页 + `rel="noopener noreferrer"`（统一封装 `ExternalLink` 组件）
6. 列表页筛选 query 编码：单值用单参数（`?status=development`）；多选技术栈用**重复参数**（`?tech=vue3&tech=python`），组件内用 `URLSearchParams.getAll('tech')` 读取，禁止逗号拼接（避免 URL 编码歧义）

## 5. 滚动行为（scrollBehavior）

- 切页默认回到顶部
- 若未来需要锚点（`#section`），滚动到对应元素

## 6. SPA 深链兜底（GitHub Pages）

GitHub Pages 对不存在路径返回 404 页面，导致 `/projects/evocode` 直达失效。方案：

- `public/404.html` 内容与 `index.html` 完全一致（构建后复制）
- 部署后浏览器访问任意子路由 → 返回 404.html → 前端路由接管渲染对应页面
- 效果：地址栏正确、内容正确，仅网络层面先收到 404 状态（可接受；SEO 交给 v1.5 预渲染）

验证命令（部署后）：

```
curl -s -o /dev/null -w "%{http_code}" https://<user>.github.io/<repo>/projects/evocode
```

返回 **404 状态码 + 404.html 内容**属正常：浏览器拿到 404.html 后由 SPA 接管渲染真实页面（地址栏与内容正确，仅网络层状态为 404）。

## 7. 重定向规则（v1 可选，v1.1 默认做）

| 旧路径 | 新路径 | 原因 |
| --- | --- | --- |
| `/project/:slug`（笔误历史） | `/projects/:slug` | 统一复数命名 |
| `/post/:slug` | `/notes/:slug` | 旧名"文章" |

实现：v1.1 用 `src/content/redirects.json` 数据驱动（内容作者可维护，规格见 `14-技术架构设计` §9 v1.1）；v1 阶段若发生迁移可临时在路由表加 `redirect` 配置。

## 8. 元信息规范

- title 总长度 ≤ 60 字符，description ≤ 120 字符
- 详情页 title 兜底：无 subtitle 时用 `site.name`；无 tags 时同理不输出空段
- 详情页 description 优先级：frontmatter `summary` > 默认
- OG 图片：`/og-image.png`（1200×630，后续可替换为自动生成）
- 站点根 `index.html` 必须含：`lang="zh-CN"`、charset、viewport、favicon、theme-color（`#FAFAF8`）
