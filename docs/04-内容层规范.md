# 04 内容层规范

> 内容层是网站核心资产：**改内容不碰代码**。本文档定义所有内容文件的 schema、校验规则、内容管线设计，并提供模板与示例。

## 1. 内容目录结构

```
src/content/
├── site.json            # 站点级配置（品牌、导航数据、首页文案）
├── about.md             # About 页正文（可选，v1 默认使用 site.json 的 bio 字段；**无 frontmatter**，纯 Markdown 正文，直接 raw 渲染，不走 parseFrontmatter；校验仅查规则 15）
├── projects/            # 每个项目一个 md，文件名 = slug
│   ├── _template.md     # 模板（含字段说明，不入管线：文件名以下划线开头）
│   └── evocode.md
├── notes/
│   ├── _template.md
│   └── evocode-architecture.md
├── lab.json             # Lab 实验条目
└── timeline.json        # 成长时间线
```

规则：**以下划线开头的文件不入管线**（`_template.md`、`_draft.md`）。

| 字段 | 类型 | 必填 | 说明 |

| `links.other` | object[] | 否 | 其他链接 |

## 3. 项目 frontmatter schema

```yaml
---
slug: evocode
title: EvoCode
subtitle: AI Software Evolution Platform
status: development
featured: true
date: 2026-08-01
tech: [Vue 3, Spring Boot, Python, LLM]
tags: [AI, FullStack]
summary: 面向软件维护场景的 AI 软件进化平台，覆盖代码分析、架构理解与 AI 报告生成。
demo: https://...
github: # 待公开仓库后补充：https://github.com/anyuer678/evocode
order: 1
draft: false
---
```

### 字段定义

| 字段 | 类型 | 必填 | 约束 | 用途 |
| --- | --- | --- | --- | --- |
| `slug` | string | 是 | kebab-case、全站唯一、非保留字（见 `02-信息架构` §4） | 路由 |
| `title` | string | 是 | ≤ 30 字 | 卡片标题 / title |
| `subtitle` | string | 否 | ≤ 60 字符，英文为主 | 卡片副标题 |
| `status` | enum | 是 | `development \| completed \| archived \| experiment` | 徽章 / 过滤 |
| `featured` | boolean | 否（默认 false） | 最多 3 个项目为 true | 首页精选 |
| `date` | string | 是 | `YYYY-MM-DD`，为"开始日期" | 排序 / 展示 |
| `tech` | string[] | 是 | ≥ 1，使用**规范名**（见 §7） | 标签 / 过滤 |
| `tags` | string[] | 否 | 自由标签（主题维度） | 分类 |
| `summary` | string | 是 | ≤ 100 字 | 卡片 / meta description |
| `demo` | string | 否 | `https://` | 演示链接 |
| `github` | string | 否 | `https://github.com/...` | 源码链接 |
| `order` | number | 否（默认 999） | 越小越靠前 | 列表排序 |
| `draft` | boolean | 否（默认 false） | `true` 时列表隐藏，详情 404 | 草稿 |

### 正文结构（固定 9 段，`##` 二级标题）

| 序号 | 段落 | 是否必需 | 写法指南（每段 2–5 句，用列表辅助） |
| --- | --- | --- | --- |
| 1 | 项目介绍 | 必需 | 背景：解决什么问题、现有方案为什么不够 |
| 2 | 设计目标 | 必需 | 2–4 条 bullet，可衡量的目标 |
| 3 | 功能 | 必需 | 功能列表，每项一句话 |
| 4 | 架构 | 必需 | 分层 / 模块 / 数据流，可附图（用代码块画图） |
| 5 | 技术选择 | 必需 | 每项技术 1–2 句理由 |
| 6 | 开发过程 | 可选 | 关键节点、迭代顺序 |
| 7 | 挑战与解决 | 可选 | 挑战 → 方案，2–3 个 |
| 8 | 未来计划 | 必需 | 明确计划列表（含"不做"项更好） |
| 9 | 源码与 Demo | 可选 | 链接列表 |

## 4. 笔记 frontmatter schema

```yaml
---
title: EvoCode 架构设计记录
date: 2026-08-05
tags: [架构, AI]
summary: 从单体到模块化的决策过程：为什么把分析引擎拆成独立服务。
draft: false
---
```

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `title` | string | 是 | ≤ 40 字 |
| `date` | string | 是 | `YYYY-MM-DD` |
| `tags` | string[] | 否 | 自由标签 |
| `summary` | string | 是 | ≤ 100 字，列表页展示 |
| `draft` | boolean | 否 | 同项目 |

写作定位：**开发日志**，不是教程博客。结构建议：背景/动机 → 发生了什么 → 结论。不追求完整教程，追求真实决策记录。

  { "date": "2026-07", "title": "完成 CodeDrill", "type": "project", "link": "/projects/codedrill" },

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `date` | string | 是 | `YYYY-MM` |
| `title` | string | 是 | ≤ 40 字 |
| `type` | enum | 是 | `project \| learning \| note \| milestone` |
| `link` | string | 否 | 站内绝对路径（`/projects/...`） |

排序：按 `date` 降序，同年同月保持 JSON 内顺序。`type=note` 的 link 指向 `/notes/...`。

## 7. 技术栈规范名（tech 字段）

`tech` 用于标签与过滤，必须使用规范名，避免重复变体（如 "vue" / "Vue3" / "Vue.js"）。默认规范表：

```
Vue 3, Vite, TypeScript, JavaScript, Spring Boot, Java, Python, LLM, Electron,
Node.js, Docker, Linux, Git, MySQL, Redis, Flask, FastAPI, MCP, AI, OpenAI API,
GitHub Actions, HTML, CSS
```

- 新增规范名：先在本表追加再使用（唯一允许的"改内容碰代码"场景）
- 标签（`tags`）不受限制，属自由维度

## 8. 内容管线设计（utils/content.js）

### 8.1 数据流

```
projects/*.md ─┐
notes/*.md   ─┼→ import.meta.glob(raw) → 解析 frontmatter → 统一数据对象 → 组件
site.json    ─┤        (构建期打包，无运行时请求)
lab.json     ─┤
timeline.json─┘
```

### 8.2 管线伪代码

> 管线为 **meta-only** 版本（决策 D1，完整实现见 `09-参考实现` §4）：主 bundle 只导出 meta，正文原文走懒加载、渲染发生在详情页 chunk。

```js
const PROJECT_STATUS = ['development', 'completed', 'archived', 'experiment']

function buildMeta(entries) {
  return entries
    .filter(([path]) => !path.includes('_'))        // 排除 _ 开头模板
    .map(([path, raw]) => {
      const { meta } = parseFrontmatter(raw)        // 轻量解析器（utils/parse-frontmatter.js）
      return { slug: 文件名, meta: normalizeMeta(meta) }
    })
    .filter((item) => !item.meta.draft)
}

export const projects = buildMeta(...)
  .sort((a, b) => (a.meta.order ?? 999) - (b.meta.order ?? 999) || b.meta.date.localeCompare(a.meta.date))
export const notes = /* 同结构，按 date 降序 */

export const getProject = (slug) => projects.find((p) => p.slug === slug)
export const getNote = (slug) => notes.find((n) => n.slug === slug)
// 原文懒加载：projectRawFiles / noteRawFiles（见 09 §4.2，非 eager glob）
```

- slug 从 frontmatter 读取（文件名仅作兜底）；两者必须一致（校验规则见 §9）；实现以 `09-参考实现.md` §4 为准（文件名兜底 + 校验强制一致）
- meta 用 `eager: true` 构建期全部打包；正文原文用**非 eager** glob，仅详情页懒加载（决策 D1）
- 列表页过滤在组件内基于 `projects` 派生（状态/技术栈/搜索词），query 驱动

### 8.3 排序与过滤规则汇总

| 场景 | 规则 |
| --- | --- |
| 项目列表 | `order` 升序 → 同值按 `date` 降序 |
| 首页精选 | `featured=true`，按同一排序规则，取前 3 |
| 首页最近笔记 | `date` 降序，取前 3 |
| 笔记列表 | `date` 降序 |
| Lab | `date` 降序 |
| 时间线 | `date` 降序 |
| 状态过滤 | `status` 精确匹配 |
| 技术栈过滤 | `tech` 包含匹配（多选 = AND 或 OR，v1 定 **OR**：任一命中即显示） |

## 9. 内容校验规则（scripts/validate-content.mjs）

构建前执行 `npm run validate`，失败则 CI 报错。规则：

1. 每个 md 文件 frontmatter 可解析
2. 必填字段齐全（按 §3/§4 表）
3. `slug` 唯一、kebab-case、非保留字；文件名（去扩展名）与 slug 一致
4. `status` / `type` 在枚举内
5. `date` 匹配 `^\d{4}-\d{2}(-\d{2})?$`，且 `YYYY-MM` 的月份在 01–12
6. `tech` 非空数组，全部在规范名表内（见 §7）
7. `summary` ≤ 100 字，`title` 长度达标
8. 项目正文包含全部**必需**段落（项目介绍/设计目标/功能/架构/技术选择/未来计划）
9. `demo` / `github` / `link` 为 `https://` 合法 URL
10. 站内链接（`/projects/...`、`/notes/...`）指向的内容 slug 存在
11. `featured` 数量 ≤ 3
12. site.json / lab.json / timeline.json 为合法 JSON 且 schema 字段类型正确
13. 正文中所有 `<img>` 必须有 `alt` 属性（防破图与无障碍）
14. frontmatter 数组字段（`tech` / `tags`）元素必须为单行简单字符串（无逗号、无嵌套引号）
15. 正文**非代码块**内容不得出现 `<` 开头的 HTML 标签（```` ``` ```` 围栏代码块内豁免——代码里含 `<` 属合法；配合 markdown-it `html: false` 双保险，硬错误）

## 10. Markdown 语法约束

- 正文标题从 `##` 开始（`#` 保留给页面 h1，正文禁止使用）
- 允许：段落、列表、有序列表、代码块、引用、行内代码、**粗体**、链接、图片、表格、分隔线
- 代码块标注语言（` ```js `），未标注按纯文本处理
- 图片：放 `public/images/<slug>/` 下，引用绝对路径 `/images/<slug>/xxx.png`；**必须写 alt**
- 内链用绝对路径（`/projects/xxx`），外链直接写 URL（渲染时自动新标签打开）
- 架构图允许用文本图（代码块内 ASCII 框图），v1 不引入 mermaid

## 13. v2.5 AI 增强预留（现在做对的事）

meta-only 管线下，数据以三份形态存在，v2.5 无需改造数据源：

```js
// 主 bundle（构建期）：meta 静态导出
{ slug, meta }                       // meta 含 tech/tags/status 等结构化字段

// 详情 chunk（懒加载）：原文与渲染
{ slug, raw }                        // raw：Markdown 原文，未来切块/embedding 直接用
{ slug, html }                       // html：运行时 renderMarkdown 输出
// url 由 slug 推导（/projects/<slug>），与路由规则天然一致
```

- `raw`：Markdown 原文（非 eager glob），未来切块/embedding 直接用，不重复解析
- `url`：内容地址稳定（slug 不可变），embedding 与结果引用可持久化
- `meta`：结构化字段，未来做过滤式检索（metadata filter）不需要再解析
- 搜索/问答检索策略留到 v2.5 专项设计，v1 不引入任何运行时成本
