# 11 内容维护手册（SOP + 写作规范）

> 写给"未来的自己"：加内容、改内容、排错的固定流程与质量标准。
> 目标是：**不读代码、不读其他文档，照本文操作即可完成 90% 的日常维护。**

## 0. 日常维护命令

```bash
npm run validate   # 内容检查（改完内容必跑）
npm run lint       # 代码检查（改了代码才需要）
npm run build      # 构建验证
npm run dev        # 本地预览
```

## 1. 添加一个新项目

1. 复制模板：`src/content/projects/_template.md` → `src/content/projects/<slug>.md`
2. 填写 frontmatter：
   - `slug`：小写 kebab-case（如 `evocode`），**发布后不可改**
   - `status`：四选一（development / completed / archived / experiment）
   - `date`：开始日期 `YYYY-MM-DD`
   - `tech`：用规范名（见 `04-内容层规范` §7），新名称先加到该表
   - `summary`：≤ 100 字，卡片上显示
3. 按 9 段结构写正文（必需段落：项目介绍 / 设计目标 / 功能 / 架构 / 技术选择 / 未来计划）
4. 想预览但不想公开：`draft: true`
5. 运行 `npm run validate`，直到零报错
6. 本地预览确认卡片与详情页渲染正常
7. 提交：`docs(projects): add <slug>`

## 2. 添加一篇笔记

1. 复制 `notes/_template.md` → `notes/<slug>.md`
2. 填 frontmatter（title / date / summary 必填）
3. 正文结构：背景动机 → 发生了什么 → 结论
4. `npm run validate` → 预览 → 提交 `docs(notes): add <title>`

## 3. 更新 Lab / 时间线

- 编辑 `lab.json` / `timeline.json`，保持字段与 schema 一致（`04-内容层规范` §5/§6）
- 时间线条目 `link` 只指向已存在的 slug
- 运行 `npm run validate` 后提交 `docs(lab|timeline): ...`

## 4. 修改既有内容

| 场景 | 做法 |
| --- | --- |
| 改正文 / 改标题 / 改 summary | 直接编辑 md，提交 `docs(...): update` |
| 想改 slug | **不允许**。开新 slug 并删除旧文件（旧链接自然 404，新内容从零累计） |
| 临时隐藏 | `draft: true`（列表隐藏、详情 404），不要删文件 |
| 改状态 | 改 `status` 字段即可（徽章/过滤自动生效） |
| 改排序 | 调 `order`（项目）或 `date`（其他） |

## 5. 写作规范

### 5.1 中文排版（正文强制遵守）

- 中英文之间加空格：`用 Vue 3 开发`（不是"用Vue3开发"）
- 中文与数字之间加空格：`共 12 个功能`
- 全角标点：中文句子里用 `，。：；（）「」`；英文/代码语境用半角
- 引号：正文用弯引号 `“”`；避免直角引号混用
- 省略号用 `……`（两个三点），不用 `...`（代码语境除外）
- 破折号用 `——`（占两字位）
- 百分比写法：`50%` 与数字同格（`50%`，不加空格）
- 版本号写法：`Vue 3`、`Spring Boot 3.x`（数字与名称之间空格）

### 5.2 质量标准（每篇内容发布前自检）

- [ ] 阅读者 30 秒内知道"这解决什么问题"
- [ ] 每段 2–5 句，不写流水账
- [ ] 具体而非抽象："支持 Markdown 渲染"优于"功能强大"
- [ ] 如实：experiment 项目不吹完成度
- [ ] summary ≤ 100 字且能独立成立（卡片上只有它）
- [ ] 无错别字、无半角标点混用
- [ ] 内部链接只指向存在的页面

### 5.3 语言基调

- 正文中文为主，技术名词保留英文；不翻译专有名词（LLM、API、Docker）
- 第一人称（"我"），像写工作日志，不像写广告
- 允许口语但要有信息量

## 6. 常见问题（FAQ）

| 问题 | 原因 / 解决 |
| --- | --- |
| 新项目不显示 | ① `draft: true` ② 文件名与 `slug` 不一致 ③ `npm run dev` 没重启（md 改动 Vite 会热更，新增文件需重启） |
| 详情页 404 | slug 拼写 / 保留字冲突（`04-内容层规范` §3） |
| 校验报"段落缺失" | 正文缺少必需 `##` 段落，对照模板补 |
| 校验报"tech 不在规范表" | 新技术名先加到 `04-内容层规范` §7 规范表 |
| 想放图片 | 放 `public/images/<slug>/`，正文用 `/images/<slug>/xxx.png`，必须写 alt |
| 过滤后一片空白 | 是 EmptyState（正常行为），点"清除筛选" |
| GitHub Pages 更新后看不到 | Pages 部署有 1–2 分钟延迟；强刷（Ctrl+F5）排除缓存 |

## 7. 偏离许可

- 本手册流程可简化，但**校验脚本必须跑**（它是内容与代码之间的唯一保险）
- 写作规范按"先内容质量、后形式"取舍；极端情况（如时间紧迫）可放宽排版，发布前补修
- 新增内容类型（如"开源贡献"板块）属于结构性变更：先在 `04-内容层规范` 补 schema，再动代码
