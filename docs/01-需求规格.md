# 01 需求规格书

> 本文档是验收依据。每个功能需求（F 编号）带独立验收标准；实现一个页面/功能时，逐条对照。

## 1. 范围与边界

### v1.0 范围内

- 7 个信息页面 + 2 类详情页（项目 / 笔记）+ 404
- 内容全部由 `src/content/` 下的 Markdown / JSON 驱动
- 静态部署，无后端、无数据库、无登录

### v1.0 明确不做（写进产品边界，防止范围蔓延）

| 排除项 | 原因 |
| --- | --- |
| 评论系统 | 需要后端；未来可用 GitHub Issues 方案 |
| 暗色模式 | 视觉方向定稿为浅色纸张感；后续单独评估 |
| 站内搜索 | v1.5 用静态索引方案（如 minisearch） |
| 多语言切换 | 内容中英混排即可，不做 i18n 框架 |
| 访问统计 | 可后接自建极简统计或 Plausible |
| 后台管理界面 | 内容即文件，无需后台 |
| 联系表单 | v1 只展示联系方式；表单需后端（未来可用 Formspree 等） |

## 2. 功能需求

### F01 全局导航与路由

- 优先级：P0
- 描述：全站统一 Header 导航 + vue-router 路由表 + 页面过渡；所有内部跳转使用 `<RouterLink>`（不触发整页刷新）。
- 验收标准：
  - [ ] Header 含品牌（点击回首页）与导航项：About / Projects / Timeline / Notes / Lab / Contact
  - [ ] 当前路由导航项有清晰激活态
  - [ ] 移动端（< 640px）导航折叠为抽屉，遮罩点击 / Esc 可关闭
  - [ ] 页面切换有 150ms 淡入过渡；切页滚动位置统一回到顶部（scrollBehavior 处理，不保存列表滚动位置）
  - [ ] 直达任意子路由（如 `/projects/evocode`）在本地 dev 正常
  - [ ] 直达子路由在 GitHub Pages 部署后不 404（见 `07-工程规范` 深链兜底）

### F02 首页 Hero 与标签轮换

- 优先级：P0
- 描述：Hero 区展示姓名、定位语、CTA 与动态轮换标签；数据来自 `site.json`。
- 验收标准：
  - [ ] 姓名为主视觉（display 字体 40px）
  - [ ] 定位语 ≤ 2 行，5 秒内可读完（"Software Developer / Building AI Tools…"）
  - [ ] 标签以轮换形式展示，间隔 500ms，切换为淡入淡出
  - [ ] `prefers-reduced-motion` 时标签静态显示首项
  - [ ] CTA：[View Projects] 跳 `/projects`，[GitHub] 外链新标签页打开
  - [ ] 高度约 55vh，视觉上有纸张网格纹理（`03-设计系统` 背景规范）

### F03 项目列表与过滤

- 优先级：P0
- 描述：`/projects` 以档案卡片展示全部项目，支持按状态与技术栈过滤。
- 验收标准：
  - [ ] 卡片含：标题、副标题、状态徽章、summary、技术栈标签、demo/github 链接
  - [ ] 状态过滤：全部 / 开发中 / 已完成 / 已归档 / 实验（默认"全部"）
  - [ ] 技术栈过滤：从现有项目技术栈动态生成标签组，可多选
  - [ ] 过滤状态写入 URL query（`?status=&tech=`），刷新 / 分享链接保持过滤
  - [ ] 无结果时显示 EmptyState（"没有符合条件的项目" + 清除筛选按钮）
  - [ ] 排序：`order` 升序优先，同 order 按 `date` 降序
  - [ ] `draft: true` 的项目不出现；详情页直达草稿一律 404（列表隐藏与详情 404 行为一致）

### F04 项目详情页

- 优先级：P0
- 描述：`/projects/:slug` 渲染项目 Markdown，结构固定为 9 段项目文档。
- 验收标准：
  - [ ] 从内容管线按 slug 精确匹配
  - [ ] slug 不存在时进入 404
  - [ ] 页头：返回链接（← Projects）、标题、副标题、状态徽章、技术栈标签、日期、demo/github 链接
  - [ ] 正文按 `##` 标题渲染，代码块高亮（标注语言则高亮，未标注按纯文本，无自动检测）
  - [ ] 代码块样式遵循 `markdown.css`（浅色纸张风格，非暗色终端风）
  - [ ] 正文阅读宽度 ≤ 720px 居中，行高 1.7
  - [ ] 页头与正文间有分隔线（细线），正文底部留足空间

### F05 时间线

- 优先级：P1
- 描述：`/timeline` 按时间倒序展示成长路线，数据来自 `timeline.json`。
- 验收标准：
  - [ ] 年份分组标题（如 2026 / 2025），组内按月倒序
  - [ ] 条目：月份 + 标题 + 类型徽章（project / learning / note / milestone）
  - [ ] 带 `link` 的条目可点击跳转
  - [ ] 时间线为纵向结构：左侧日期列 + 节点圆点 + 右侧内容
  - [ ] 空数据时显示 EmptyState
  - [ ] 新增条目只需改 JSON，无需改代码

### F06 笔记列表与详情

- 优先级：P1
- 描述：`/notes` 展示开发日志列表，`/notes/:slug` 渲染正文。
- 验收标准：
  - [ ] 列表行：标题 + 日期 + summary + 标签
  - [ ] 标签过滤：点标签只显示含该标签的笔记（URL query `?tag=`）
  - [ ] 详情页：返回链接 + 标题 + 日期 + 标签 + 正文（复用 ArticleContent 渲染）
  - [ ] 正文从 `##` 开始，与项目详情渲染一致性
  - [ ] 无结果 EmptyState
  - [ ] 新增笔记只需加 md 文件

### F07 Lab

- 优先级：P1
- 描述：`/lab` 收纳不长期维护的小项目，数据来自 `lab.json`。
- 验收标准：
  - [ ] 卡片：名称 + 一句话描述 + 状态徽章 + 日期 + 可选链接
  - [ ] 按日期倒序；可按状态过滤（可选，v1 实现为状态筛选下拉）
  - [ ] 实验性项目明确标注（experiment），降低读者预期
  - [ ] 空数据 EmptyState

### F08 About / Contact

- 优先级：P1
- 描述：About 自我介绍（数据来自 `site.json` + 可选 `about.md` 正文）；Contact 展示联系方式。
- 验收标准：
  - [ ] About：简介、技术栈/方向、目前在做什么；正文来自 `site.json` 的 bio 与可选 `about.md`（单独加载渲染，不走内容管线 glob）
  - [ ] Contact：邮箱（点击 `mailto:`）、GitHub、其他链接；无表单
  - [ ] 邮箱用编码方式放置（`&#64;` 或 JS 拼接），避免被爬虫直接抓取

### F09 404 页面

- 优先级：P2
- 描述：未匹配路由显示简洁 404。
- 验收标准：
  - [ ] 文案友好（如"页面不存在" + 简短说明）
  - [ ] 提供"返回首页"按钮
  - [ ] 直接访问不存在的子路由同样命中

### F10 响应式

- 优先级：P0
- 描述：桌面 / 平板 / 手机三档布局。
- 验收标准：
  - [ ] < 640px 单列；640–1024 平板双列；> 1024 桌面按设计
  - [ ] 无横向滚动条（全站）
  - [ ] 触摸目标 ≥ 44px（导航、按钮、卡片链接）
  - [ ] 图片 `loading="lazy"`（首屏除外）与 `width/height` 防 CLS

### F11 SEO 基础

- 优先级：P1
- 描述：每个页面有独立 title / description / OG 标签。
- 验收标准：
  - [ ] 路由 `afterEach` 统一设置 `document.title`（规则见 `02-信息架构`）
  - [ ] meta description 写入（默认站点描述，列表页可写统一描述）
  - [ ] 首页 OG 标签（og:title / og:description / og:image）齐全
  - [ ] `index.html` 含基础 meta 与 favicon

### F12 无障碍基础

- 优先级：P1
- 描述：满足 WCAG 2.1 AA 的核心项（完整清单见 `07-工程规范`）。
- 验收标准：
  - [ ] 语义化：`header / nav / main / footer` landmark；每页唯一 `h1`
  - [ ] 键盘可完整操作（Tab 顺序合理，焦点可见）
  - [ ] 正文对比度 ≥ 4.5:1，大号文字 ≥ 3:1
  - [ ] 图标按钮有 aria-label；外链有可识别文本
  - [ ] `prefers-reduced-motion` 生效

## 3. 非功能需求

| 类别 | 指标 | 说明 |
| --- | --- | --- |
| 性能 | 首页 LCP ≤ 1.5s（4G 模拟） | 静态站，无外部字体 / 无大图阻塞 |
| 性能 | 首屏 JS ≤ 150KB gzip | 路由级代码分割（`import()` 懒加载） |
| 性能 | CLS ≤ 0.1 | 图片显式宽高、骨架占位 |
| 性能 | Lighthouse Performance ≥ 90 | 移动端模拟 |
| 兼容 | Chrome / Edge / Firefox 最近 2 个大版本，Safari 15+，iOS 15+ | 不支持 IE |
| 可维护 | 新增内容零代码改动 | 唯一例外：新增技术栈规范名（改 `04-内容层` 的规范表） |
| 可维护 | 内容与代码完全分离 | `src/content/` 之外禁止出现业务文案 |
| 安全 | 无密钥 / 无环境变量 | 纯静态，不引任何运行时 fetch |

## 4. 边界情况（具体场景决策）

| 场景 | 决策 |
| --- | --- |
| 无 featured 项目 | 首页隐藏"精选项目"区块，不显示空状态（保持首页克制） |
| 无笔记 / 无项目 | 列表页显示 EmptyState（首页区块隐藏） |
| 标题 / summary 超长 | CSS 截断（两行省略）；summary 校验长度上限，但不断行适配显示 |
| 项目缺某可选段落 | 正常渲染，缺段不报错（校验只查必需段落） |
| 两个项目 date 相同 | 按 `order` 决定先后；order 也相同按文件名稳定排序 |
| slug 冲突 / 保留字 | 校验脚本报错，拒绝构建（发布前发现，不是运行时问题） |
| 图片缺失 / alt 缺失 | 校验脚本报 alt 缺失；图片 404 时浏览器占位显示（破图），发布前人工检查 |
| 过滤组合无结果 | EmptyState + 一键清除筛选（不清除 URL query 之外的浏览器状态） |
| 详情页直达草稿 | 404（列表不出现 = 视为不存在，行为一致） |
| 时间线同月多条 | 保持 JSON 内书写顺序（倒序书写习惯：新条目写前面） |
| 外部链接失效 | 静态站无法自动检测；发布检查单中人工抽查 demo/github 链接 |
| 内容校验失败但时间紧 | 禁止跳过：validate 是发布保险，报错必须修到零 |
| 用户通过手机直接访问子路由 | 深链兜底（404.html）同样生效，无差别 |

## 5. 优先级总览（MoSCoW）

| 级别 | 需求 |
| --- | --- |
| Must（P0） | F01 导航路由 / F02 Hero / F03 项目列表 / F04 项目详情 / F10 响应式 |
| Should（P1） | F05 时间线 / F06 笔记 / F07 Lab / F08 About+Contact / F11 SEO / F12 无障碍 |
| Could（P2） | F09 404 打磨 / 标签轮换打字机效果 / 项目封面图 |
| Won't（v1） | 见本文档第 1 节"明确不做" |
