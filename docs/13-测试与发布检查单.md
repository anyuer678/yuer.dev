## 5. 性能测量（Lighthouse）

```bash
npm run build
npm run preview -- --port 4173
npx lighthouse http://localhost:4173 --view --only-categories=performance,accessibility,best-practices,seo
```

| 指标 | 预算 |
| --- | --- |
| Performance | >= 90 |
| Accessibility | >= 95 |
| LCP | <= 1.5s |
| CLS | <= 0.1 |
| 首屏 JS | <= 150KB gzip |

> 注（2026-08-10 实测，Edge + lighthouse）：Performance **92** / Accessibility **95** / Best Practices **100** / SEO **100**，CLS 0.088、TBT 270ms、首屏 JS gzip 50.8KB 均达标。
> LCP 1.9s 略超 1.5s 预算：主线程 914ms 花在 Style & Layout（hero 网格纹理 + 卡片阴影为最大来源），属本地 preview（无 gzip/CDN）的保守值，线上 CDN 会更低；若需压到预算内，首选项是 hero `::before` 网格改更轻实现。
> 命令注：Edge 环境下需 `$env:CHROME_PATH = '...msedge.exe'`，线上 URL 偶发 `DOM.resolveNode` 兼容错误（Lighthouse 官方支持 Chrome），本地 preview 结果可信。

命中预算外的处理：定位到具体资源（`npx vite-bundle-visualizer` 或 Network 面板），按 `07-工程规范` 第 7 节决策。

## 6. 发布流程

1. 本地过完本表第 1–5 节
2. 提交 + 推送 main（提交前：validate + lint + build 三连）
3. GitHub Actions 自动构建部署（1–3 分钟）
4. 部署验证：

```bash
curl -s -o /dev/null -w "%{http_code}" https://<user>.github.io/<repo>/
curl -s -o /dev/null -w "%{http_code}" https://<user>.github.io/<repo>/projects/evocode
# 200 或 404 均可能（404.html 兜底属正常，见 02-信息架构 第 6 节），关键看内容：
curl -s https://<user>.github.io/<repo>/projects/evocode | findstr /i "EvoCode"
```

5. 手机上打开首页与一个详情页复查

## 7. 回滚方案

- 回滚 = 恢复上一个绿色提交：`git revert <bad-commit>`（保留历史）或 push 旧 commit（重置）
- 部署是纯静态产物，回滚即重新构建，无数据风险
- 内容事故（如误删项目）：git 历史里找回文件即可

## 8. 偏离许可

- 本表是验收基线，不追求 100% 覆盖所有边界组合；按"核心路径 + 高概率边界"执行
- 若某项测试长期不适用（如无移动设备），在备注列注明原因，不必硬凑
