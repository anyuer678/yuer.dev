# Yuer Studio —— 开发规范与开发思路（总览）

> 项目代号：Yuer Studio（可后续正式定名）
> 定位：**Developer Portfolio + Digital Garden** —— 个人开发者作品展示与成长档案系统

本文档是全部开发规范的**入口**。所有细节见下方子文档，实施前必须通读。

---

## 1. 项目定位

不是"电子简历网站"，而是：

- **作品展示**（Projects）：证明"我能做东西"
- **成长档案**（Journey）：证明"我持续进步"
- **思考记录**（Thoughts）：证明"我不是只会复制代码"

它是所有项目（GitHub → 个人网页 → 项目详情 → Demo → 源码）的**总入口**，形成完整闭环。
网站的价值不在于技术难度，而在于**让陌生人在 5 分钟内理解你的能力与成长**。

## 2. 核心设计原则

1. **5 秒原则**：首页让陌生人 5 秒内知道"这是一个做软件的人"
2. **少即是多**：首页不塞信息，详细内容进子页面
3. **内容驱动**：项目、笔记全部用 Markdown 维护，改内容不碰代码
4. **克制审美**：浅色极简纸张感，不用科技蓝 / 代码雨 / 赛博朋克
5. **克制动效**：少量、有意义的动画，不炫技

## 3. 技术选型（摘要，理由见 `07-工程规范`）

| 项 | 选择 |
| --- | --- |
| 框架 | Vue 3（组合式 API + `<script setup>`） |
| 构建 | Vite |
| 路由 | vue-router 4 |
| Markdown | markdown-it + highlight.js |
| 内容加载 | `import.meta.glob` 批量导入 md/json（零代码加内容） |
| 样式 | 设计令牌（CSS 变量）+ 原生 CSS，不引 UI 库 |
| 托管 | GitHub Pages |
| 质量 | ESLint + Prettier + 内容校验脚本 |

## 6. 规范适用原则（不教条）

- 本套文档是**默认基线**，不是法条。执行时按实际情况取舍（时间、内容量、审美变化），偏离时遵循：
  1. **先记后改**：结构性偏离（技术选型、schema、组件 API、视觉令牌）先写进对应文档或 ADR 再改代码
  2. **小事自由**：样式微调、文案、顺序等不涉及契约的改动，直接做，不必回写文档
  3. **数据契约最硬**：内容 schema、slug 规则、校验脚本这三样改动必须同步文档
- 文档之间冲突时优先级：`03-设计系统` 令牌值 > `09-参考实现` > 其他描述性章节
