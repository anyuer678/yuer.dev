# 15 演进路线（v1.1 → 工作室 `/room`）

> 目标：在不推翻「暖白纸张 + 静态零 fetch + 7 层分层」的前提下，让站点从「内容档案」升级为「可被记住的作品集」。
> Wave 3 主特别页：**纸感工作室 `/room`（多场景 + 物件状态）**；列表/详情仍是主路径。
> 本文档是 v1 上线后的**实施权威**；与旧版路线图冲突时以本文为准，并回写 `08` / `10` / `14`。
> 决策日：2026-09-17（同日修订房间定位）。状态：已定稿，待实施。

## 0. 设计前提（不可动摇）

| 前提 | 含义 |
|------|------|
| 视觉锚点 | 暖白纸张感 + 陶土橙强调（ADR-009）；特别页是「纸感实验室」，不是科技蓝 HUD |
| 运行时数据 | 主站保持 D3；GitHub 数据一律**构建期**写入，仅 Dashboard 可作为明确豁免的内部工具 |
| 分层 | 特别页 = P0 路由页 + 可选独立 chunk；禁止 pages 互相 import；内容仍走 P4 |
| 预算 | 主 chunk ≤ 120KB gzip；特别页各自独立懒加载，不进首屏 |
| 动效清单制 | 新增动效先入 `03-设计系统` §7.2 清单，再写代码（ADR-011） |

## 1. 现状诊断（2026-09）

对照 GitHub 公开仓（27）与站点内容：

1. **联动断**：仅 frontmatter `github` 外链 + 详情相关笔记；Dashboard 硬编码 15 仓、不进导航、与设计系统脱节
2. **层级平**：Flagship 与课程实验同权重，扫读成本高
3. **Demo 浪费**：≥9 个仓已开 GitHub Pages，站点 `demo` 字段大量空置
4. **活性不可见**：release / CI / 最后推送只在 Dashboard
5. **检索缺失**：60+ 笔记无全文搜索
6. **漏仓**：新建仓（如 spotlight-wallpaper）不会自动进入站点视野

## 2. 三波总路线

```text
Wave 1 地基 ──► Wave 2 活性 ──► Wave 3 特别页
（可读可扫）    （闭环有心跳）   （记忆点与传播）
```

| Wave | 主题 | 预估 | 出口标准 |
|------|------|------|----------|
| 1 | 内容分层、封面、GitHub 同步、Demo、检索 | ~1 周 | 10 秒内能说出「是谁 + 3 个最强项目 + 怎么玩」 |

## Wave 1 — 地基

### 1.1 项目分级（tier）

**内容契约**（`04` 增量）：frontmatter 新增

```yaml
tier: flagship | product | lab   # 缺省 lab
```

| tier | 数量建议 | 展示规则 |
|------|----------|----------|
| flagship | ≤ 3 | 首页大卡；Projects「精选」区；星图节点最大 |
| product | 8–12 | Projects 主网格；可有 demo |
| lab | 其余 | 默认进 Lab 弱化区或 Projects 折叠「更多」 |

**页面行为**：

- Home：仅 featured 且 tier=flagship（或 featured 沿用、tier 校验一致）
- Projects：无筛选时 Featured → Product →「实验室与课程」可折叠
- 校验：flagship 计数 ≤ 3（扩展原 featured 规则）

### 1.2 封面策略

| 类型 | 来源 |
|------|------|
| Web / 游戏 / 组件库 | 实截图或 docs 站截图，16:9 |
| CLI / Python 工具 | 统一「纸面终端」模板图（脚本生成：标题 + 一行命令 + 陶土橙 prompt） |
| 无图 | 几何纹理 / 品牌底，禁止灰方块占位 |

存放：`public/images/<slug>/cover.png`；frontmatter `cover: images/<slug>/cover.png`。

### 1.3 GitHub 构建期同步（核心联动）

**新文件**

| 路径 | 职责 |
|------|------|
| `src/content/repo-map.yaml` | 仓名 → slug / showcase / ignore；唯一映射权威 |
| `scripts/sync-github.mjs` | 拉 API → 写 `src/content/github-data.json` |
| `.github/workflows/sync-content.yml`（可选） | 定时或手动触发 sync 并开 PR / 直接 build |

**repo-map 示例**

```yaml
lumen:
  slug: lumen
  showcase: true
kb-ui:
  slug: kb-ui
  showcase: true
spotlight-wallpaper:
  slug: spotlight-wallpaper   # 映射了但缺 md → validate/CI 警告
huayinlaoqiang:
  ignore: true                # 明确不上站
```

**github-data.json 字段（每仓）**

```ts
{
  name: string
  language: string | null
  stars: number
  pushed_at: string           // ISO
  ci_status: 'success' | 'failure' | 'pending' | 'unknown'
  release: string | null      // latest tag
  homepage: string | null
  pages_url: string | null    // has_pages 时推导 https://<user>.github.io/<repo>/
  topics: string[]
}
```

**管线合并**（`04` / `14` 增量）：

- `content.js` 读取 `github-data.json`（eager glob json 已支持）
- 导出 `export const githubRepos` 与 `export function getRepoData(slugOrName)`
- `ProjectMeta` 合并只读字段：`repoStats?: RepoStats`（展示层用，不进 frontmatter 手写）

**CI**：`deploy.yml` 在 build 前增加 `sync-github`（token：`GITHUB_TOKEN`）；本地可 `npm run sync:github`。

**校验增量**：映射 slug 不存在对应 md → ERROR 或 WARNING（建议 WARNING + 列表打印，避免新仓立刻卡部署）。

### 1.4 Demo 链全接

- sync 时若 `has_pages` 且未手写 `demo` → 自动填 `pages_url`
- 手写 `demo` 优先于自动推导
- ProjectCard / Detail：`在线试用` 优先展示，其次 `Demo`，再次仅 `GitHub`

### 1.5 笔记全文检索

- 依赖：`minisearch`（构建期索引，运行时小）
- `scripts/build-search-index.mjs`：读 notes meta + 正文纯文本摘要 → `src/content/search-index.json`
- Notes 页顶栏搜索框；结果高亮标题/摘要；query 写入 `?q=`（延续 D2 URL 即状态）

## Wave 3 — 特别页面：纸感工作室 `/room`

> **主特别页 = `/room`（工作室）**，精细度档位：**高 —— 多场景 + 物件状态**（非 Three.js 3D）。
> Atlas 降级为房内「挂画/桌面星图」入口或可选轻量页；Lumen 叙事、Bench 保留为独立路由，由房内物件进入。
> 共同约束：整段懒加载；可整体下线而不影响主站；视觉服从 `03` tokens；**列表/详情仍是面试与分享主路径**。

### 3.0 总原则：房间是门厅，不是唯一展厅

| 原则 | 含义 |
|------|------|
| 双入口 | `/projects` `/notes` 可直达、可分享；房间是「有性格的导航」，不是内容唯一入口 |
| 内容模型 | 物件只绑定 **slug / query / 路由**，不复制正文；新项目 = 改映射 + 可选新热区，不重写整屋 |
| 技术形态 | 分层插画（SVG/WebP）+ 语义化热区 `button`；场景切换用路由或轻量状态机；**禁止 Three.js / WebGL 房间** |
| 预算 | `/room` 及场景图独立 chunk；单场景主视觉 WebP ≤ 200KB，场景间懒加载 |
| 降级 | `prefers-reduced-motion` 关微动效；小屏 = 场景轮播 + 物件列表（等价信息，非残缺体验）；键盘可 Tab 热区 |

```text
  首页 Hero「进入工作室」 ──► /room
                               │
        ┌──────────────────────┼──────────────────────┐
        ▼                      ▼                      ▼
   场景 A 书桌区           场景 B 书架墙            场景 C 窗边/夜灯
   （默认）                （项目分层）              （Pulse / 叙事）
        │                      │                      │
   笔记本→Lumen 叙事       分层书脊→Projects?tier   窗→HomePulse 浮层
   终端→/bench             抽屉→Lab                 星图挂画→/atlas?
   相框→About              便签→Notes               咖啡杯→彩蛋
```

### 3.A 工作室主壳 `/room`

**定位**：全站记忆点与空间导航；用「逛一间书房」建立个人品牌，同时把流量导回结构化页面。

| 项 | 规格 |
|----|------|
| 路由 | `/room`；`meta.nav` 建议 true（主视觉入口）；Home Hero 次按钮「进入工作室」 |
| 场景 | **3 个主场景**（书桌 / 书架墙 / 窗边），左右切换或锚点导航；URL 可带 `?scene=desk`（延续 D2） |
| 场景切换 | 横向 slide 或交叉淡入；`aria` 场景名；不整页刷新 |
| 热区 | 每场景 6–10 个可点物件；视觉 hover 微反馈（描边/轻微上浮）；点击行为见映射表 |
| 物件状态 | 见 §3.B「多场景 + 物件状态」——开抽屉、开灯、翻开笔记本、点亮屏幕等 |
| 旁路 | 常驻「以列表浏览」链到 `/projects`；页脚说明「内容亦可从导航直达」 |
| 数据 | `src/content/room.json`（场景、热区、文案、目标路由）+ 既有 `projects`/`github-data` |
| 组件树 | `pages/Room.vue` → `features/room/RoomStage` · `RoomScene` · `RoomHotspot` · `RoomDrawer` · `RoomLegend` |
| 技术 | CSS transform + 局部 transition；不用 GSAP；音频默认关（若加环境音需显式开关） |

**物件 ↔ 内容映射（初版，写入 room.json）**

| 场景 | 物件 | 状态/交互 | 去向 |
|------|------|-----------|------|

| 书桌 | 终端（唤醒） | 屏幕亮起 | `/bench` |
| 书桌 | 相框 | hover 放大 | `/about` |
| 书桌 | 便签堆 | 抽出 1–3 张 | `/notes` 或最近笔记 |
| 书架 | 三层书脊 | hover 亮层 | `/projects?tier=flagship\|product\|lab` |
| 书架 | 抽屉（拉开） | open/close | `/lab` |

### 3.B 多场景 + 物件状态（精细度档）

在「可点」之上增加**可变状态**，但状态不承载业务数据，只作叙事与反馈。

| 状态类型 | 示例 | 约束 |
|----------|------|------|
| 开合 | 抽屉拉开露出 Lab、笔记本翻开第一页 | 单一 `data-state`；动画 ≤ 220ms |
| 亮灭 | 终端屏亮、夜灯、窗昼夜 | 与 `prefers-reduced-motion` 及手动「日夜」开关 |
| 进度 | 桌上进度条 = Flagship 完成感（读 tier/status） | 只读派生，不写库 |
| 记忆 | 本场景曾打开过的抽屉保持打开（sessionStorage） | 仅 UX，可一键重置 |
| 浮层 | 点窗弹出 Pulse；点书脊不离房、先出预览卡 | 浮层必须含「打开完整页」 |

**明确不做（房间边界）**

| 不做 | 原因 |
|------|------|
| Three.js / WebGL 3D 房间 | 与 ADR-009、预算、移动端冲突 |
| 真终端执行 | 安全与复杂度 |
| 房间内写死项目正文 | 与内容管线重复、必漂移 |
| 强制逛完才能看项目 | 违背「门厅」原则 |

**验收（房间）**

- 3 场景切换流畅；每场景 ≥ 6 个有效热区且键盘可达
- 所有热区都能到达既有结构化页或有意义浮层+深链
- 关掉 JS 的降级说明仍在（站点级 noscript 已有）；减动效模式可完成同等导航
- `/room` 懒加载后，主站首屏预算不受影响
